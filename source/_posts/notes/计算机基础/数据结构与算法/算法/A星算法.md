# A* 算法
## A* 算法意义
###  两种基础寻路算法缺陷
- **广度优先 BFS**：盲目遍历，向四周均匀扩散，能找到最短路径，但**效率极低**，大量无效探索。
- **贪心最佳优先搜索**：只看「离终点多近」，只走预估最近的点，速度快，但**容易绕路、找不到最短路径**。

### A* 的核心定位
**A* = BFS（保证最短路径） + 贪心算法（启发式加速）**

结合两者优点：

1. 能保证**全局最短路径**；
2. 依靠启发函数大幅减少无效搜索，**效率极高**；
3. 是游戏、网格寻路、地图导航最经典的智能寻路算法。

## A* 核心公式
$$\boldsymbol{F = G + H}$$
- $F$：**综合代价**，当前节点的总评分，A* 每次永远选择 **F 值最小** 的节点拓展；
- $G$：**实际代价**，**从起点走到当前节点** 已经付出的消耗；
- $H$：**启发预估代价**，**从当前节点走到终点** 的预估消耗（核心灵魂）。

### 分项通俗解释
1. **G**
真实走过的路。
网格中上下左右走一格，通常固定 $G+1$；斜向移动可设为固定代价。
作用：**保证路径最短，防止贪心乱走**。

2. **H**
没走的路，是估算值，也叫**启发函数**。
作用：**引导算法朝着终点方向走，减少无效搜索**。
> 关键规则：$H$ 必须是**可采纳的**（预估距离 ≤ 真实距离），否则A*无法保证最短路径。

3. **F（决策依据）**
平衡「已经走的路」和「还要走的路」，F越小，这个节点越优先探索。

## 关键集合概念
1. **开放列表 `OpenList`**
候选列表：所有已经发现、待考察、待拓展的节点。
每次循环：从 `OpenList` 取出 **F最小** 的节点作为当前点。

2. **关闭列表 `CloseList`**
已处理列表：已经计算过、完全拓展完毕、不再重复访问的节点。
避免回头重复计算、死循环。

3. **父节点 Parent**
每个节点记录自己的上一个节点。
寻路结束后，**从终点反向回溯父节点 → 反转得到完整路径**。

## A* 完整运行流程
1. 初始化：把**起点**加入 `OpenList`；
2. 循环判断：若 `OpenList` 为空 → 无路可走，寻路结束；
3. 选点：取出 `OpenList` 中 **F最小** 的节点，作为「当前节点」；
4. 标记：当前节点移入 `CloseList`，不再重复访问；
5. 终止判断：如果当前节点 == 终点 → 回溯生成路径，算法结束；
6. 遍历邻居（上下左右/八方向）：
   - 跳过：越界、障碍物、已在 `CloseList` 的节点；
   - 计算：新的 $G$ 值（从起点经过当前点到邻居的代价）；
   - 择优：
     - 邻居不在 `OpenList`：直接加入，记录 $G、H、F$，绑定父节点；
     - 邻居已在 `OpenList`：如果**新G更小**（走当前节点更近），就更新代价与父节点；
7. 重复 2~6，直到找到终点或无可用节点。

## 常用启发函数 H
### 曼哈顿距离（四方向移动｜上下左右）
适用：只能上下左右走，不能斜走
$$H = |x_1 - x_2| + |y_1 - y_2|$$

### 欧几里得距离（自由移动）
适用：平面任意角度移动
$$H = \sqrt{(x_1-x_2)^2 + (y_1-y_2)^2}$$

### 切比雪夫距离（八方向移动｜含斜向）
适用：游戏常用，上下左右+四个斜角
$$H = \max(|x_1-x_2|,|y_1-y_2|)$$

## 核心特性与约束
###  最优性条件
只要 **H 是可采纳启发（预估不高估真实距离）**
A* 一定能找到**最短路径**。

### 优缺点
优点：
- 兼顾最短路径与搜索效率；
- 结构简单、易实现、易优化；
- 适配网格、`TileMap`、2D/3D 游戏寻路。

缺点：
- 大规模地图下，`OpenList` 频繁查找最小F，性能下降；
- 依赖启发函数设计，H不合理会严重影响效率。

```c++
// 网格节点
struct Node {
    int x, y;           // 坐标
    int g, h, f;        // g：起点到当前代价，h：启发值，f=g+h
    Node* parent;       // 父节点，用于回溯路径

    Node(int x_, int y_) : x(x_), y(y_), g(0), h(0), f(0), parent(nullptr) {}

    // 优先队列小顶堆（f 最小优先）
    bool operator>(const Node& other) const {
        return f > other.f;
    }
};

// 曼哈顿距离（最简单的启发函数）
int manhattan(const Node* a, const Node* end) {
    return abs(a->x - end->x) + abs(a->y - end->y);
}

// A* 寻路主函数
std::vector<Node*> aStar(
    const std::vector<std::vector<int>>& grid,
    Node* start,
    Node* end
) {
    int rows = grid.size();
    int cols = grid[0].size();

    // 开放列表：待检查节点（小顶堆）
    std::priority_queue<Node*, std::vector<Node*>, std::greater<Node*>> openList;
    // 关闭列表：已检查节点
    std::vector<std::vector<bool>> closed(rows, std::vector<bool>(cols, false));
    // 保存所有节点指针，最后统一释放
    std::vector<Node*> allNodes;

    openList.push(start);
    allNodes.push_back(start);

    // 上下左右四方向
    const int dirs[4][2] = {{-1,0}, {1,0}, {0,-1}, {0,1}};

    while (!openList.empty()) {
        // 取出 f 最小的节点
        Node* curr = openList.top();
        openList.pop();

        int x = curr->x;
        int y = curr->y;
        closed[x][y] = true;

        // 到达终点，回溯路径
        if (x == end->x && y == end->y) {
            std::vector<Node*> path;
            while (curr != nullptr) {
                path.push_back(curr);
                curr = curr->parent;
            }
            std::reverse(path.begin(), path.end());
            return path;
        }

        // 遍历四个方向
        for (const auto& dir : dirs) {
            int nx = x + dir[0];
            int ny = y + dir[1];

            // 越界 / 障碍物 / 已检查
            if (nx < 0 || nx >= rows || ny <0 || ny >= cols) continue;
            if (grid[nx][ny] == 1) continue;
            if (closed[nx][ny]) continue;

            // 计算新代价
            int newG = curr->g + 1;
            Node* neighbor = new Node(nx, ny);
            allNodes.push_back(neighbor);

            neighbor->g = newG;
            neighbor->h = manhattan(neighbor, end);
            neighbor->f = neighbor->g + neighbor->h;
            neighbor->parent = curr;

            openList.push(neighbor);
        }
    }

    // 无路径
    return {};
}
```

## A* 算法优化

- 开放列表 `OpenList` 改用 **优先队列（最小堆）**
- 关闭列表 `CloseList` 不用 HashSet，直接给节点打标记
- 启发函数 H 优化：**避免开根号**
- 节点对象池复用
- JPS 跳点搜索
- 加权 A*（不再是最短路）

## JPS 跳点搜索

**JPS（Jump Point Search）**：是 **A* 算法的强优化变种**，专门针对**均匀网格地图**的寻路加速算法。

- 底层依旧是 **A* 框架**：$F=G+H$、启发函数、开放/关闭列表完全不变
- 核心区别：**不逐个格子遍历邻居，而是直接「跳跃」到关键拐点（跳点）**
- 效果：**剔除大量冗余节点**，搜索节点数量减少 70%~95%，速度比普通 A* 快数倍到数十倍

适用场景：2D 方格地图、塔防、RTS、RPG、Tile map 游戏；
**不适用**：不规则网格、动态代价地图、任意多边形地形。

### A* 的缺陷
常规四方向/八方向 A*：
1. 每一个格子都要加入开放列表、计算代价、比较F值；
2. 在**无障碍物的直线路径**上，大量连续格子都是「无意义冗余节点」；
3. 大片空地会产生巨量节点，堆爆 `OpenList`，性能暴跌。

> 举例：一条100格的直路
> - 普通A*：遍历 100 个节点
> - JPS：只保留**起点、终点、必要拐点**，中间全部跳过

### JPS 核心核心概念
#### 强制邻居（Forced Neighbor）
定义：如果当前节点的**相邻斜向有障碍物**，导致**必须拐弯才能通行**，则该方向的邻居为**强制邻居**，必须停下来、作为新的搜索起点。

简单理解：
> 前面直走被墙卡住，不得不绕路 → 这里就是必须处理的关键点。

#### 跳点（Jump Point）
满足任意一条，即为**跳点**：
1. 起点、终点；
2. 拥有**强制邻居**的节点（必须拐弯）；
3. 两个不同移动方向的转折点。

JPS 规则：
- 非跳点：**直接跳过，不加入开放列表，不计算代价**
- 跳点：**暂停跳跃，加入A*开放列表，继续向多方向拓展搜索**

#### 两类移动方向
JPS 八方向分为两类，分开规则判定：
1. **直线方向**：上下左右（轴向）
2. **斜线方向**：左上/右上/左下/右下（对角）

### JPS 跳跃规则
#### 规则1：直线方向跳跃（上下左右）
以**向右**为例：
1. 持续向右一格一格跳跃前进；
2. 每一步检查上下两侧格子：
   - 若一侧有墙、一侧可走 → 产生**强制邻居** → 当前点为跳点，停止跳跃；
3. 撞到墙/地图边界 → 停止；
4. 遇到终点 → 停止。

#### 规则2：斜线方向跳跃（对角）
以**右下**为例：
1. 先**递归跳跃水平方向**、再**递归跳跃竖直方向**；
2. 只要水平/竖直任意方向找到跳点，当前斜向节点即为跳点；
3. 斜向移动本身不会产生强制邻居，依赖两个轴向的判定。

> 关键：斜线跳跃依赖**轴向跳跃的递归探测**，这是 JPS 算法的精髓。

### JPS 整体运行流程
#### A*
1. 取出F最小节点
2. 遍历**8个相邻格子**
3. 逐个计算G/H/F，加入开放列表

#### JPS
1. 取出F最小跳点（和A*完全一致）
2. **不遍历8邻域**，而是向8个方向执行「跳跃探测」
3. 沿方向一路跳过去，只寻找**跳点**
4. 找到跳点后，计算代价、加入`OpenList`
5. 重复直到抵达终点

### JPS 与 A* 区别
| 特性 | 普通 A* | JPS 跳点搜索 |
|------|---------|--------------|
| 遍历方式 | 逐个格子拓展8邻域 | 方向长距离跳跃，只搜拐点 |
| 处理节点 | 极多，大量冗余 | 极少，只保留关键跳点 |
| 启发函数 | 曼哈顿/切比雪夫 | 完全通用，无需修改 |
| 路径最优性 | 最优最短路径 | **同样保证最优最短路径** |
| 额外开销 | 低 | 少量跳跃递归判断开销 |
| 综合性能 | 差（大图卡顿） | 极强（大图流畅） |

> 重点：**JPS 是 无损优化，不会绕路、不会丢失最短路径**。

### JPS 的优缺点
#### 优点
1. 极致减少搜索节点数，性能碾压原生A*；
2. 完全兼容八方向网格寻路；
3. 路径质量和A*完全一致，保证最短；
4. 只需改造「邻居拓展逻辑」，A*主体框架不用改。

#### 缺点
1. **仅适合均匀网格**，无法用于非均匀代价地图（如草地/沙地减速）；
2. 斜线递归跳跃逻辑复杂，代码实现比A*难不少；
3. 动态障碍物频繁变化的场景，优势会被削弱；
4. 不适合三维、多边形导航网格 Nav Mesh。
