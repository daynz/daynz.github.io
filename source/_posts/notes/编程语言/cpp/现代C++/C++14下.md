# 智能指针工厂函数

C++14 正式引入 `std::make_unique` 模板函数，作为 `std::unique_ptr` 的专用工厂函数；而 `std::make_shared`（C++11 引入）、`std::make_shared_for_overwrite`（C++20 引入）等智能指针工厂函数，共同构成了 C++ 智能指针的 “安全创建范式”。这些工厂函数解决了裸指针直接构造智能指针的安全性、内存效率和代码简洁性问题，是现代 C++ 中动态内存管理的核心最佳实践。

核心价值：**通过统一的工厂函数创建智能指针，消除裸指针暴露、避免内存泄漏、提升内存分配效率**，同时简化智能指针的初始化语法，让动态内存管理更符合 RAII（资源获取即初始化）原则。

## 背景

C++11 引入了 `std::unique_ptr` 和 `std::shared_ptr`，但未为 `unique_ptr` 提供对应的工厂函数，导致以下痛点：

1. **裸指针暴露风险**：直接用 `new` 构造 `unique_ptr` 时，裸指针可能在传递过程中泄露，或因异常导致内存泄漏；
2. **代码冗余**：需手动匹配 `new` 的类型与 `unique_ptr` 的模板参数，易出现类型不匹配错误；
3. **内存分配不优化**：`shared_ptr` 可通过 `make_shared` 合并控制块与对象内存分配，而 `unique_ptr` 无等效方案；
4. **异常安全问题**：函数参数传递时，裸指针构造智能指针可能因参数求值顺序导致内存泄漏。

```c++
// C++11 痛点1：裸指针构造 unique_ptr，暴露 new 表达式
std::unique_ptr<int> p1(new int(10)); 
// C++11 痛点2：异常安全风险（假设计算 func() 时抛出异常，new int(20) 的内存泄漏）
func(std::unique_ptr<int>(new int(20)), risky_func()); 
// C++11 痛点3：类型冗余（int 重复写）
std::unique_ptr<std::string> p2(new std::string("hello"));
```

## 核心语法和基础使用

**`std::make_unique` 核心定义（C++14）**

`std::make_unique` 是 `<memory>` 头文件中定义的模板函数，用于创建 `std::unique_ptr`，语法分为三种重载：

| 重载版本              | 适用场景                      | 语法示例                       |
| --------------------- | ----------------------------- | ------------------------------ |
| 单对象版本            | 创建单个对象的 unique_ptr     | `std::make_unique<T>(args...)` |
| 数组版本              | 创建数组的 unique_ptr         | `std::make_unique<T[]>(size)`  |
| 定长数组版本（C++20） | 创建固定大小数组的 unique_ptr | `std::make_unique<T[N]>()`     |

```c++
// 1. 单对象版本：创建单个int对象，值为10
auto p1 = std::make_unique<int>(10);
std::cout << *p1 << std::endl; // 输出：10
// 2. 单对象版本：创建带构造参数的自定义类型
struct Person {
    std::string name;
    int age;
    Person(const std::string& n, int a) : name(n), age(a) {}
};
auto p2 = std::make_unique<Person>("Alice", 25);
std::cout << p2->name << ", " << p2->age << std::endl; // 输出：Alice, 25
// 3. 数组版本：创建长度为5的int数组（值默认初始化）
auto p3 = std::make_unique<int[]>(5);
for (int i = 0; i < 5; ++i) {
    p3[i] = i * 2; // 赋值：0,2,4,6,8
    std::cout << p3[i] << " ";
}
std::cout << std::endl; // 输出：0 2 4 6 8
// 4. 定长数组版本（C++20）：创建固定大小为3的string数组
auto p4 = std::make_unique<std::string[3]>();
p4[0] = "a"; p4[1] = "b"; p4[2] = "c";
std::cout << p4[1] << std::endl; // 输出：b
```

**`std::make_shared`（C++11 对比参考）**

`std::make_shared` 是 `std::shared_ptr` 的工厂函数，与 `make_unique` 语法相似，但核心差异在于内存分配：

- `make_shared` 会将 `shared_ptr` 的**控制块**（引用计数、弱引用计数等）与对象内存**一次性分配**，减少内存碎片；
- `make_unique` 仅分配对象内存（`unique_ptr` 无控制块），更轻量。

```c++
// std::make_shared 创建 shared_ptr
auto sp1 = std::make_shared<int>(100);
std::cout << *sp1 << ", ref count: " << sp1.use_count() << std::endl;
// 输出：100, ref count: 1
// 自定义类型（带构造参数）
auto sp2 = std::make_shared<Person>("Bob", 30);
std::cout << sp2->name << ", " << sp2->age << std::endl; // 输出：Bob, 30
```

**工厂函数的核心优势**

```c++
// 反面示例：裸指针构造 unique_ptr（不推荐）
std::unique_ptr<int> bad_ptr(new int(5));
// 正面示例：make_unique（推荐）
auto good_ptr = std::make_unique<int>(5);

/* 核心优势对比 */
// 1. 异常安全：避免参数求值顺序导致的内存泄漏
// 不安全：new int(10) 先执行，若 func2() 抛异常，内存泄漏
// func1(std::unique_ptr<int>(new int(10)), func2());
// 安全：make_unique 是单一表达式，RAII 立即生效
func1(std::make_unique<int>(10), func2());

// 2. 代码简洁：无需重复写类型
// 冗余：std::unique_ptr<std::vector<int>> p(new std::vector<int>);
// 简洁：auto p = std::make_unique<std::vector<int>>();

// 3. 消除裸指针：全程无 new 暴露，符合 RAII 原则
```

## 核心使用场景

**替代裸 `new` 构造 `unique_ptr`**

任何需要创建 `unique_ptr` 的场景，都应优先使用 `make_unique`，而非直接 `new`：

```c++
// 业务场景：动态创建配置对象
struct Config {
    std::string path = "/tmp";
    int timeout = 30;
    Config(const std::string& p, int t) : path(p), timeout(t) {}
};
// 推荐：make_unique 创建
std::unique_ptr<Config> create_config(const std::string& path, int timeout) {
    return std::make_unique<Config>(path, timeout); // 无需 new
}
auto cfg = create_config("/etc", 60);
std::cout << cfg->path << ", " << cfg->timeout << std::endl; // 输出：/etc, 60
```

**容器中存储智能指针**

`make_unique`/`make_shared` 是容器中管理动态对象的最佳方式，避免手动管理内存：

```c++
// 存储 unique_ptr 的容器
std::vector<std::unique_ptr<Person>> people;
// 批量创建并添加
people.push_back(std::make_unique<Person>("Charlie", 28));
people.push_back(std::make_unique<Person>("Diana", 35));
// 遍历访问
for (const auto& p : people) {
    std::cout << p->name << ", " << p->age << std::endl;
}// 输出：// Charlie, 28 Diana, 35
```

**异常安全的函数参数传递**

`make_unique` 确保动态内存分配与智能指针对象构造是**原子操作**，避免异常导致的内存泄漏：

```c++
// 模拟可能抛异常的函数
int risky_func() {
    throw std::runtime_error("something wrong");
}
// 接收 unique_ptr 参数的函数
void process_data(std::unique_ptr<int> data, int extra) {
    if (data) {
        std::cout << "Data: " << *data << ", Extra: " << extra << std::endl;
    }
}
try {
    // 安全：make_unique 是单一表达式，即使 risky_func 抛异常，也无内存泄漏
    process_data(std::make_unique<int>(42), risky_func());
} catch (const std::exception& e) {
    std::cout << "Exception: " << e.what() << std::endl;
}
```

**与 `std::move` 结合转移所有权**

```c++
std::unique_ptr<int> transfer_ownership() {
    auto ptr = std::make_unique<int>(99);
    return ptr; // 自动移动（NRVO 优化）
}
auto p = transfer_ownership();
std::cout << *p << std::endl; // 输出：99
// 手动转移所有权
std::unique_ptr<int> p2 = std::move(p);
if (!p) {
    std::cout << "p is null" << std::endl; // 输出：p is null
}
std::cout << *p2 << std::endl; // 输出：99
```

## 核心规则与注意事项

**`make_unique` 的限制**

- **不支持自定义删除器**：若需为 `unique_ptr` 指定自定义删除器（如 `std::unique_ptr<T, Deleter>`），无法使用 `make_unique`，需手动构造：

```c++
// 自定义删除器（示例：打印日志后释放）
struct CustomDeleter {
    void operator()(int* p) const {
        std::cout << "Deleting int: " << *p << std::endl;
        delete p;
    }
};
std::unique_ptr<int, CustomDeleter> p(new int(10), CustomDeleter{});// 无法用 make_unique，需手动构造
```

- **数组初始化限制**：`make_unique<T[]>` 仅支持默认初始化，无法直接初始化数组元素（需后续赋值）；

- **C++14 之前不可用**：若项目需兼容 C++11，需自行实现简易版 `make_unique`：

```c++
// C++11 兼容版 make_unique（简化版）
template <typename T, typename... Args>
std::unique_ptr<T> make_unique(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}
```

| 场景                    | 推荐使用         | 原因                                       |
| ----------------------- | ---------------- | ------------------------------------------ |
| 独占所有权（无需共享）  | make_unique      | 更轻量（无控制块）、语义更清晰             |
| 共享所有权              | make_shared      | 合并内存分配，减少内存碎片，效率更高       |
| 需要自定义删除器        | 手动构造智能指针 | make_* 系列不支持自定义删除器              |
| 需兼容 C++11            | make_shared      | make_unique 是 C++14 引入                  |
| 大对象 / 需快速释放内存 | make_unique      | make_shared 控制块与对象内存绑定，释放延迟 |

- 内存泄漏的最后防线

  - `make_unique`/`make_shared` 不能完全避免内存泄漏（如智能指针被循环引用），但能消除**绝大部分**因裸指针导致的泄漏；

  - `shared_ptr` 的循环引用需通过 `std::weak_ptr` 解决，而 `unique_ptr` 无此问题（独占所有权）。

- C++20 扩展：make_shared_for_overwrite
  - C++20 引入 `std::make_shared_for_overwrite`，用于创建未初始化的对象（跳过构造函数），提升性能（类似 `new (nothrow) T`）：

```c++
// C++20：创建未初始化的 string（避免默认构造的开销）
auto sp = std::make_shared_for_overwrite<std::string>();
*sp = "hello"; // 直接赋值，跳过默认构造
std::cout << *sp << std::endl; // 输出：hello
```

# 用户自定义字面量的标准库扩展

C++11 引入了**用户自定义字面量（User-Defined Literals, UDL）**，允许程序员为自定义类型创建专属字面量语法；而 **C++14 对标准库进行了核心扩展**，为 `std::string`、`std::chrono`（时间）、`std::complex`（复数）三大核心组件内置了标准字面量后缀，彻底告别繁琐的类型构造语法，让代码更简洁、直观、易读。

核心价值：**用极简的后缀语法（如`s`/`s`/`ms`/`i`）直接创建标准库对象**，替代冗长的构造函数调用，统一字面量表达风格，大幅提升标准库对象的初始化效率。

## 背景

C++11 虽支持自定义字面量，但**标准库本身未提供任何内置字面量**，创建常用标准库对象必须手动调用构造函数，存在以下痛点：

1. **代码冗长**：创建字符串、时间、复数对象需写完整类型 + 构造函数；
2. **可读性差**：时间间隔（如 100 毫秒）、复数（如 3+4i）用构造函数表达不直观；
3. **易出错**：手动指定类型 / 单位易写错，字面量与类型不匹配；
4. **语法不一致**：基础类型有字面量（`10`/`3.14`），标准库对象却没有。

```c++
// C++11 痛点：标准库对象初始化繁琐
// 1. std::string 必须手动构造
std::string str1 = std::string("hello"); 
// 2. std::chrono 时间间隔语法极繁琐
auto duration = std::chrono::milliseconds(100); // 100毫秒
// 3. std::complex 复数写法不直观
std::complex<double> c(3.0, 4.0); // 3+4i
```

## 核心语法和基础使用

C++14 在三个命名空间下提供了**官方标准字面量后缀**，均为**模板 UDL**，自动推导类型，无需手动指定：

| 标准库组件          | 命名空间                          | 后缀                         | 功能                            | 示例          |
| ------------------- | --------------------------------- | ---------------------------- | ------------------------------- | ------------- |
| `std::string`       | `std::literals::string_literals`  | `s`                          | 字符串字面量，创建`std::string` | `"hello"s`    |
| `std::chrono` 时间  | `std::literals::chrono_literals`  | `h`/`min`/`s`/`ms`/`us`/`ns` | 时间间隔字面量                  | `100ms`、`2h` |
| `std::complex` 复数 | `std::literals::complex_literals` | `i`/`il`/`if`                | 虚数字面量                      | `3.0i`、`4if` |

**std::string 字符串字面量（后缀：`s`）**

**作用**：将 C 风格字符串 `const char*` 直接转换为 `std::string` 对象。

**命名空间**：`using namespace std::string_literals;`

```c++
// 引入字符串字面量后缀
using namespace std::string_literals;
// C++11：繁琐
std::string str_old = std::string("test");
// C++14：极简，直接创建 std::string
auto str = "hello world"s; 
// 类型：std::string，而非 const char*
// 支持拼接（直接+）
auto full = "hello"s + " c++14"s;
```

**std::chrono 时间字面量（最常用扩展）**

**作用**：直接创建**时间间隔（std::chrono::duration）** 对象，支持时分秒毫秒微秒纳秒。

**命名空间**：`using namespace std::chrono_literals;`

**完整后缀列表**：

- `h`：小时
- `min`：分钟
- `s`：秒
- `ms`：毫秒
- `us`/`μs`：微秒
- `ns`：纳秒

```c++
using namespace std::chrono_literals;
// 直接创建时间间隔对象
auto one_sec = 1s;       // std::chrono::seconds(1)
auto hundred_ms = 100ms; // std::chrono::milliseconds(100)
auto half_hour = 0.5h;   // 30分钟
// 最常用：线程休眠（代码极简洁）
std::this_thread::sleep_for(500ms); // 休眠500毫秒
// 时间运算（直接加减）
auto total = 1min + 30s; // 1分30秒
```

**std::complex 复数字面量（后缀：`i`/`if`/`il`）**

**作用**：直接创建**虚数 / 复数**对象，数学代码更直观。

**命名空间**：`using namespace std::complex_literals;`

**后缀**：

- `i`：`double` 类型虚数
- `if`：`float` 类型虚数
- `il`：`long double` 类型虚数

```c++
using namespace std::complex_literals;
// C++11：不直观
std::complex<double> c_old(3.0, 4.0);
// C++14：数学写法，一目了然
auto c = 3.0 + 4.0i;  // 复数 3+4i
auto f = 1.5if;       // float 虚数
auto l = 2.0il;       // long double 虚数
// 复数运算
auto res = (1.0 + 2.0i) * (3.0 + 4.0i);
```

## 核心规则与注意事项

- **命名空间规则**

  - 所有标准库 UDL 都位于 **`std::literals`** 及其子命名空间下；

  - 最推荐写法：`using namespace std::literals;`（一次性引入全部）；

  - 也可按需引入：`using namespace std::string_literals;`；

  - **不能在全局命名空间定义与标准库冲突的 UDL 后缀**（如`s`/`ms`）。


- **关键特性**

  - **自动类型推导**：无需写模板参数，编译器自动生成对应标准库对象；

  - **编译期创建**：多数标准库字面量是`constexpr`，可在编译期计算；

  - **类型安全**：避免手动构造时的类型写错问题；

  - **与基础字面量兼容**：`100ms`是整数 + 后缀，`1.5s`是浮点数 + 后缀。


- **常见误区**

  - **误区 1**：`"hello"s` 和 `"hello"` 一样

    错误：前者是`std::string`，后者是`const char*`，类型完全不同；

  - **误区 2**：`1s`是整数

    错误：`1s`是`std::chrono::seconds`对象，不是 int；

  - **误区 3**：C++11 可用这些后缀

    错误：**标准库 UDL 是 C++14 专属特性**。

- 最佳实践

  - **线程休眠必用**：`sleep_for(500ms)` 替代冗长的`milliseconds(500)`；

  - **字符串优先用**：`"str"s` 直接得到`std::string`，避免隐式转换；

  - **数学 / 科学计算**：用`i`后缀写复数，代码接近数学公式；

  - **头文件中谨慎使用**：`using namespace` 避免污染头文件作用域。

# `std::integer_sequence` 及相关工具

C++14 引入的 **`std::integer_sequence`** 是模板元编程的核心基础工具，用于表示**编译期整数序列**（如 `0,1,2,3,...,N-1`）。配合 `std::make_index_sequence`、`std::index_sequence_for` 等配套工具，它能在编译期生成、传递、展开整数序列，是实现**可变参数解包、数组 / 元组遍历、编译期循环**的关键组件。

核心价值：**在编译期生成整数序列，驱动可变参数模板的非递归展开**，彻底替代复杂的递归模板元编程，让元组遍历、数组初始化、参数包展开等操作简洁、高效、无递归。

## 背景

C++11 支持可变参数模板，但**遍历 / 解包参数包**必须通过**递归**实现，存在以下痛点：

1. **递归冗余**：遍历元组、数组需编写递归函数 + 终止条件，代码冗长；
2. **编译低效**：递归模板实例化增加编译时间；
3. **可读性差**：嵌套递归逻辑难以理解和调试；
4. **无法直接生成序列**：无法快速生成 `0~N` 的编译期整数序列。

```c++
// C++11 痛点：递归遍历 tuple（繁琐）
template <size_t I = 0, typename... Args>
void print_tuple(const std::tuple<Args...>& t) {
    if constexpr (I < sizeof...(Args)) { // C++17 才有 constexpr if，C++11 更麻烦
        std::cout << std::get<I>(t) << " ";
        print_tuple<I + 1>(t);
    }
}
```

## 核心定义与工具链

`std::integer_sequence` 位于 `<utility>` 头文件，是一个**空类模板**，仅用于**携带编译期整数序列**。C++14 提供完整工具链：

| 工具名称                            | 作用                                                   | 示例                                       |
| ----------------------------------- | ------------------------------------------------------ | ------------------------------------------ |
| `std::integer_sequence<T, Ints...>` | 通用编译期整数序列（T 为整数类型）                     | `integer_sequence<int, 0,1,2>`             |
| `std::index_sequence<Ints...>`      | **最常用**：等价于 `integer_sequence<size_t, Ints...>` | `index_sequence<0,1,2>`                    |
| `std::make_index_sequence<N>`       | 生成 `0,1,2,...,N-1` 序列                              | `make_index_sequence<3>` → `<0,1,2>`       |
| `std::index_sequence_for<T...>`     | 生成匹配参数包长度的序列                               | `index_sequence_for<int,double>` → `<0,1>` |

## 核心语法与使用

**基础定义**

```c++
// 通用整数序列（int 类型）
template <typename T, T... Ints>
struct integer_sequence {};
// 索引序列（size_t 类型，最常用）
template <size_t... Ints>
using index_sequence = integer_sequence<size_t, Ints...>;
// 生成 0~N-1 序列
template <size_t N>
using make_index_sequence = /* 编译器自动生成 0,1,..N-1 */;
// 按参数包长度生成序列
template <typename... Args>
using index_sequence_for = make_index_sequence<sizeof...(Args)>;
```

**核心用法：序列推导 + 完美转发展开**

**核心技巧**：通过函数参数推导 `index_sequence`，再在参数包中展开序列，**无递归**完成遍历。

```c++
// 辅助函数：通过 index_sequence 展开序列
template <size_t... Indices>
void print_indices(std::index_sequence<Indices...>) {
    // 折叠表达式（C++17）打印序列
    ((std::cout << Indices << " "), ...) << std::endl;
}
// 生成 0,1,2,3
print_indices(std::make_index_sequence<4>{}); 
// 输出：0 1 2 3
```

## 核心使用场景

**遍历 std::tuple（无递归，C++14 标准实现）**

最经典用途：**非递归遍历元组**，替代 C++11 递归方案。

```c++
// 辅助展开函数
template <typename Tuple, size_t... Indices>
void print_tuple_impl(const Tuple& t, std::index_sequence<Indices...>) {
    ((std::cout << std::get<Indices>(t) << " "), ...) << std::endl;
}
// 对外接口：自动生成匹配 tuple 长度的序列
template <typename... Args>
void print_tuple(const std::tuple<Args...>& t) {
    print_tuple_impl(t, std::index_sequence_for<Args...>{});
}
auto t = std::make_tuple(10, "hello", 3.14);
print_tuple(t); // 输出：10 hello 3.14
```

**数组初始化 / 编译期数组生成**

用整数序列为数组**批量赋值**，实现编译期初始化。

```c++
template <size_t N, size_t... Indices>
constexpr std::array<int, N> create_array_impl(std::index_sequence<Indices...>) {
    // 用序列值初始化数组：array[0]=0, array[1]=1...
    return {Indices...};
}

```

**完美转发参数包（重构函数）**

配合 `std::forward`，通过整数序列**转发元组参数**到函数（C++17 `std::apply` 底层原理）。

```c++
void func(int a, double b, const std::string& c) {
    std::cout << a << " " << b << " " << c << std::endl;
}
// 元组参数解包调用函数
template <typename Func, typename Tuple, size_t... Indices>
decltype(auto) apply_impl(Func&& f, Tuple&& t, std::index_sequence<Indices...>) {
    return std::forward<Func>(f)(std::get<Indices>(std::forward<Tuple>(t))...);
}
template <typename Func, typename Tuple>
decltype(auto) apply(Func&& f, Tuple&& t) {
    return apply_impl(
        std::forward<Func>(f),
        std::forward<Tuple>(t),
        std::make_index_sequence<std::tuple_size_v<std::decay_t<Tuple>>>{}
    );
}
auto t = std::make_tuple(10, 3.14, "test");
apply(func, t); 
// 输出：10 3.14 test
```

用于构造函数、静态函数的编译期参数展开。

## 核心规则与注意事项

- 关键特性

  - **纯编译期**：`integer_sequence` 是空类，无运行时开销；

  - **无递归**：通过模板推导展开，替代递归元编程；

  - **类型安全**：仅处理整数类型（`int`/`size_t`）；

  - **配合折叠表达式**：C++17 折叠 + C++14 序列 = 完美可变参数处理。

- **常见误区**

  - 误区 1：`integer_sequence` 是运行时数据

    错误：它是**类型**，仅存在于编译期，不占内存；

  - 误区 2：`make_index_sequence<N>` 生成 `1~N`

    错误：生成 **`0~N-1`**；

  - 误区 3：C++11 可用

    错误：**C++14 专属**。

- **最佳实践**

  - 优先使用 `std::index_sequence`（`size_t` 类型）；
  - 遍历元组、数组、参数包时，用**序列推导 + 辅助函数**；
  - 与 `constexpr` 结合实现编译期计算；
  - 与 C++17 折叠表达式搭配，代码极简。

# `<functional>` 中的透明比较器

C++14 为 `<functional>` 库引入了**透明比较器（Transparent Comparators）**，核心是给 `std::less`/`std::greater` 等增加了**模板特化 `std::less<>`**（空尖括号）。它允许关联容器（`std::map`/`std::set`）**在查找时避免不必要的类型转换 / 拷贝**，大幅提升性能，同时让异构查找（heterogeneous lookup）成为可能。

核心价值：**让比较器 “透明” 地处理不同但兼容的类型**，实现**无拷贝、无隐式转换、高效查找**，是现代 C++ 优化 `map/set` 的关键特性。

## 背景

C++11 及之前的比较器存在严重缺陷：

```c++
std::set<std::string> s = {"apple", "banana"};
// C++11 问题：查找时必须传入 std::string
// 会发生 const char* → std::string 的**临时对象拷贝**，性能损耗
auto it = s.find(std::string("apple")); 
// 直接传字符串字面量会编译失败！
// 因为 less<string> 只能比较 string 和 string
auto it = s.find("apple"); // ERROR in C++11
```

**痛点总结**：

1. **查找必须创建临时对象**，造成拷贝开销；
2. **不支持异构查找**：无法用 `const char*` 查 `std::string`、用 `std::string_view` 查 `std::string`；
3. **类型强绑定**，比较器不灵活。

## 核心语法和基础使用

C++14 引入了**无模板参数的比较器特化**：

| 透明比较器（C++14）    | 等价含义                   | 作用           |
| ---------------------- | -------------------------- | -------------- |
| `std::less<>`          | `std::less<void>`          | 透明小于比较器 |
| `std::greater<>`       | `std::greater<void>`       | 透明大于比较器 |
| `std::less_equal<>`    | `std::less_equal<void>`    | 透明小于等于   |
| `std::greater_equal<>` | `std::greater_equal<void>` | 透明大于等于   |

**核心特性**

1. **透明（异构）**：可比较**两个不同但兼容的类型**（如 `std::string` 和 `const char*`）；
2. **无拷贝**：查找时**不创建临时对象**；
3. **完美转发**：内部使用完美转发，保留值类别（左值 / 右值）；
4. **自动推导**：无需指定比较类型，自动推导。

**高效 std::set（推荐写法）**

```c++
// C++14 透明比较器：less<>
std::set<std::string, std::less<>> s{"apple", "banana", "orange"};
// 直接传入字符串字面量，无拷贝、无临时string
auto it = s.find("apple");
// 也支持 string_view（零拷贝）
auto it2 = s.find(std::string_view("banana"));
```

**高效 std::map**

```c++
// key 是 string，比较器用 less<>
std::map<std::string, int, std::less<>> map{
    {"one", 1}, {"two", 2}
};
// 直接用 const char* 查找，零拷贝
auto it = map.find("one"); 
```

## 透明比较器的工作原理

`std::less<>` 是 `std::less<void>` 的别名，它的 `operator()` 是**模板化**的：

```c++
// 简化实现
template<>
struct less<void> {
    template<typename T, typename U>
    constexpr auto operator()(T&& t, U&& u) const
        noexcept(noexcept(std::forward<T>(t) < std::forward<U>(u)))
        -> decltype(std::forward<T>(t) < std::forward<U>(u))
    {
        return std::forward<T>(t) < std::forward<U>(u);
    }
};
```

- 接受**任意两个类型** `T`、`U`；
- 只要 `T < U` 合法，就能比较；

- 完美转发，无拷贝。

## 核心使用场景

**字符串容器的高性能查找（最常用）**

**避免 `const char\*` → `std::string` 的临时拷贝**，性能提升显著。

```c++
// 普通写法（C++11，慢）
std::set<std::string> s1;
s1.find(std::string("test")); // 拷贝构造临时string

// 透明写法（C++14，快）
std::set<std::string, std::less<>> s2;
s2.find("test"); // 无拷贝，直接比较
```

**配合 std::string_view 零成本查找**

现代 C++ 最佳实践：

```c++
std::map<std::string, int, std::less<>> m;
m.find(std::string_view("key")); // 零拷贝
```

**智能指针容器查找**

用裸指针查找 `shared_ptr` 容器：

```c++
std::set<std::shared_ptr<int>, std::less<>> s;
int* raw_ptr = new int(10);
s.find(raw_ptr); // 透明比较，无需构造临时 shared_ptr
```

| 方式       | 比较器                   | 查找写法            | 临时对象        | 性能 |
| ---------- | ------------------------ | ------------------- | --------------- | ---- |
| C++11 旧版 | `std::less<std::string>` | `find(string("a"))` | 创建临时 string | 慢   |
| C++14 透明 | `std::less<>`            | `find("a")`         | 无              | 快   |

## 核心规则与注意事项

- **必须显式指定比较器**
  - **容器默认不会使用透明比较器**，必须手动写：

```c++
std::set<std::string, std::less<>> s;// 正确
std::set<std::string> s; // 默认仍是 less<string>，不透明
```

- **严格弱序不变**
  - 透明比较器**必须保持严格弱序**（和普通比较器规则一致），否则容器行为未定义。

- **适用容器**

  - 仅**关联容器**需要：

  - `std::set` / `std::map`
  - `std::multiset` / `std::multimap`
  - 无序容器 `unordered_map` 不适用（需要哈希透明）。

# `std::shared_timed_mutex` 和 `std::shared_lock`

C++14 引入 `std::shared_timed_mutex`（共享定时互斥量）和配套的 `std::shared_lock`（共享锁），实现了**读写锁（Reader-Writer Lock）** 机制 —— 允许多个读操作并发执行，写操作独占执行。这填补了 C++11 仅支持独占锁（`std::mutex`/`std::lock_guard`）的空白，大幅提升了 “多读少写” 场景下的并发性能，是并发编程中优化读操作吞吐量的核心工具。

核心价值：**区分读 / 写操作的锁权限，读操作共享加锁（并发执行），写操作独占加锁（互斥执行）**，在保证数据一致性的前提下，最大化读密集型场景的并发效率。

## 背景

C++11 仅提供 `std::mutex`（独占互斥量）和 `std::lock_guard`/`std::unique_lock`（独占锁），所有操作（无论读写）都需独占锁，导致以下痛点：

1. **读操作并发阻塞**：即使多个读操作无数据竞争，也需串行执行，浪费多核资源；
2. **性能瓶颈**：“多读少写” 场景（如配置读取、缓存查询）中，独占锁导致读吞吐量极低；
3. **无定时加锁能力**：无法实现 “限时尝试加锁”，易导致线程永久阻塞。

```c++
std::mutex mtx;
int shared_data = 0;
// 读操作（本可并发，却因独占锁串行）
void read_data() {
    std::lock_guard<std::mutex> lock(mtx); // 独占锁
    // 模拟读操作
    for (int i = 0; i < 1000000; ++i) {}
    std::cout << "Read: " << shared_data << std::endl;
}
std::vector<std::thread> threads;
for (int i = 0; i < 4; ++i) {
    threads.emplace_back(read_data);
}
for (auto& t : threads) { t.join(); }
// 输出：4个读操作串行执行，耗时远高于并发执行
```

## 核心语法和基础使用

**读写锁核心模型**

| 锁类型         | 权限               | 兼容场景                       | 适用操作 |
| -------------- | ------------------ | ------------------------------ | -------- |
| 共享锁（读锁） | 多个线程可同时持有 | 与其他共享锁兼容，与独占锁互斥 | 读操作   |
| 独占锁（写锁） | 仅一个线程可持有   | 与所有锁（共享 / 独占）都互斥  | 写操作   |

**`std::shared_timed_mutex` 核心接口**

`std::shared_timed_mutex` 是 `<shared_mutex>` 头文件中的互斥量类型，支持两类加锁：

| 接口                    | 功能                                  | 锁类型 |
| ----------------------- | ------------------------------------- | ------ |
| `lock()`                | 独占加锁（写锁），阻塞直到获取锁      | 独占锁 |
| `lock_shared()`         | 共享加锁（读锁），阻塞直到获取锁      | 共享锁 |
| `try_lock()`            | 尝试独占加锁，立即返回 bool（非阻塞） | 独占锁 |
| `try_lock_shared()`     | 尝试共享加锁，立即返回 bool（非阻塞） | 共享锁 |
| `try_lock_for()`        | 限时尝试独占加锁（C++14 定时能力）    | 独占锁 |
| `try_lock_shared_for()` | 限时尝试共享加锁                      | 共享锁 |
| `unlock()`              | 释放独占锁                            | 独占锁 |
| `unlock_shared()`       | 释放共享锁                            | 共享锁 |

**`std::shared_lock` 核心语法**

`std::shared_lock` 是共享锁的 RAII 封装（类似 `std::lock_guard` 对独占锁的封装），自动管理共享锁的生命周期：

```c++
// 基础语法
std::shared_timed_mutex mtx;
// 共享加锁（读锁）：RAII 自动释放
std::shared_lock<std::shared_timed_mutex> read_lock(mtx); 
// 手动控制加锁/解锁（非RAII）
std::shared_lock<std::shared_timed_mutex> read_lock2(mtx, std::defer_lock); // 延迟加锁
read_lock2.lock_shared(); // 手动共享加锁
// ... 读操作 ...
read_lock2.unlock(); // 手动释放
```

**完整使用示例（多读少写）**

```c++
// 共享互斥量（读写锁核心）
std::shared_timed_mutex st_mtx;
int shared_counter = 0;
// 读操作：共享加锁（并发执行）
void reader(int id) {
    // 共享锁：多个reader可同时持有
    std::shared_lock<std::shared_timed_mutex> lock(st_mtx);
    std::cout << "Reader " << id << " read: " << shared_counter << std::endl;
    // 模拟耗时读操作（验证并发）
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
}
// 写操作：独占加锁（串行执行）
void writer(int id) {
    // 独占锁：用unique_lock封装独占加锁
    std::unique_lock<std::shared_timed_mutex> lock(st_mtx);
    shared_counter++;
    std::cout << "Writer " << id << " wrote: " << shared_counter << std::endl;
    std::this_thread::sleep_for(std::chrono::milliseconds(50));
}
std::vector<std::thread> threads;
// 启动8个读线程（并发执行）
for (int i = 0; i < 8; ++i) {
    threads.emplace_back(reader, i);
}
// 启动2个写线程（串行执行）
for (int i = 0; i < 2; ++i) {
    threads.emplace_back(writer, i);
}
for (auto& t : threads) {
    t.join();
}
/* 典型输出（读操作并发，写操作独占）：
Reader 0 read: 0
Reader 1 read: 0
Reader 2 read: 0
Reader 3 read: 0
Reader 4 read: 0
Reader 5 read: 0
Reader 6 read: 0
Reader 7 read: 0
Writer 0 wrote: 1
Writer 1 wrote: 2*/
```

## 核心使用场景

**读密集型数据缓存**

最典型场景：缓存系统（如配置缓存、热点数据缓存），读操作远多于写操作，共享锁大幅提升并发读性能：

```c++
// 配置缓存：读多写少
class ConfigCache {
private:
    std::unordered_map<std::string, std::string> cache_;
    std::shared_timed_mutex mtx_; // 读写锁
public:
    // 读操作：共享加锁
    std::string get(const std::string& key) {
        std::shared_lock lock(mtx_); // 共享锁，多个读线程并发
        auto it = cache_.find(key);
        return it != cache_.end() ? it->second : "";
    }

    // 写操作：独占加锁
    void set(const std::string& key, const std::string& value) {
        std::unique_lock lock(mtx_); // 独占锁，串行写
        cache_[key] = value;
    }

    // 批量更新：独占加锁
    void update_batch(const std::unordered_map<std::string, std::string>& data) {
        std::unique_lock lock(mtx_);
        for (const auto& [k, v] : data) {
            cache_[k] = v;
        }
    }
};
// 测试：多线程读，单线程写
ConfigCache cache;
void batch_read() {
    for (int i = 0; i < 1000; ++i) {
        cache.get("db_host");
    }
}
void single_write() {
    cache.set("db_host", "127.0.0.1");
    cache.set("db_port", "3306");
}
```

**定时加锁（避免永久阻塞）**

`std::shared_timed_mutex` 支持定时加锁，适合对响应时间有要求的场景，避免线程因锁阻塞超时：

```c++
// 限时尝试共享加锁（读操作）
bool try_read_with_timeout(int& data, int timeout_ms) {
    std::shared_lock<std::shared_timed_mutex> lock(
        st_mtx, 
        std::chrono::milliseconds(timeout_ms) // 限时加锁
    );
    if (lock.owns_lock()) { // 成功获取共享锁
        data = shared_counter;
        return true;
    }
    return false; // 超时未获取锁
}
// 限时尝试独占加锁（写操作）
bool try_write_with_timeout(int new_value, int timeout_ms) {
    std::unique_lock<std::shared_timed_mutex> lock(
        st_mtx,
        std::chrono::milliseconds(timeout_ms)
    );
    if (lock.owns_lock()) {
        shared_counter = new_value;
        return true;
    }
    return false;
}
int data;
// 尝试100ms内获取读锁
if (try_read_with_timeout(data, 100)) {
    std::cout << "Read success: " << data << std::endl;
} else {
    std::cout << "Read timeout" << std::endl;
}
```

**动态切换锁类型（升级 / 降级）**

可通过手动控制锁的生命周期，实现 “读锁升级为写锁” 或 “写锁降级为读锁”（需注意死锁风险）：

```c++
// 锁降级：写锁 → 读锁（安全）
void downgrade_lock_example() {
    // 1. 先获取独占写锁
    std::unique_lock<std::shared_timed_mutex> write_lock(st_mtx);
    shared_counter = 100; // 写操作
    
    // 2. 降级为共享读锁（释放写锁，获取读锁）
    std::shared_lock<std::shared_timed_mutex> read_lock(std::move(write_lock));
    std::cout << "Downgraded: " << shared_counter << std::endl; // 读操作
    // 其他读线程可并发访问
}
// 锁升级：读锁 → 写锁（需先释放读锁，否则死锁）
void upgrade_lock_example() {
    // 1. 先获取共享读锁
    std::shared_lock<std::shared_timed_mutex> read_lock(st_mtx);
    if (shared_counter < 100) {
        // 2. 必须先释放读锁，再尝试获取写锁
        read_lock.unlock();
        std::unique_lock<std::shared_timed_mutex> write_lock(st_mtx);
        shared_counter += 10; // 写操作
    }
}
```

## 核心规则与注意事项

- 关键限制与行为
  - 锁兼容性：
    - 多个共享锁（读锁）可共存；
    - 独占锁（写锁）与任何锁（共享 / 独占）互斥；
    - 写锁优先级：部分实现中写锁优先级高于读锁（避免写饥饿），但标准未强制。

- 死锁风险：
  - 锁升级时若不先释放读锁，会导致死锁（当前线程持有读锁，又尝试获取写锁，而写锁需等待所有读锁释放）；
  - 避免嵌套锁：同一线程不要同时持有多个共享锁 / 独占锁。
- **C++17 简化**：C++17 引入 `std::shared_mutex`（无定时功能的轻量版），仅支持 `lock()`/`lock_shared()` 等基础接口，性能略优。

| 场景     | std::mutex（独占锁） | std::shared_timed_mutex（读写锁） |
| -------- | -------------------- | --------------------------------- |
| 纯读操作 | 串行执行，性能低     | 并发执行，性能高                  |
| 纯写操作 | 性能略优（无锁切换） | 性能略低（锁类型判断）            |
| 多读少写 | 性能差               | 性能大幅提升（核心优势）          |
| 多写少读 | 更适用               | 无优势，甚至性能更低              |

- RAII 封装的必要性

  - 必须使用 `std::shared_lock`/`std::unique_lock` 封装 `std::shared_timed_mutex`，避免手动解锁遗漏导致的死锁；

  - `std::lock_guard` 仅支持独占锁，不能用于共享锁。

| 特性     | C++ `std::shared_timed_mutex` | Java `ReentrantReadWriteLock` |
| -------- | ----------------------------- | ----------------------------- |
| 可重入性 | 不可重入                      | 可重入                        |
| 定时加锁 | 支持（C++14）                 | 支持                          |
| 锁降级   | 支持（手动）                  | 支持（内置方法）              |
| 锁升级   | 需手动释放读锁                | 支持（但易死锁）              |
| 性能     | 原生实现，性能优              | JVM 层面实现，略逊            |
