# 内联变量

C++17 引入的**内联变量（Inline Variables）** 是解决 C++ 多年来**全局 / 静态变量跨文件重复定义**问题的革命性语法糖。它允许你**直接在头文件中定义全局变量、类静态成员变量**，而无需担心链接错误，彻底告别了繁琐的 `.cpp` 实现文件。

核心价值：**头文件即定义，跨文件安全共享，自动去重，仅初始化一次**。完美解决了 C++ 中静态成员变量和全局常量必须分散在头文件与源文件中的历史痛点。

## 背景

在 C++17 之前，全局变量和类的**静态成员变量**遵循 **One Definition Rule (ODR，单一定义规则)**：

- 若在**头文件**中**定义**变量，当该头文件被多个 `.cpp` 文件包含时，会产生**多个定义**，链接器报 **multiple definition** 错误；
- 必须在**头文件声明** + **.cpp 文件定义**，代码分散、维护繁琐。

```c++
// C++14 痛点：类静态成员变量必须分文件写
// config.h (头文件)
struct Config {
    static int max_count; // 仅声明
};
// config.cpp (源文件)
int Config::max_count = 100; // 必须在cpp中定义
```

## 核心语法与基础使用

`inline` 关键字直接修饰变量定义，即可实现**头文件内联定义**：

**类静态成员内联变量**

直接在**类内部**初始化静态成员，无需 `.cpp` 文件：

```c++
struct Config {
    // C++17：直接在头文件定义+初始化，无需cpp
    inline static int max_count = 100;
    // 常量可省略 inline（constexpr 变量隐式内联）
    static constexpr double PI = 3.14159;
};
// 直接使用，无需链接额外cpp文件
int main() {
    std::cout << Config::max_count << std::endl; // 100
    std::cout << Config::PI << std::endl;        // 3.14159
}
```

**全局 / 命名空间内联变量**

在头文件中定义全局共享变量，多文件包含安全无冲突：无论被多少个 `.cpp` 包含，**全局仅有一份实例**。

```c++
namespace Global {
    // 全局共享变量，头文件直接定义
    inline std::string app_name = "MyApp";
    inline int version = 1;
}
```

**多文件共享**

```c++
// test.h
inline int shared_val = 10; // 内联变量
// a.cpp
#include "test.h"
void set_val() { shared_val = 20; } // 修改
// b.cpp
#include "test.h"
void print_val() { std::cout << shared_val << std::endl; } // 读取
// main.cpp
#include "test.h"
extern void set_val();
extern void print_val();
int main() {
    set_val();   // 20
    print_val(); // 20（全局唯一实例）
}
```

**核心规则**

1. **头文件安全**：允许多次包含，**链接期自动去重**，仅保留一个实例；
2. **初始化保证**：**全局仅初始化一次**，避免多次构造 / 析构；
3. **与 `constexpr` 兼容**：`constexpr` 静态成员变量**隐式内联**，无需手动加 `inline`；
4. **作用域不变**：作用域与普通变量完全一致，仅改变链接行为；
5. **有序初始化**：与其他全局变量遵循相同的初始化顺序规则。

## 核心使用场景

**类静态常量 / 配置变量**

替代传统的 “头文件声明 + cpp 定义”，代码极简：

```c++
// C++17 最优写法
class Math {
public:
    // 常量：隐式 inline
    static constexpr double E = 2.71828;
    // 可读写静态变量：显式 inline
    inline static int counter = 0;
};
```

**头文件专用库 (Header-Only Libraries)**

纯头文件库的**必备特性**，无需链接静态 / 动态库，直接使用：

```c++
struct Logger {
    inline static bool enable_debug = true;
    static void log(const char* msg) {
        if (enable_debug) std::cout << msg << std::endl;
    }
};
```

**全局共享配置**

跨模块共享的全局参数，集中在头文件管理：

```c++
namespace AppConfig {
    inline int port = 8080;
    inline std::string host = "localhost";
    inline bool is_running = true;
}
```

**替代匿名命名空间**

匿名命名空间变量仅当前文件可见，而**内联变量全局共享**：

```c++
namespace { int local_val = 0; }// 匿名空间：仅本文件可见
inline int global_val = 0;// 内联变量：全局可见，唯一实例
```

## 核心规则与注意事项

| 特性           | 内联变量 (C++17)            | 传统写法 (C++14 及之前)     |
| -------------- | --------------------------- | --------------------------- |
| **定义位置**   | **头文件直接定义 + 初始化** | 头文件声明，.cpp 文件定义   |
| **多文件包含** | 安全，**自动去重**          | 报 multiple definition 错误 |
| **代码量**     | 极简，一行完成              | 两行，分文件编写            |
| **实例数量**   | **全局唯一实例**            | 唯一（但写法繁琐）          |
| **纯头文件库** | 完美支持                    | 无法支持                    |

- **`constexpr` 隐式 `inline`**：
  - `static constexpr` 变量**自动是内联的**，无需额外写 `inline`；
- **仅影响链接行为**：
  - 内联变量的作用域、访问控制与普通变量完全一致；

- **线程安全**：
  - 多线程同时读写内联变量**仍需加锁**，`inline` 不提供线程安全保障；

- **初始化顺序**：
  - 跨文件全局变量的初始化顺序未定义，内联变量也遵循此规则。

# 类模板实参推导

C++17 引入的**类模板实参推导（CTAD）** 是模板语法的重大简化，允许编译器根据类模板的构造函数参数**自动推导模板实参**，无需显式指定模板参数。这一特性填补了 C++ 模板体系中 “类模板无法像函数模板一样自动推导参数” 的空白，让类模板的使用语法与普通类一致，大幅降低了模板代码的使用门槛，提升了代码的简洁性和可读性。

核心价值：**类模板的模板参数可由构造函数参数自动推导**，消除显式指定模板参数的冗余代码，让 `std::pair`/`std::vector`/ 自定义类模板的实例化更直观，符合 “最小惊讶原则”。

## 背景

C++17 之前，类模板的实例化必须**显式指定所有模板参数**，即使构造函数参数足以明确模板类型，也无法自动推导，导致以下痛点：

1. **代码冗余**：模板参数与构造函数参数类型重复，如 `std::pair<int, std::string> p(1, "hello");` 中 `int`/`std::string` 重复声明；
2. **语法繁琐**：复杂模板类型（如 `std::map<std::string, std::vector<int>>`）的显式指定易出错，且代码冗长；
3. **与函数模板不一致**：函数模板可自动推导参数，类模板却不行，语法规则不统一；
4. **临时对象创建复杂**：创建类模板临时对象时，需完整指定模板参数，如 `func(std::vector<int>{1,2,3});`。

```c++
// 1. 冗余：int 重复指定
std::vector<int> vec1{1, 2, 3}; 
// 2. 繁琐：pair 的两个模板参数需手动指定
std::pair<int, std::string> p1(10, "test");
// 3. 复杂类型更易出错
std::map<std::string, std::vector<int>> map1{{"a", {1,2}}, {"b", {3,4}}};
// 自定义类模板：必须显式指定 T
template <typename T>
struct Box {
    Box(T val) : value(val) {}
    T value;
};
Box<int> box1(10); // 必须写 <int>，即使构造函数参数是 int
```

## 核心语法与基础使用

CTAD 的核心是：编译器通过**类模板的构造函数参数类型**，自动推导模板参数的类型 / 值，生成对应的类模板实例。

```c++
// C++17 前：显式指定模板参数
TemplateClass<Type1, Type2> obj(args);
// C++17 后：CTAD 自动推导
TemplateClass obj(args);
```

**标准库容器的 CTAD**

```c++
// 1. vector：从初始化列表推导 T = int
std::vector vec{1, 2, 3, 4}; // 等价于 std::vector<int> vec{1,2,3,4}
std::cout << typeid(vec).name() << std::endl; // 输出：std::vector<int, std::allocator<int>>
// 2. pair：从构造参数推导 T1=int, T2=std::string
std::pair p(100, "hello"); // 等价于 std::pair<int, const char*> 或 std::pair<int, std::string>（编译器自动适配）
std::cout << p.first << ", " << p.second << std::endl; // 100, hello
// 3. map：推导键值对类型为 std::string → std::vector<int>
std::map map{{"math", {90, 85}}, {"english", {95, 88}}};
// 等价于 std::map<std::string, std::vector<int>> map{...}
```

**自定义类模板的 CTAD**

```c++
// 自定义类模板
template <typename T, typename U>
struct Pair {
    T first;
    U second;
    // 构造函数：参数类型对应模板参数 T、U
    Pair(T f, U s) : first(f), second(s) {}
};
// 单模板参数类模板
template <typename T>
struct Box {
    T value;
    // 构造函数推导 T
    Box(T val) : value(val) {}
    // 多构造函数也支持推导（编译器匹配最匹配的构造函数）
    Box(T val1, T val2) : value(val1 + val2) {}
};
    // 1. 推导 T=int, U=double
    Pair p(10, 3.14); 
    std::cout << p.first << ", " << p.second << std::endl; // 10, 3.14
    // 2. 推导 T=int（匹配单参数构造函数）
    Box b1(5); 
    std::cout << b1.value << std::endl; // 5
    // 3. 推导 T=int（匹配双参数构造函数）
    Box b2(3, 7);
    std::cout << b2.value << std::endl; // 10
```

## 推导指南（Deduction Guides）

当默认的 CTAD 推导规则无法满足需求（如构造函数参数类型与模板参数类型不一致），可通过**推导指南**（Deduction Guides）手动指定推导规则，这是 CTAD 的扩展特性。

```c++
// 类模板：模板参数 T 是存储类型，构造函数参数是 const char*
template <typename T>
struct StringWrapper {
    T str;
    // 构造函数参数是 const char*，默认 CTAD 无法推导 T=std::string
    StringWrapper(const char* s) : str(s) {}
};
// 推导指南：告诉编译器，当构造参数是 const char* 时，推导 T=std::string
StringWrapper(const char*) -> StringWrapper<std::string>;
    // CTAD + 推导指南：推导 T=std::string
    StringWrapper sw("hello world");
    std::cout << sw.str << std::endl; // hello world
    std::cout << typeid(sw.str).name() << std::endl; // std::string
```

**标准库的推导指南示例**

标准库为容器提供了预定义的推导指南，例如：

```c++
// std::vector 的推导指南（简化版）
template <typename Iter>
vector(Iter first, Iter last) -> vector<typename std::iterator_traits<Iter>::value_type>;
// 使用推导指南：从迭代器推导 T=int
std::vector vec(std::begin({1,2,3}), std::end({1,2,3}));
```

## 核心使用场景

**简化标准库容器的实例化**

CTAD 最常用的场景是简化 `std::vector`/`std::map`/`std::pair` 等标准库容器的实例化，消除冗余的模板参数：

```c++
// 1. unordered_map：推导键=std::string，值=int
std::unordered_map um{{"apple", 5}, {"banana", 3}};
for (const auto& [k, v] : um) {
    std::cout << k << ": " << v << std::endl;
}
// 2. set：推导 T=int
std::set s{1, 3, 5, 7};
for (int num : s) {
    std::cout << num << " ";
} // 1 3 5 7
// 3. pair 嵌套推导
std::pair p(std::make_pair(1, 2), std::make_pair(3.14, "pi"));
// 推导为 std::pair<std::pair<int,int>, std::pair<double, const char*>>
std::cout << p.first.first << ", " << p.second.second << std::endl; // 1, pi
```

**自定义类模板的简洁使用**

CTAD 让自定义类模板的使用与普通类无差异，降低用户使用成本：

```c++
// 业务场景：通用数据包装器
template <typename T>
struct DataWrapper {
    T data;
    bool is_valid;

    // 构造函数1：仅数据
    DataWrapper(T d) : data(d), is_valid(true) {}
    // 构造函数2：数据 + 有效性
    DataWrapper(T d, bool valid) : data(d), is_valid(valid) {}
};
// 推导指南：当构造参数是 const char* 时，推导 T=std::string
DataWrapper(const char*) -> DataWrapper<std::string>;
    // 1. 推导 T=int
    DataWrapper dw1(100);
    std::cout << dw1.data << ", " << std::boolalpha << dw1.is_valid << std::endl; // 100, true
    // 2. 推导 T=double
    DataWrapper dw2(3.14, false);
    std::cout << dw2.data << ", " << dw2.is_valid << std::endl; // 3.14, false
    // 3. 推导指南生效：T=std::string
    DataWrapper dw3("test data");
    std::cout << dw3.data << std::endl; // test data
```

**模板参数的非类型推导**

CTAD 不仅支持类型参数推导，还支持**非类型模板参数**的推导（如数值、大小等）：

```c++
// 非类型模板参数：数组大小 N
template <typename T, size_t N>
struct FixedArray {
    T arr[N];
    // 构造函数：从初始化列表推导 T 和 N
    FixedArray(std::initializer_list<T> list) {
        size_t i = 0;
        for (const auto& val : list) {
            if (i < N) arr[i++] = val;
        }
    }
};
// 推导指南：从初始化列表推导 T 和 N
template <typename T, typename... Args>
FixedArray(T, Args...) -> FixedArray<T, 1 + sizeof...(Args)>;
    // 推导 T=int, N=3
    FixedArray arr{1, 2, 3};
    std::cout << sizeof(arr.arr)/sizeof(arr.arr[0]) << std::endl; // 3
    // 推导 T=double, N=2
    FixedArray arr2{3.14, 2.718};
    std::cout << arr2.arr[0] << ", " << arr2.arr[1] << std::endl; // 3.14, 2.718
```

**与结构化绑定结合**

CTAD + 结构化绑定，让复合类型的使用更简洁：

```c++
// CTAD 推导 tuple 的模板参数：int, std::string, bool
auto t = std::tuple(10, "hello", true);
// 结构化绑定解构
auto [id, msg, flag] = t;
std::cout << id << ", " << msg << ", " << flag << std::endl; // 10, hello, 1
```

## 核心规则与注意事项

- 关键限制与行为

  - 推导失败的场景：
    - 构造函数参数无法唯一确定模板参数（如重载构造函数导致歧义）；
    - 模板参数与构造函数参数无直接关联（需推导指南补充）；
    - 非类型模板参数无法从构造参数推导（需推导指南）。

  - 推导优先级：
    - 手动指定的模板参数 > 推导指南 > 默认 CTAD 推导；
    - 若推导结果有歧义，编译器报错（需显式指定模板参数）。

  - 不支持的场景：
    - 类模板的静态成员函数调用无法触发 CTAD；
    - 推导模板参数后，若类模板实例化非法（如类型不匹配），编译报错；
    - C++17 不支持部分推导（必须推导所有模板参数，C++20 支持部分推导）。

- 推导指南的使用原则

  - 推导指南仅用于**补充默认 CTAD 的不足**，不要滥用（否则增加代码复杂度）；

  - 推导指南的参数类型需与构造函数参数类型匹配；

  - 推导指南不影响类的构造，仅影响模板参数推导。

- 与函数模板推导的区别

| 特性           | 类模板实参推导（CTAD）           | 函数模板参数推导             |
| -------------- | -------------------------------- | ---------------------------- |
| 触发方式       | 类实例化时，通过构造函数参数推导 | 函数调用时，通过函数参数推导 |
| 扩展方式       | 推导指南                         | 模板特化 / 重载              |
| 部分推导       | C++17 不支持，C++20 支持         | 天然支持                     |
| 非类型参数推导 | 需推导指南                       | 直接推导                     |

# 模板模板参数的简写语法

C++17 为**模板模板参数**带来了关键的**简写语法（省略形参名称）**，彻底解决了传统写法中**无用形参名冗余**的问题，让模板代码更简洁、更符合现代 C++ 风格。

核心价值：**模板模板参数无需声明无用的形参名称，直接用`class`/`typename`声明即可**，消除冗余代码，让嵌套模板的写法更清爽。

## 背景

模板模板参数是 **“模板的模板”**，即参数本身是一个模板（如`std::vector`、`std::list`）。

在**C++17 之前**，模板模板参数有一个强制冗余规则：

即使**完全用不到**形参名称，也**必须声明一个形参名**，否则编译报错，导致代码冗余。

```c++
// C++14 痛点：必须写无用的形参名（如 Args），即使从未使用
template <template <typename... Args> class Container>// 这里 Args 完全没用，但必须写！
struct Test { };
// 使用：
Test<std::vector> t;
```

## 核心语法与基础使用

C++17 允许**直接省略模板模板参数的形参名称**，仅保留参数类型声明，语法大幅简化：

传统写法（C++14 及之前，冗余）

```c++
template <template <typename... Args> class Container>
```

C++17 简写（推荐，无冗余）

```c++
template <template <typename...> class Container>
```

- **完全兼容旧代码**：C++17 支持传统写法，旧代码无需修改；
- **无功能差异**：简写仅简化语法，不改变模板模板参数的任何行为；
- **可变参数包必须写`...`**：可变参数模板仍需保留`...`，仅删除名称；
- `template <typename...> class T`
- ``template <typename> class T`（少`...`，无法匹配可变参数模板）
- **适用所有场景**：类模板、函数模板、变量模板的模板模板参数均支持；
- **`class`/`typename`等价**：声明模板模板参数时，`class`和`typename`完全通用。

**基础容器适配（最常用场景）**

```c++
// C++17 简写：无冗余形参名
template <template <typename...> class Container>
struct Wrapper {
    Container<int> data;
};
// 使用：直接传入模板（vector/list）
Wrapper<std::vector> w1; // 包装vector<int>
Wrapper<std::list> w2;   // 包装list<int>
```

**带固定参数的模板模板参数**

对于有**默认参数 / 固定参数**的模板，简写同样适用：

```c++
// 传统：template <template <typename T, typename Alloc> class Container>
// C++17：直接省略形参名
template <template <typename, typename> class Container>
struct Wrapper2 {
    Container<int, std::allocator<int>> data;
};
```

**混合`typename`/`class`的简写**

C++17 允许混用简写，完全兼容：

```c++
// 任意组合，均可省略形参名
template <template <typename, class, int> class Tpl>
struct Test3 { };
```

## 核心使用场景

**通用容器封装（最主流）**

```c++
// C++17 标准写法
template <template <typename...> class Container>
int get_size(const Container<int>& c) {
    return c.size();
}
get_size(std::vector<int>{1,2,3}); // 兼容vector、list、deque等所有容器
```

**模板元编程**

```c++
// 编译期判断：类型是否为指定模板的实例
template <template <typename...> class Template, typename T>
struct is_instance : std::false_type {};
template <template <typename...> class Template, typename... Args>
struct is_instance<Template, Template<Args...>> : std::true_type {};
// 测试：std::vector<int> 是否为 vector 的实例
is_instance<std::vector, std::vector<int>>::value; // true
```

**纯头文件库**

```c++
// 纯头文件工具类
template <template <typename...> class Container>
struct Tool {
    static void clear(Container<int>& c) { c.clear(); }
};
```

## 核心规则与注意事项

| 特性         | C++17 简写语法       | C++14 传统写法           |
| ------------ | -------------------- | ------------------------ |
| **形参名**   | **可省略**（无冗余） | **必须声明**（即使无用） |
| **代码长度** | 短，清爽             | 长，冗余                 |
| **可读性**   | 极高                 | 一般（多余参数干扰）     |
| **可变参数** | `typename...`        | `typename... Args`       |
| **功能**     | 完全一致             | 完全一致                 |

- **必须 C++17 及以上**：C++11/14 不支持此简写，会编译报错；

- **固定参数不能省略**：仅省略**形参名**，参数种类（`typename`/`int`）不能删；
  - `template <typename, int> class T`
  - `template <typename> class T`（丢失`int`参数）

- **与`auto`非类型模板参数兼容**：C++17 可搭配`auto`使用：

```c++
// C++17：模板模板参数 + auto非类型参数
template <template <auto...> class T>
struct Test4 { };
```

# `__has_include` 预处理器运算符

C++17 引入的 **`__has_include`** 是一个**预处理器运算符**，专门用于**在编译前检查指定的头文件是否存在**。它让你可以根据头文件的可用性，**动态决定是否包含、启用 / 禁用对应功能**，是跨平台、跨标准、跨库兼容的核心预处理器工具。

核心价值：**编译期检测头文件是否存在，实现条件化包含代码，大幅提升跨平台 / 跨版本兼容性**，彻底解决传统预处理器无法判断头文件可用性的痛点。

## 背景

在 C++17 之前，**没有标准方式检测头文件是否存在**：

1. 无法判断目标平台 / 编译器是否提供某个头文件（如 `<optional>`、`<filesystem>`）；
2. 跨平台代码只能用**编译器宏、版本宏**间接判断，极易出错；
3. 包含不存在的头文件会直接触发**编译错误**，无法优雅降级。

## 核心语法与基础使用

`__has_include` 是**预处理器指令**，仅在**预处理阶段**执行，返回布尔值：

```c++
__has_include("头文件路径")  // 检查相对/当前目录头文件
__has_include(<系统头文件>) // 检查标准库/系统库头文件
```

**核心规则**

1. **预处理期执行**：早于编译，不生成运行时代码；
2. **返回值**：存在返回 `1`（true），不存在返回 `0`（false）；
3. **配合 `#if` 使用**：必须结合预处理器条件指令使用；
4. **大小写敏感**：头文件名称严格匹配（系统依赖）；
5. **标准兼容**：C++17、C11 及以上标准原生支持。

```c++
// 检查是否存在 <optional> 头文件
#if __has_include(<optional>)
    #include <optional>
    #define HAS_OPTIONAL 1
#else
    #define HAS_OPTIONAL 0
#endif
// 根据头文件可用性编写兼容代码
#if HAS_OPTIONAL
    std::optional<int> val = 42;
#else
    int val = 42;
#endif
```

**系统头文件（尖括号）**

用于标准库、系统库、第三方库头文件：

```c++
// 检查 C++17 文件系统库
#if __has_include(<filesystem>)
    #include <filesystem>
    namespace fs = std::filesystem;
// 检查旧版实验性文件系统库
#elif __has_include(<experimental/filesystem>)
    #include <experimental/filesystem>
    namespace fs = std::experimental::filesystem;
#else
    #error "不支持文件系统库"
#endif
```

**本地头文件（双引号）**

用于项目自定义头文件：

```c++
// 检查项目本地头文件是否存在
#if __has_include("config.h")
    #include "config.h"
#else
    #include "default_config.h"
#endif
```

## 核心使用场景

**跨标准 C++ 版本兼容**

根据编译器支持的 C++ 版本，自动适配头文件：

```c++
// C++17 新头文件自动检测
#if __has_include(<variant>)
    #include <variant>
#endif
#if __has_include(<any>)
    #include <any>
#endif
```

**跨平台兼容（Windows/Linux/macOS）**

检测系统特有头文件，实现平台无关代码：

```c++
// 跨平台网络头文件
#if __has_include(<winsock2.h>)
    #include <winsock2.h> // Windows
#elif __has_include(<unistd.h>)
    #include <unistd.h>  // Linux/macOS
#endif
```

**第三方库依赖检测**

检测第三方库头文件是否存在，自动启用对应功能：

```c++
// 检测是否安装了 spdlog 日志库
#if __has_include(<spdlog/spdlog.h>)
    #include <spdlog/spdlog.h>
    #define USE_SPDLOG 1
#else
    #define USE_SPDLOG 0
#endif
```

**头文件存在性断言**

强制要求必须存在某个头文件，否则友好报错：

```c++
#if !__has_include(<vector>)
    #error "编译必须支持 C++ 标准库 <vector>"
#endif
```

## 核心规则与注意事项

- 与标准版本无关
  - `__has_include` 本身是**预处理器指令**，即使编译器以 C++11/14 模式运行，**只要支持该扩展就可用**（GCC 5+, Clang 3.5+, MSVC 2017+）。
- 不递归检测
  - 仅检查**头文件是否存在**，不检查头文件内部的依赖是否完整。
- 可嵌套使用
  - 在头文件内部继续用 `__has_include` 检测其他依赖：

```c++
// a.h
#if __has_include(<b.h>)
    #include <b.h>
#endif
```

| 特性     | `__has_include` (C++17)    | 传统方案 (编译器 / 版本宏)     |
| -------- | -------------------------- | ------------------------------ |
| 检测方式 | **直接检测头文件是否存在** | 间接通过编译器 / OS / 版本判断 |
| 准确性   | 100% 精准                  | 易出错（版本兼容混乱）         |
| 可移植性 | **标准跨平台**             | 依赖非标准宏，不可移植         |
| 语法     | 简洁直观                   | 冗长复杂                       |
| 优雅降级 | 支持                       | 难以支持                       |

**注意事项**

1. **仅预处理期有效**：不能在运行时 / 普通代码中使用；
2. **大小写敏感**：`<Vector>` 和 `<vector>` 是不同文件；
3. **路径规则**：遵循编译器头文件搜索路径规则；
4. **不检查语法**：只判断文件是否存在，不检查头文件语法是否正确；
5. **宏兼容**：可配合 `#ifdef`/`#ifndef` 组合使用。

# 强制省略复制

C++17 引入的**强制省略复制（Mandatory Copy Elision，也叫强制返回值优化、强制拷贝消除）**，是 C++ 值类别体系的**革命性修正**。

它**强制编译器**在特定场景下**完全跳过对象的拷贝 / 移动构造**，**直接在目标内存原地构造对象**，不再是 “可选优化”，而是**语言标准保证**。

核心价值：**100% 保证零拷贝、零移动，代码可移植、行为可预测，不可拷贝 / 不可移动对象也能正常返回 / 传参**。

## 背景

C++11/14 中，**拷贝省略是可选优化**：

1. 编译器**可以选择**优化掉拷贝 / 移动，但**不是必须**；
2. 即使优化生效，**类仍必须提供可访问的拷贝 / 移动构造函数**，否则编译报错；
3. 不可拷贝、不可移动的对象（如 `std::unique_ptr` 以外的自定义类型）**无法按值返回 / 传参**；
4. 不同编译器优化行为不一致，代码行为不可预测。

```c++
// C++14 痛点：即使会被优化，也必须有拷贝/移动构造函数
struct NoCopy {
    NoCopy() = default;
    NoCopy(const NoCopy&) = delete; // 禁止拷贝
};
NoCopy foo() {
    return NoCopy{}; // C++14：编译错误！必须可拷贝/可移动
}
```

## 核心定义

C++17 标准规定：

当**纯右值** 用于**初始化同类型对象**时，**直接原地构造**，**完全不调用拷贝 / 移动构造**，且**不要求类提供拷贝 / 移动函数**。

强制省略复制**自动生效**，无需写任何关键字，满足条件就**100% 触发**。

**函数按值返回临时对象**

```c++
struct NoCopy {
    NoCopy() { std::cout << "构造\n"; }
    // 完全删除拷贝 + 移动
    NoCopy(const NoCopy&) = delete;
    NoCopy(NoCopy&&) = delete;
};
NoCopy create() {
    // C++17：强制优化，直接在调用处构造
    return NoCopy();
}
NoCopy obj = create(); // 零拷贝、零移动
```

**用临时对象直接初始化变量**

```c++
// 强制省略，直接构造
NoCopy obj = NoCopy();
NoCopy obj; //等价
```

**函数传参（临时对象做实参）**

```c++
void take(NoCopy) {}
take(NoCopy{}); // 直接构造到参数位置，无拷贝
```

## 核心使用场景

**不可拷贝、不可移动对象的正常返回**

```c++
struct OnlyDefaultConstruct {
    OnlyDefaultConstruct() = default;
    OnlyDefaultConstruct(const OnlyDefaultConstruct&) = delete;
    OnlyDefaultConstruct(OnlyDefaultConstruct&&) = delete;
};
OnlyDefaultConstruct make() {
    return OnlyDefaultConstruct();
}
```

**工厂模式 / 纯右值返回**

```c++
template <typename T, typename... Args>
T make(Args&&... args) {
    return T(std::forward<Args>(args)...); // 强制零拷贝
}
auto obj = make<NoCopy>();
```

**保证代码可移植**

不再依赖编译器优化开关，**所有平台行为一致**。

| 特性                        | C++17 强制省略复制 | C++14 可选优化        |
| --------------------------- | ------------------ | --------------------- |
| **是否保证**                | **100% 保证**      | 看编译器心情          |
| **是否需要拷贝 / 移动函数** | **不需要**         | **必须有（可访问）**  |
| **不可拷贝对象返回**        | ✅ 支持             | ❌ 编译失败            |
| **运行成本**                | 0（原地构造）      | 0（优化后）           |
| **适用对象**                | 临时对象 (prvalue) | 临时对象 + 具名返回值 |

## 核心规则与注意事项

1. **强制生效，不可关闭**

   不是优化，是**标准规定**，所有兼容 C++17 的编译器必须遵守。

2. **不要求拷贝 / 移动构造函数存在**

   即使 `=delete` 拷贝、移动，依然可以返回、传参、初始化。

3. **只针对 纯右值 (prvalue) 临时对象**

   - 临时对象：`foo()`、`A{}` → **可优化**
   - 具名对象：`A a; return a;` → **不属于强制优化（仍是可选优化）**

4. **完全零成本**

   不生成任何拷贝 / 移动代码，**运行时无任何开销**。

**特别注意**：具名返回值优化（NRVO）

```c++
NoCopy create() {
    NoCopy a;
    return a; // 具名对象
}
```

- 这是 **NRVO**，**C++17 仍然是可选优化**
- 不属于**强制省略复制**
- 依然要求类**可移动 / 可拷贝**
- 强制复制省略 **只针对临时对象**，不针对具名变量。

# `auto` 推导的规则调整

C++17 对 `auto` 类型推导做了**两项关键、实用、影响深远的规则调整**，彻底解决了 C++11/14 中 `auto` 推导不符合直觉、容易踩坑的问题，让 `auto` 更智能、更安全、更符合人类习惯。

核心价值：**auto 推导更贴近人类直觉，兼容花括号初始化，支持非类型模板参数，大幅减少类型错误**。

## 背景

C++11/14 中 `auto` 推导有两个**反直觉、极易踩坑**的设计：

- **用 `{}` 初始化，auto 强制推导为 `std::initializer_list`**

```c++
auto x = {1};  // C++11/14: 推导成 std::initializer_list<int>
```

- `auto` 不能作为非类型模板参数

```c++
template <auto N>  // C++11/14: 直接报错 ❌
struct X {};
```

## 核心语法与基础使用

**花括号初始化推导规则**

**只推导列表，不强行转 initializer_list**

C++17 把 `auto` + `{}` 推导分成**两种清晰情况**，完全符合直觉：

- **`auto x = { ... };` （赋值形式）**
  - *推导保持不变：仍然推导为 `std::initializer_list<T>`**

```c++
auto a = {1};     // std::initializer_list<int>
auto b = {1,2};   // std::initializer_list<int>
```

- **`auto x{ ... };` （直接初始化）**
  - **直接推导为单个元素的类型！**

```c++
auto x{1};        // C++17: int
auto y{1,2};      // C++17: 编译报错
```

**允许 `auto` 作为非类型模板参数（NTTP）**

```c++
template <auto N>  // C++17 合法 ✅
struct Value {};
```

- **作用：自动推导非类型模板参数的类型**

```c++
Value<10> v1;     // auto → int
Value<'a'> v2;    // auto → char
Value<true> v3;   // auto → bool
```

- 可以写**通用整数 / 枚举模板**

不用再写冗余的模板参数：

```c++
// C++14: 必须写类型
template <typename T, T N>
struct X {};
// C++17: auto 自动推导类型
template <auto N>
struct Y {};
```

| 代码                | C++14 推导              | C++17 推导              | 说明           |
| ------------------- | ----------------------- | ----------------------- | -------------- |
| `auto x = 42;`      | `int`                   | `int`                   | 不变           |
| `auto x = {42};`    | `initializer_list<int>` | `initializer_list<int>` | 不变           |
| `auto x{42};`       | `initializer_list<int>` | **`int`**               | **C++17 修复** |
| `auto x{1,2};`      | `initializer_list<int>` | **编译错误**            | **C++17 禁止** |
| `template <auto N>` | 错误                    | 正确                    | **C++17 新增** |

## 核心使用场景

**安全的单值初始化**

```c++
auto val{100};  // C++17: int ✅ 安全、直观
```

**通用非类型模板**

```c++
template <auto value>
constexpr auto get_value = value;
auto a = get_value<5>;    // int
auto b = get_value<'c'>;  // char
```

**枚举作为模板参数（无需指定类型）**

```c++
enum class Color { Red, Green };
template <auto C>  // C++17
void set_color() {}
set_color<Color::Red>();  // 自动推导为 Color
```

## 核心规则与注意事项

- **`auto=` 形式不受影响**
  - `auto x = {1}` 仍然是列表，保持向后兼容。
- **非类型模板 `auto` 不能推导浮点 / 字符串**
  - 仅支持：整数、枚举、指针、成员指针。
