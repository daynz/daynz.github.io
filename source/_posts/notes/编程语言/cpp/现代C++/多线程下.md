# 条件变量

在 `<condition_variable>` 头文件中提供了**条件变量（Condition Variable）** 机制，核心用于解决多线程间的 “生产者-消费者” 同步问题 —— 让一个 / 多个线程等待某个条件满足，当条件成立时，由其他线程通知等待的线程继续执行。这是比单纯使用互斥锁更高效的同步方式（避免线程无意义的轮询等待）。

## 背景

互斥锁的局限性：仅用互斥锁实现 “等待条件” 时，线程需不断加锁检查条件（轮询），导致 CPU 资源浪费。

条件变量的核心价值：**让等待线程进入休眠状态，直到被通知唤醒**，彻底避免轮询的 CPU 浪费。

## 核心概念与基础语法

**核心组件**

| 类型                          | 核心特性                                                     |
| ----------------------------- | ------------------------------------------------------------ |
| `std::condition_variable`     | 仅支持配合`std::unique_lock<std::mutex>`使用，功能更全（推荐） |
| `std::condition_variable_any` | 支持配合任意锁类型（如`std::lock_guard`、自定义锁），但有轻微性能开销 |

**核心函数**

| 函数                                            | 功能                                                         |
| ----------------------------------------------- | ------------------------------------------------------------ |
| `wait(unique_lock<mutex>& lck)`                 | 释放锁并阻塞线程，直到被通知唤醒；唤醒后重新加锁，检查条件（需外层循环） |
| `wait(unique_lock<mutex>& lck, Predicate pred)` | 重载版：唤醒后仅当`pred()`为 true 时才继续，否则重新休眠     |
| `notify_one()`                                  | 唤醒一个等待的线程（随机选择）                               |
| `notify_all()`                                  | 唤醒所有等待的线程                                           |
| `wait_for(lck, 时长, pred)`                     | 等待指定时长，超时或条件满足时返回（返回值为 bool：条件是否满足） |
| `wait_until(lck, 时间点, pred)`                 | 等待到指定时间点，超时或条件满足时返回                       |

## 核心使用场景

**生产者-消费者模型**

经典的单生产者 - 单消费者模型：生产者生产数据后通知消费者，消费者等待数据就绪。

- **虚假唤醒**：等待的线程可能在没有被`notify`的情况下被唤醒（操作系统底层机制导致）

- **解决方案**：必须用**循环检查条件**（`wait`的重载版自带循环，或手动写 while 循环）

```c++
// 手动循环（等价于wait(lock, pred)）
while (!data_ready) {
    cv.wait(lock); // 无pred的版本，需手动循环
}
```

**使用例**

```c++
// 共享数据
int data = 0;
bool data_ready = false; // 等待的条件
mutex mtx;
condition_variable cv;
// 消费者线程：等待数据就绪
void consumer() {
    unique_lock<mutex> lock(mtx); // 必须用unique_lock（wait需要解锁/加锁）
    // 等待条件：data_ready为true时才继续（外层循环避免虚假唤醒）
    cv.wait(lock, []() { return data_ready; });

    // 条件满足，处理数据
    cout << "消费者：获取到数据 = " << data << endl;
    data_ready = false; // 重置条件
}
// 生产者线程：生产数据并通知消费者
void producer() {
    // 模拟生产数据（耗时操作）
    this_thread::sleep_for(chrono::seconds(1));
    lock_guard<mutex> lock(mtx);
    data = 100;
    data_ready = true; // 设置条件为true
    cout << "生产者：数据已生产，通知消费者" << endl;
    cv.notify_one(); // 唤醒一个等待的线程
}
thread t_consumer(consumer);
thread t_producer(producer);
t_consumer.join();
t_producer.join();
```

**多消费者唤醒（notify_all ()）**

多个线程等待同一条件，条件满足时唤醒所有等待线程

```c++
// 共享条件：是否开始
bool start = false;
mutex mtx;
condition_variable cv;

// 多个工作线程
void worker(int id) {
    unique_lock<mutex> lock(mtx);
    cv.wait(lock, []() { return start; });
    cout << "工作线程" << id << "：开始执行" << endl;
}
// 创建3个工作线程（均等待start条件）
thread t1(worker, 1);
thread t2(worker, 2);
thread t3(worker, 3);
// 主线程：5秒后通知所有线程开始
this_thread::sleep_for(chrono::seconds(2));
{
    lock_guard<mutex> lock(mtx);
    start = true;
}
cv.notify_all(); // 唤醒所有等待线程
t1.join();
t2.join();
t3.join();
```

**超时等待（wait_for）**

避免线程永久等待，设置超时时间，超时后主动退出。

```c++
void wait_with_timeout() {
    unique_lock<mutex> lock(mtx);
    // 等待3秒，若条件仍不满足则返回
    bool condition_met = cv.wait_for(lock, chrono::seconds(3), []() { return ready; });

    if (condition_met) {
        cout << "超时前条件满足，继续执行" << endl;
    } else {
        cout << "3秒超时，条件仍不满足，退出" << endl;
    }
}
thread t(wait_with_timeout);
// 不设置ready，让线程超时
t.join();
```

### 核心规则与注意事项

1. **必须配合`std::unique_lock`**
   - `std::condition_variable::wait()` 会在休眠前**释放锁**，唤醒后**重新加锁**，只有`std::unique_lock`支持手动解锁 / 加锁（`std::lock_guard`不支持），因此必须使用`unique_lock`。

2. **条件变量的 “条件” 必须受互斥锁保护**

   - 读取 / 修改条件（如`data_ready`）时，必须加锁，避免数据竞争；

   - 通知线程需先修改条件，再调用`notify`（顺序不可颠倒）。

3. **避免 “丢失通知”**

   - 错误示例：通知线程先调用`notify`，再修改条件，可能导致等待线程错过通知；

   - 正确做法：先加锁修改条件，再调用`notify`（如场景 1 的生产者线程）。

4. **`notify_one()` vs `notify_all()`**

   - `notify_one()`：唤醒一个等待线程（适合单消费者场景），开销小；

   - `notify_all()`：唤醒所有等待线程（适合多消费者场景），开销大，需确保所有线程都需要被唤醒。

# 异步操作

在 `<future>` 头文件中引入了**异步操作**机制，核心用于实现**异步执行任务 + 同步获取结果** 的编程模式——让任务在后台线程执行，主线程可继续处理其他逻辑，待需要结果时再获取（或等待任务完成）。这是比直接使用 `std::thread` 更便捷的并发编程方式，无需手动管理线程和同步（如互斥锁 / 条件变量）。

异步操作的核心价值：**标准化封装 “任务执行 + 结果获取 + 同步”**，无需手动编写同步代码，大幅简化并发编程。

## 背景

直接使用线程的痛点：用 `std::thread` 实现 “后台执行任务并获取结果” 时，需手动处理同步（如互斥锁 + 条件变量），代码冗余且易出错。

```c++
int result; // 存储任务结果
bool done = false;
mutex mtx;
condition_variable cv;
// 后台任务：计算1+2+...+100
void calc_sum() {
    int sum = 0;
    for (int i = 1; i <= 100; ++i) sum += i;
    
    lock_guard<mutex> lock(mtx);
    result = sum;
    done = true;
    cv.notify_one();
}
thread t(calc_sum);
// 主线程可执行其他逻辑...
cout << "主线程处理其他事情..." << endl;
// 等待任务完成并获取结果
unique_lock<mutex> lock(mtx);
cv.wait(lock, []() { return done; });
cout << "计算结果：" << result << endl;
t.join();
```

## 核心组件与基础概念

C++11 异步操作的核心组件分为三类，协同实现 “异步任务 - 结果获取”

| 组件                    | 核心作用                                                     |
| ----------------------- | ------------------------------------------------------------ |
| `std::future<T>`        | 未来值：获取异步任务的结果（T 为结果类型，void 表示无返回值），仅可被**一个线程**获取一次 |
| `std::shared_future<T>` | 共享未来值：可被**多个线程**多次获取结果                     |
| `std::promise<T>`       | 承诺：与`future`配对，用于**主动设置**任务结果 / 异常        |
| `std::packaged_task<T>` | 任务包装器：封装可调用对象（函数 / Lambda），将其与`future`绑定 |
| `std::async()`          | 异步函数：最便捷的异步操作入口，直接启动异步任务并返回`future`（推荐首选） |

### `std::async`

`std::async` 是最简单的异步操作入口，自动创建线程执行任务，并返回`future`用于获取结果。

```c++
// 重载1：默认策略（自动决定是否创建新线程）
std::future<T> async(std::launch::policy, 可调用对象, 参数...);
// 重载2：省略策略，等价于std::launch::async | std::launch::deferred
std::future<T> async(可调用对象, 参数...);
```

**策略说明**：

- `std::launch::async`：强制创建新线程，立即执行任务；
- `std::launch::deferred`：延迟执行（懒加载），仅当调用`future.get()`/`wait()`时才在当前线程执行；
- 默认策略：`std::launch::async | std::launch::deferred`。

**异步计算求和**

```c++
// 待异步执行的任务：计算1~n的和
int sum(int n) {
    int res = 0;
    for (int i = 1; i <= n; ++i) {
        res += i;
        this_thread::sleep_for(chrono::milliseconds(10)); // 模拟耗时
    }
    return res;
}
// 1. 启动异步任务（强制创建新线程）
future<int> fut = async(launch::async, sum, 100);
// 2. 主线程执行其他逻辑（无需等待）
cout << "主线程处理其他事情..." << endl;
// 3. 获取结果：若任务未完成，get()会阻塞直到完成
// 若任务抛出异常，get()会重新抛出该异常（可捕获）
int result = fut.get(); // 阻塞获取结果，且仅能调用一次（调用后future进入 “无效状态”）；
cout << "1~100的和：" << result << endl; // 输出5050
// 若用launch::deferred，sum会在fut.get()时在主线程执行（无新线程）
```

### `std::promise` / `std::future`

`promise` 用于**主动设置**任务结果（或异常），与`future`配对使用，适用于 “手动控制任务完成时机” 的场景（如多线程协作）。

**线程间传递结果**

```c++
// 任务函数：接收promise，完成后设置结果
void task(promise<int> prom) {
    int res = 100 * 2; // 模拟计算
    this_thread::sleep_for(chrono::seconds(1));
    prom.set_value(res); // 设置结果，触发future就绪 set_value() 仅可调用一次（多次调用抛异常）
}
// 1. 创建promise和关联的future
promise<int> prom;
future<int> fut = prom.get_future();
// 2. 启动线程，将promise移动传入（不可拷贝）
thread t(task, move(prom));//promise 不可拷贝，需用std::move传递
// 3. 主线程等待并获取结果
cout << "等待任务结果..." << endl;
int res = fut.get();
cout << "任务结果：" << res << endl; // 输出200
t.join();
// 若任务异常，可调用set_exception()设置异常（get()时抛出）。
```
### `std::shared_future`

`std::future` 仅能被一个线程获取一次结果，`shared_future` 可被多个线程多次获取，适用于 “多线程共享同一任务结果” 的场景。

**多线程读取结果**

```c++
// 共享结果的线程函数
void read_result(shared_future<int> sf, int id) {
    cout << "线程" << id << "获取结果：" << sf.get() << endl;
}
future<int> fut = async(launch::async, sum, 100);
// 将future转换为shared_future（需move）
shared_future<int> sf = move(fut);
// 多个线程共享结果
thread t1(read_result, sf, 1);
thread t2(read_result, sf, 2);
t1.join();
t2.join();
```

#### 核心成员函数

**`std::future / std::shared_future`** 

| 函数                 | 功能                                                         |
| -------------------- | ------------------------------------------------------------ |
| `get()`              | 阻塞获取结果（`future`仅可调用一次，`shared_future`可多次调用） |
| `wait()`             | 阻塞等待任务完成（不获取结果）                               |
| `wait_for(时长)`     | 超时等待：返回`future_status`（`ready`/`timeout`/`deferred`） |
| `wait_until(时间点)` | 等待到指定时间点，返回`future_status`                        |
| `valid()`            | 判断`future`是否有效（未调用`get()`且关联的任务存在）        |

**`std::promise`**

| 函数                               | 功能                                                        |
| ---------------------------------- | ----------------------------------------------------------- |
| **`get_future()`**                 | 获取与该 `promise` 绑定的 `future` 对象（**只能调用一次**） |
| **`set_value(T)`**                 | **设置结果值**，唤醒等待的 `future`；未设置则析构时抛异常   |
| **`set_exception(exception_ptr)`** | **设置异常**，让 `future.get()` 时抛出该异常                |
| **`swap(promise& other)`**         | 交换两个 `promise` 的内部状态                               |

**超时等待任务**

```c++
future<int> fut = async(launch::async, []() {
    this_thread::sleep_for(chrono::seconds(3));
    return 100;
});
// 等待2秒，检查任务状态
future_status status = fut.wait_for(chrono::seconds(2));
if (status == future_status::ready) {
    cout << "任务完成，结果：" << fut.get() << endl;
} else if (status == future_status::timeout) {
    cout << "2秒超时，任务未完成" << endl; // 输出此条
} else if (status == future_status::deferred) {
    cout << "任务延迟执行" << endl;
}
```

### `std::packaged_task`

`packaged_task` 封装可调用对象（函数 / Lambda），将其执行结果绑定到`future`，适用于 “任务需复用 / 延迟执行” 的场景。

**封装并执行任务**

```c++
// 1. 封装任务：签名为int(int)（输入int，返回int）
packaged_task<int(int)> task([](int n) {
    return n * n; // 计算平方
});
// 2. 获取关联的future
future<int> fut = task.get_future();
// 3. 执行任务（可在当前线程/新线程执行）
thread t(move(task), 10); // 传入参数10，执行任务
// 4. 获取结果
int res = fut.get();
cout << "10的平方：" << res << endl; // 输出100
t.join();
```

#### 核心成员函数

| 函数                            | 功能                                                 |
| ------------------------------- | ---------------------------------------------------- |
| **get_future()**                | 获取绑定的 `future`，**仅调用一次**                  |
| **operator()**                  | **执行任务**，调用内部函数，将结果存入共享状态       |
| **make_ready_at_thread_exit()** | 执行任务，但**延迟到线程退出时**才让 `future` 就绪   |
| **valid()**                     | 判断 `packaged_task` 是否**拥有有效任务 / 状态**     |
| **reset()**                     | **重置共享状态**，可重新执行任务（保留原可调用对象） |
| **swap(packaged_task& other)**  | 交换两个 `packaged_task` 的内部状态                  |

## 处理异步任务的异常

异步任务抛出的异常会被存储到`future`中，调用`get()`时重新抛出

```c++
int risky_task() {
    throw runtime_error("任务执行失败！");
    return 0;
}
future<int> fut = async(launch::async, risky_task);
try {
    int res = fut.get();
} catch (const exception& e) {
    cout << "捕获异常：" << e.what() << endl; // 输出：任务执行失败！
}
```

# 线程本地存储

引入了标准化的**线程本地存储**机制（核心关键字 `thread_local`），允许创建 “每个线程独有一份” 的变量实例——不同线程访问该变量时，操作的是各自独立的副本，而非共享的全局 / 静态变量。这是解决多线程数据共享冲突的轻量化方案，无需加锁即可保证线程安全。

线程本地存储的核心价值：**为每个线程分配独立的变量副本**，线程对变量的操作仅作用于自身副本，彻底避免数据竞争，且无需互斥锁 / 原子操作。

## 背景

全局 / 静态变量的线程安全问题：普通全局 / 静态变量是进程级共享的，多线程同时读写会引发数据竞争

```c++
// 全局共享变量：所有线程共用一份
int global_counter = 0;
void increment() {
    for (int i = 0; i < 1000; ++i) {
        global_counter++; // 数据竞争，结果不可靠
    }
}
thread t1(increment);
thread t2(increment);
t1.join();
t2.join();
cout << "global_counter = " << global_counter << endl; // 结果小于2000
```

## 核心语法

**`thread_local`** 是 C++11 新增的存储类说明符（与`static`/`extern`同级），可修饰全局变量、静态变量、类的静态成员变量。

| 修饰位置         | 变量生命周期                     | 初始化时机                 |
| ---------------- | -------------------------------- | -------------------------- |
| 全局变量         | 线程创建时初始化，线程退出时销毁 | 线程首次访问时（懒初始化） |
| 函数内静态变量   | 线程创建时初始化，线程退出时销毁 | 线程首次调用该函数时       |
| 类的静态成员变量 | 线程创建时初始化，线程退出时销毁 | 线程首次访问该成员时       |

**修饰全局变量**

```c++
// 线程本地全局变量：每个线程有独立副本
thread_local int tls_counter = 0;
void increment() {
    // 操作的是当前线程的tls_counter副本
    for (int i = 0; i < 1000; ++i) {
        tls_counter++;
    }
    // 输出当前线程的副本值（必然是1000）
    cout << "线程" << this_thread::get_id() << "：tls_counter = " << tls_counter << endl;
}
thread t1(increment);
thread t2(increment);
t1.join();
t2.join();
// 主线程的tls_counter副本仍为0（未操作）
cout << "主线程：tls_counter = " << tls_counter << endl;
```

**修饰函数内静态变量**

```c++
void func() {
    // 线程本地静态变量：每个线程首次调用func时初始化
    thread_local static int tls_var = 0;
    tls_var++;
    cout << "线程" << this_thread::get_id() << "：tls_var = " << tls_var << endl;
}
// 线程1调用2次func，tls_var递增
thread t1([]() {
    func(); // 输出1
    func(); // 输出2
});
// 线程2调用func，tls_var是独立副本（输出1）
thread t2(func);
t1.join();
t2.join();
```

**修饰类的静态成员变量**

```c++
class MyClass {
public:
    // 类的线程本地静态成员：每个线程有独立副本
    thread_local static int tls_member;
    static void increment() {
        tls_member++;
        cout << "线程" << this_thread::get_id() << "：tls_member = " << tls_member << endl;
    }
};
// 必须在类外初始化（线程本地变量的初始化规则）
thread_local int MyClass::tls_member = 0;
thread t1(MyClass::increment); // 输出1
thread t2(MyClass::increment); // 输出1
t1.join();
t2.join();
```

## 关键规则

- **不可修饰局部非静态变量**：`thread_local` 仅能修饰全局、静态（函数内 / 类成员）变量，修饰普通局部变量会编译报错；

  - ```c++
    void wrong_func() {
        thread_local int x = 0; // 错误：局部非静态变量不能用thread_local
    }
    ```

- **初始化的线程独立性**：每个线程的 TLS 变量副本会独立初始化（即使是常量初始化）；

- **生命周期与线程绑定**：线程退出时，其所有 TLS 变量副本会自动销毁（调用析构函数）；

- **存储位置**：TLS 变量存储在进程的 “线程本地存储区”，而非全局 / 栈 / 堆区。

## 使用场景

**线程私有状态管理**

存储每个线程的独有状态（如日志上下文、请求 ID、配置参数），无需通过函数参数传递

```c++
// 线程本地存储：当前请求ID
thread_local string current_request_id = "";
// 处理请求：设置当前线程的请求ID
void handle_request(const string& req_id) {
    current_request_id = req_id;
    process_request(); // 内部可直接访问current_request_id
}
// 处理逻辑：无需传递req_id，直接用线程本地变量
void process_request() {
    cout << "处理请求：" << current_request_id << endl;
}
thread t1(handle_request, "req_1001");
thread t2(handle_request, "req_1002");
t1.join();
t2.join();
```

**避免线程安全的函数重入问题**

某些函数依赖全局状态（如随机数生成器），多线程调用时会出错，TLS 可让每个线程有独立的状态副本

```c++
// 线程本地随机数生成器：每个线程独立，无需加锁
thread_local mt19937 rng(random_device{}());
// 线程安全的随机数生成函数
int generate_random(int min, int max) {
    uniform_int_distribution<int> dist(min, max);
    return dist(rng); // 操作当前线程的rng副本
}
thread t1([]() {
    for (int i = 0; i < 3; ++i) {
        cout << "线程1随机数：" << generate_random(1, 100) << endl;
    }
});
thread t2([]() {
    for (int i = 0; i < 3; ++i) {
        cout << "线程2随机数：" << generate_random(1, 100) << endl;
    }
});
t1.join();
t2.join();
```

**性能优化（替代锁 / 原子操作）**

对于高频访问的线程私有变量，TLS 无需加锁 / 原子操作，性能远高于共享变量 + 同步

```c++
// 替代：全局原子计数器（有性能开销）
// atomic_int global_count(0);
// 线程本地计数器：无同步开销
thread_local int tls_count = 0;
void high_freq_operation() {
    for (int i = 0; i < 1000000; ++i) {
        tls_count++; // 无锁，性能最优
    }
    // 最后汇总（如需全局统计，仅需一次同步）
    static atomic_int total_count(0);
    total_count += tls_count;
}
thread t1(high_freq_operation);
thread t2(high_freq_operation);
t1.join();
t2.join();
cout << "总计数：" << total_count << endl; // 输出2000000
```

## TLS vs 其他线程安全方案

| 方案         | 核心特性                     | 性能 | 适用场景                               |
| ------------ | ---------------------------- | ---- | -------------------------------------- |
| thread_local | 每个线程独立副本，无数据竞争 | 极高 | 线程私有状态、高频访问的线程独有关变量 |
| std::mutex   | 互斥访问共享变量             | 低   | 复杂临界区、多线程共享数据             |
| std::atomic  | 硬件级原子操作，无锁         | 高   | 简单共享变量（计数器、标志位）         |
| 函数参数传递 | 线程私有，无共享             | 中   | 少量、低频传递的线程私有数据           |

**选型建议**

1. **线程私有状态**：优先用`thread_local`（最简洁、性能最优）；
2. **简单共享计数器**：用`std::atomic`；
3. **复杂共享临界区**：用`std::mutex`；
4. **少量临时数据**：用函数参数传递。

# 标准库容器的线程安全性

*   **规则明确**：
    1.  **读写冲突**：如果多个线程同时访问同一个容器实例，且其中至少有一个是写操作（插入、删除、修改元素），**必须**使用互斥锁 (`std::mutex`) 进行保护。
    2.  **纯读并发**：如果多个线程同时对同一个容器实例进行**只读**访问（没有写操作），则是安全的，不需要加锁。
    3.  **不同元素访问**：C++11 标准保证，如果多个线程访问**不同**的容器实例，或者访问同一个容器中**完全不同**的元素（且不改变容器结构，如 size/capacity），通常是安全的（具体取决于容器类型，`std::vector` 修改不同元素通常安全，但 `std::list` 节点操作需小心）。
*   **错误示范**：

```cpp
std::vector<int> vec;
// 线程 A
vec.push_back(1); 
// 线程 B (同时执行)
vec.push_back(2); 
// 危险！可能导致数据竞争、崩溃或数据损坏
```

*   **正确做法**：

```cpp
std::vector<int> vec;
std::mutex mtx;
// 线程 A & B
{
    std::lock_guard<std::mutex> lock(mtx);
    vec.push_back(1);
}
// 安全
```
