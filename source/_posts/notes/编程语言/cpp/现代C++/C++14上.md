# 变量模板

C++14 引入的**变量模板**（Variable Template）是模板机制的重要扩展，允许将变量（包括全局变量、静态成员变量、命名空间变量）定义为模板，支持按类型 / 非类型参数实例化不同版本的变量。这填补了 C++ 模板体系中 “变量无法泛型化” 的空白，让泛型编程覆盖到变量层面，大幅提升了代码的复用性和类型安全性。

变量模板的核心价值：**将变量泛型化，通过模板参数自动推导 / 指定变量类型 / 值**，消除重复定义，统一变量的泛型管理，是模板体系从 “函数 / 类” 延伸到 “变量” 的关键特性。

## 背景

C++11 及更早版本中，模板仅支持函数模板和类模板，变量无法直接泛型化：

1. 需为不同类型定义重复变量（如不同类型的 π 值、不同类型的默认阈值），代码冗余；
2. 无法通过类型推导自动适配变量类型，需手动指定或通过宏定义间接实现，易出错；
3. 类的静态成员变量需为每个类型手动实例化，无法批量泛型化。

```c++
// C++11 痛点1：重复定义不同类型的常量
const double PI_double = 3.1415926535;
const float PI_float = 3.1415926f;
const long double PI_long_double = 3.141592653589793238L;

// C++11 痛点2：类静态成员变量需手动实例化
template <typename T>
struct MathConst {
    static const T PI; // 声明
};
// 手动实例化int版本
template<> const int MathConst<int>::PI = 3;
// 手动实例化double版本
template<> const double MathConst<double>::PI = 3.1415926535;
cout << PI_double << endl; // 3.1415926535
cout << MathConst<double>::PI << endl; // 3.1415926535
```

## 核心语法

变量模板的核心是用`template`关键字定义带模板参数的变量，语法分为**类型参数变量模板**和**非类型参数变量模板**

编译器会根据实例化时的模板参数，生成对应版本的变量，等价于为每个参数组合定义一个独立变量。

```c++
// 类型参数变量模板（最常用）
template <typename T>
const T PI = T(3.141592653589793238L);
// 非类型参数变量模板
template <int N>
const int ARRAY_SIZE = N * 10;
```

**泛型常量**

```c++
// 定义类型参数变量模板：泛型PI常量
template <typename T>
const T PI = T(3.141592653589793238L);
// 定义非类型参数变量模板：泛型数组大小
template <int N>
constexpr int BUFFER_SIZE = N * 1024;
// 实例化double类型的PI
cout << "double PI: " << PI<double> << endl; // 3.141592653589793
// 实例化float类型的PI
cout << "float PI: " << PI<float> << endl;   // 3.1415927
// 实例化int类型的PI
cout << "int PI: " << PI<int> << endl;       // 3
// 实例化非类型参数变量模板
cout << "BUFFER_SIZE<1>: " << BUFFER_SIZE<1> << endl;   // 1024
cout << "BUFFER_SIZE<2>: " << BUFFER_SIZE<2> << endl;   // 2048
```

**关键**：变量模板的实例化需指定模板参数（类型 / 非类型），编译器会根据参数生成对应类型 / 值的变量，且支持`constexpr`（编译期常量）。

**类静态成员变量模板**

C++14 允许将类的静态成员变量定义为模板，实现 “类级别的泛型变量”

```c++
struct Config {
    // 类内定义静态成员变量模板
    template <typename T>
    static const T DEFAULT_VALUE;
};
// 类外实例化不同类型的默认值
template<> const int Config::DEFAULT_VALUE<int> = 0;
template<> const double Config::DEFAULT_VALUE<double> = 0.0;
template<> const std::string Config::DEFAULT_VALUE<std::string> = "default";
cout << Config::DEFAULT_VALUE<int> << endl;        // 0
cout << Config::DEFAULT_VALUE<double> << endl;     // 0
cout << Config::DEFAULT_VALUE<std::string> << endl;// default
```

**变量模板与类型别名结合**

变量模板可结合`using`类型别名，简化复杂类型的变量实例化

```c++
// 定义泛型容器的默认大小
template <typename T>
constexpr size_t DEFAULT_CONTAINER_SIZE = 10;
// 类型别名：简化vector类型
template <typename T>
using DefaultVector = std::vector<T>;
int main() {
    // 使用变量模板指定vector初始大小
    DefaultVector<int> vec(DEFAULT_CONTAINER_SIZE<int>);
    cout << "vec初始大小：" << vec.size() << endl; // 10
    DefaultVector<std::string> str_vec(DEFAULT_CONTAINER_SIZE<std::string>);
    cout << "str_vec初始大小：" << str_vec.size() << endl; // 10
```

**变量模板的特化（全特化 / 偏特化）**

与函数模板 / 类模板类似，变量模板支持全特化和偏特化，为特定类型定制变量值

```c++
// 通用版本：任意类型的默认阈值为0
template <typename T>
const T DEFAULT_THRESHOLD = T(0);
// 全特化：bool类型的默认阈值为true
template<> const bool DEFAULT_THRESHOLD<bool> = true;
// 偏特化：指针类型的默认阈值为nullptr
template <typename T>
const T* DEFAULT_THRESHOLD<T*> = nullptr;
cout << DEFAULT_THRESHOLD<int> << endl;    // 0
cout << boolalpha << DEFAULT_THRESHOLD<bool> << endl; // true
int* ptr = DEFAULT_THRESHOLD<int*>;
cout << (ptr == nullptr) << endl; // true（指针阈值为nullptr）
```

**`constexpr` 变量模板（编译期计算）**

变量模板支持`constexpr`，可在编译期计算变量值，提升性能

```c++
// 编译期计算不同类型的2的N次方
template <typename T, int N>
constexpr T POWER_OF_TWO = []() constexpr {
    T res = 1;
    for (int i = 0; i < N; ++i) {
        res *= 2;
    }
    return res;
}(); // 立即调用Lambda（C++14 constexpr Lambda）
// 编译期计算：int类型2^10=1024
constexpr int val1 = POWER_OF_TWO<int, 10>;
cout << val1 << endl; // 1024
// 编译期计算：long long类型2^20=1048576
constexpr long long val2 = POWER_OF_TWO<long long, 20>;
cout << val2 << endl; // 1048576
```

## 核心使用场景

**泛型常量 / 配置项**

最常用场景：定义跨类型的通用常量（如 π、自然常数 e、默认阈值），避免重复定义

```c++
// 泛型自然常数e
template <typename T>
const T E = T(2.718281828459045235L);
// 泛型重力加速度
template <typename T>
const T GRAVITY = T(9.80665);
// 计算物理公式：m*g*h（重力势能）
double mass = 5.0;
double height = 10.0;
double potential_energy = mass * GRAVITY<double> * height;
cout << "重力势能：" << potential_energy << endl; // 490.3325
// 计算指数函数：e^2
double exp_val = pow(E<double>, 2);
cout << "e^2 = " << exp_val << endl; // 7.38905609893065
```

**类静态成员泛型化**

为类的静态成员提供泛型支持，适配不同类型的业务逻辑

```c++
// 全局缓存类
class CacheManager {
public:
    // 静态成员变量模板：不同类型的缓存容器
    template <typename T>
    static std::unordered_map<std::string, T> cache;
    // 静态方法：添加缓存
    template <typename T>
    static void add_cache(const std::string& key, const T& value) {
        cache<T>[key] = value;
    }
    // 静态方法：获取缓存
    template <typename T>
    static T get_cache(const std::string& key) {
        return cache<T>[key];
    }
};
// 实例化不同类型的缓存容器
template<> std::unordered_map<std::string, int> CacheManager::cache<int>;
template<> std::unordered_map<std::string, std::string> CacheManager::cache<std::string>;
CacheManager::add_cache<int>("age", 25);
CacheManager::add_cache<std::string>("name", "Alice");
cout << CacheManager::get_cache<int>("age") << endl; // 25
cout << CacheManager::get_cache<std::string>("name") << endl; // Alice
```

**编译期配置与优化**

结合`constexpr`的变量模板可在编译期确定变量值，用于静态数组大小、编译期分支等

```c++
// 编译期判断类型大小，设置不同的缓冲区大小
template <typename T>
constexpr size_t BUFFER_SIZE = (sizeof(T) <= 4) ? 1024 : 4096;
// 编译期确定数组大小：int占4字节，缓冲区1024
char int_buffer[BUFFER_SIZE<int>];
cout << "int缓冲区大小：" << sizeof(int_buffer) << endl; // 1024
// double占8字节，缓冲区4096
char double_buffer[BUFFER_SIZE<double>];
cout << "double缓冲区大小：" << sizeof(double_buffer) << endl; // 4096
```

**适配模板库 / STL 扩展**

变量模板可用于扩展 STL 或自定义模板库，为不同类型提供统一的默认值 / 配置

```c++
// 为不同容器类型定义默认初始化容量
template <typename Container>
constexpr size_t DEFAULT_CAPACITY = 0;
// 偏特化：vector默认容量为10
template <typename T>
constexpr size_t DEFAULT_CAPACITY<std::vector<T>> = 10;
// 偏特化：list默认容量为0（list无capacity概念）
template <typename T>
constexpr size_t DEFAULT_CAPACITY<std::list<T>> = 0;
std::vector<int> vec;
vec.reserve(DEFAULT_CAPACITY<decltype(vec)>);
cout << "vec预留容量：" << vec.capacity() << endl; // 10
std::list<int> lst;
// list无reserve，此处仅演示
cout << "list默认容量：" << DEFAULT_CAPACITY<decltype(lst)> << endl; // 0
```

## 核心规则与注意事项

- 变量模板的本质
  - 变量模板是 “模板化的变量声明”，编译器不会直接生成变量，仅在**显式实例化**（指定模板参数）时生成具体变量，遵循模板的 “按需实例化” 规则。

- 特化规则

  - 变量模板的全特化需完全匹配模板参数（如`template<> const bool PI<bool> = true;`）；

  - 偏特化仅支持类型参数（非类型参数不支持偏特化）；

  - 特化版本的变量类型必须与通用版本一致（如通用版本是`const T`，特化版本也需是`const`）。

- 作用域与可见性

  - 全局变量模板的作用域是全局，需避免命名冲突；

  - 类静态成员变量模板的作用域是类内部，实例化时需加类名（如`Config::DEFAULT_VALUE<int>`）；

  - 变量模板的声明需在使用前（遵循 “先声明后使用”）。

- 与宏定义的区别
  - 变量模板优于宏定义的核心点：

| 特性       | 变量模板                       | 宏定义                   |
| ---------- | ------------------------------ | ------------------------ |
| 类型安全   | 强类型，编译期类型检查         | 无类型检查，易出错       |
| 作用域     | 支持局部 / 类 / 命名空间作用域 | 全局作用域，易冲突       |
| 特化       | 支持全特化 / 偏特化            | 不支持，需手动定义多个宏 |
| 编译期计算 | 支持 `constexpr` 编译期计算    | 仅简单文本替换，无计算   |

**与 C++17 inline 变量模板的结合**

C++17 的`inline`变量允许变量模板在头文件中直接实例化，无需在源文件中单独定义，简化跨文件使用

```c++
// 头文件中定义inline变量模板（C++17）
template <typename T>
inline const T MAX_VALUE = T(1000);
// 其他源文件可直接使用，无需重复实例化
cout << MAX_VALUE<int> << endl; // 1000
```

# 二进制字面量

C++14 引入的**二进制字面量**是数值字面量的重要扩展，允许直接用二进制形式书写整数（包括无符号、有符号、长整型等），无需通过十进制 / 十六进制转换。这大幅提升了底层编程（如位操作、硬件控制、协议解析）的代码可读性和直观性，避免了手动转换二进制与十进制 / 十六进制的错误。

二进制字面量的核心价值：**直接用`0b/0B`前缀书写二进制数值**，让代码中的二进制逻辑与数值书写形式完全一致，消除转换成本，提升代码可读性和准确性。

## 背景

C++11 及更早版本仅支持**十进制**（如`10`）、**八进制**（前缀`0`，如`012`）、**十六进制**（前缀`0x/0X`，如`0xA`）字面量，无二进制字面量：

1. 表示二进制数值需手动转换为十进制 / 十六进制，易出错且可读性差；
2. 位操作场景（如设置寄存器位、掩码定义）中，无法直观体现二进制位的含义；
3. 硬件相关代码中，二进制逻辑与代码书写形式脱节，增加维护成本。

```c++
// C++11 痛点：表示二进制1010（十进制10）需用十进制/十六进制
int mask1 = 10;       // 二进制1010，无法直观看出位结构
int mask2 = 0xA;      // 十六进制，仍需转换才能对应二进制
cout << mask1 << endl; // 10
// 位操作：设置第1位和第3位（二进制1010），代码无直观性
int val = 0;
val |= (1 << 1) | (1 << 3); // 等价于二进制1010，逻辑不直观
cout << val << endl; // 10
```

## 核心语法

二进制字面量的核心是通过**前缀`0b`或`0B`** 标识二进制数值，后缀可结合整型修饰符（如`u`、`l`、`ll`）指定类型：

```c++
// 基础语法：0b/0B + 二进制数字（0/1）
int a = 0b1010;    // 二进制1010 → 十进制10
unsigned int b = 0B11110000u; // 二进制11110000 → 十进制240，无符号
long long c = 0b1000000000000000ll; // 二进制长整型
```

编译器会将二进制字面量直接解析为对应整数值，与十进制 / 十六进制字面量等价，但可读性大幅提升。

**直观表示二进制数值**

```c++
// 二进制字面量：直接表示二进制1010（十进制10）
int binary_val = 0b1010;
cout << "0b1010 = " << binary_val << endl; // 10
// 无符号二进制字面量
unsigned int u_val = 0B11111111u; // 二进制8位全1 → 十进制255
cout << "0B11111111u = " << u_val << endl; // 255
// 长整型二进制字面量
long l_val = 0b10000000000l; // 二进制10000000000 → 十进制1024
cout << "0b10000000000l = " << l_val << endl; // 1024
// 超长二进制字面量（64位）
long long ll_val = 0b1111000011110000111100001111000011110000111100001111000011110000ll;
cout << "64位二进制字面量 = " << ll_val << endl;
```

**关键**：二进制字面量仅支持`0`和`1`，不能包含其他数字（如`0b12`会编译报错）；前缀`0b`/`0B`大小写均可，推荐统一用`0b`。

**数字分隔符（C++14）结合二进制字面量**

C++14 同时引入了**数字分隔符`'`**，可在二进制字面量中插入分隔符，提升长二进制数的可读性

```c++
// 无分隔符：长二进制数易看错
int mask1 = 0b1111000011110000;
// 有分隔符：按4位分组，直观（类似十六进制的每4位对应1位）
int mask2 = 0b1111'0000'1111'0000;
cout << mask1 << endl; // 61680
cout << mask2 << endl; // 61680（与mask1等价）
// 按字节（8位）分组
unsigned int byte_mask = 0b11111111'00000000'11111111'00000000u;
cout << byte_mask << endl; // 4278255360
```

**注意**：分隔符`'`仅用于视觉分隔，不影响数值本身，可放在任意位置（但建议按 4 位 / 8 位分组）。

**二进制字面量与位操作结合**

二进制字面量最核心的用途是位操作，让位逻辑与代码完全对应

```c++
// 定义位掩码：第1位和第3位为1（二进制1010）
const int MASK = 0b1010;
int val = 0;
// 设置掩码位：逻辑直观，无需计算移位
val |= MASK;
cout << "设置掩码后：" << val << endl; // 10
// 清除第1位（二进制1000）
val &= ~0b0010;
cout << "清除第1位后：" << val << endl; // 8
// 检查第3位是否为1
if (val & 0b1000) {
    cout << "第3位为1" << endl; // 输出
```

**二进制字面量与类型转换**

二进制字面量可直接参与类型转换，与普通整型字面量规则一致

```c++
// 二进制字面量转换为char（ASCII码）
char ch = 0b1000001; // 二进制1000001 → 十进制65 → 'A'
cout << ch << endl; // A
// 二进制字面量转换为bool（非0为true）
bool flag = 0b1; // true
cout << boolalpha << flag << endl; // true
// 无符号二进制字面量转换为十六进制输出
unsigned int val = 0b1101'0110u;
cout << hex << val << endl; // d6（十六进制）
```

**二进制字面量在枚举 / 常量中的使用**

二进制字面量可用于枚举、`constexpr`常量定义，固化二进制逻辑

```c++
// 枚举：硬件寄存器位定义
enum class RegisterBit : uint8_t {
    BIT0 = 0b00000001,
    BIT1 = 0b00000010,
    BIT2 = 0b00000100,
    BIT3 = 0b00001000,
    BIT7 = 0b10000000
};
// constexpr常量：协议帧头（二进制）
constexpr uint16_t FRAME_HEADER = 0b10101010'11001100;
cout << "BIT3 = " << static_cast<int>(RegisterBit::BIT3) << endl; // 8
cout << "FRAME_HEADER = " << FRAME_HEADER << endl; // 43724
```

## 核心使用场景

**底层位操作（寄存器 / 掩码）**

硬件编程、嵌入式开发中，二进制字面量可直观定义寄存器位、掩码

```c++
// 嵌入式寄存器配置：设置GPIO口的第0、2、4位为输出
const uint32_t GPIO_OUTPUT_MASK = 0b10101; // 二进制10101 → 十进制21
// 配置寄存器
void set_gpio_output(uint32_t* gpio_reg) {
    *gpio_reg |= GPIO_OUTPUT_MASK; // 设置指定位为1
}
uint32_t gpio_reg = 0;
set_gpio_output(&gpio_reg);
cout << "GPIO寄存器值：" << gpio_reg << endl; // 21
```

**协议解析 / 编码**

网络协议、通信协议中，二进制帧结构可直接用二进制字面量表示

```c++
// CAN总线数据帧：帧格式为 1位帧类型 + 3位优先级 + 4位数据长度
const uint8_t FRAME_TYPE_DATA = 0b0; // 0=数据帧，1=远程帧
const uint8_t PRIORITY_HIGH = 0b111; // 最高优先级
const uint8_t DATA_LEN_8 = 0b1000;   // 数据长度8字节
// 组合帧头
uint8_t frame_header = (FRAME_TYPE_DATA << 7) | (PRIORITY_HIGH << 4) | DATA_LEN_8;
cout << "帧头二进制：" << bitset<8>(frame_header) << endl; // 01111000
cout << "帧头十进制：" << static_cast<int>(frame_header) << endl; // 120
```

**辅助工具**：可结合`<bitset>`头文件的`bitset`类，直接输出二进制形式，便于调试。

**算法中的位运算优化**

```c++
// 快速判断整数是否为2的幂（二进制仅1位为1）
bool is_power_of_two(uint32_t n) {
    if (n == 0) return false;
    // 二进制逻辑：n & (n-1) == 0 表示仅1位为1
    return (n & (n - 1)) == 0b0;
}
cout << is_power_of_two(0b1000) << endl; // 1（true）
cout << is_power_of_two(0b1010) << endl; // 0（false）
// 哈希掩码：二进制全1，用于取模优化
const uint32_t HASH_MASK = 0b11111111'11111111'11111111'11111111u;
uint32_t hash_val = 123456789;
uint32_t index = hash_val & HASH_MASK; // 等价于取模2^32
cout << "哈希索引：" << index << endl; // 123456789
```

**测试用例中的二进制数据**

单元测试中，二进制字面量可精准构造测试数据

```c++
// 测试位翻转函数
uint8_t flip_bits(uint8_t val) {
    return ~val;
}
// 测试用例：二进制10101010翻转后应为01010101
uint8_t input = 0b10101010;
uint8_t expected = 0b01010101;
assert(flip_bits(input) == expected); // 断言通过
cout << "测试通过" << endl;
```

## 核心规则与注意事项

1. **语法限制**

   - 二进制字面量仅支持**整数类型**，不支持浮点数（如`0b10.1`编译报错）；

   - 仅能包含数字`0`和`1`，包含其他数字（如`0b123`）会触发编译错误；

   - 前缀`0b`/`0B`是强制要求，无前缀的`1010`会被解析为十进制。

2. **类型规则**

   - 二进制字面量的默认类型与十进制字面量一致：
     - 如`0b1010`默认是`int`，超出`int`范围则为`long`，再超出则为`long long`；

   - 可通过后缀指定类型：
     - `u`/`U`：无符号（如`0b1010u` → `unsigned int`）；
     - `l`/`L`：长整型（如`0b1010l` → `long`）；
     - `ll`/`LL`：长长整型（如`0b1010ll` → `long long`）。

3. **数字分隔符的使用规范**

   - 分隔符`'`可插入任意位置，但建议按**4 位**（半字节）或**8 位**（字节）分组，符合二进制阅读习惯；

   - 分隔符不能出现在前缀后（如`0b'1010`报错），也不能连续使用（如`0b10''10`报错）。

4. **与其他进制的等价性**

   - 二进制字面量与十进制 / 十六进制字面量在编译后完全等价，仅书写形式不同

   - ```c++
     // 以下三个值完全等价（十进制10）
     int a = 10;       // 十进制
     int b = 0xA;      // 十六进制
     int c = 0b1010;   // 二进制
     cout << (a == b && b == c) << endl; // 1（true）
     ```

5. **兼容性与迁移**

   - 若需兼容 C++11 及更早版本，可通过宏定义模拟二进制字面量

   - ```c++
     // 兼容宏：将二进制字符串转换为整数
     #define BIN(x) strtol(#x, NULL, 2)
     int mask = BIN(1010); // 等价于0b1010（C++14）
     ```

# 函数返回类型推导

C++14 引入的**函数返回类型推导**是对函数声明语法的核心增强，允许普通函数（非 Lambda）的返回类型通过`auto`关键字由编译器自动推导，无需显式指定。这解决了 C++11 中函数返回类型必须显式声明（或通过繁琐的尾置返回类型）的痛点，大幅简化了泛型函数、模板函数的定义，提升了代码的简洁性和灵活性。

函数返回类型推导的核心价值：**用`auto`替代显式返回类型，编译器根据函数`return`语句自动推导返回类型**，彻底简化函数声明语法，尤其适配泛型编程场景。

## 背景

C++11 及更早版本中，函数返回类型必须显式指定，仅支持**尾置返回类型**（Trailing Return Type）作为有限补充：

1. 普通函数必须先声明返回类型，无法根据函数体逻辑自动推导；
2. 泛型函数 / 模板函数的返回类型若依赖模板参数，需用`decltype`结合尾置返回类型，语法冗长；
3. 返回类型与函数体逻辑耦合时，修改函数体需同步修改返回类型，易出错。

```c++
// C++11 痛点1：普通函数必须显式指定返回类型
int add_int(int a, int b) { return a + b; } // 固定int返回类型
// C++11 痛点2：模板函数需尾置返回类型 + decltype，语法繁琐
template <typename T, typename U>
auto add_generic(T a, U b) -> decltype(a + b) { // 尾置返回类型
    return a + b;
}
cout << add_int(1, 2) << endl; // 3
cout << add_generic(1.5, 2.5) << endl; // 4.0
```

函数返回类型推导的核心价值：**用`auto`替代显式返回类型，编译器根据函数`return`语句自动推导返回类型**，彻底简化函数声明语法，尤其适配泛型编程场景。

## 核心语法与基础使用

函数返回类型推导的核心是将函数返回类型声明为`auto`，编译器通过函数体中的`return`语句推导实际返回类型：

```c++
// C++14 基础语法：auto + 函数名 + 参数列表 + 函数体
auto add(auto a, auto b) { // 结合泛型Lambda的auto参数（C++14）
    return a + b; // 编译器推导返回类型为a+b的类型
}
```

编译器推导规则：

- 若函数有多个`return`语句，所有返回值的类型必须**兼容**（可隐式转换为同一类型）；
- 推导结果遵循普通类型推导规则（如`int+double`推导为`double`）；
- 无`return`语句的函数（如`void`函数）推导为`void`。

**普通函数返回类型推导**

```c++
// 示例1：普通函数返回类型推导（int）
auto add_int(int a, int b) {
    return a + b; // 推导返回类型为int
}
// 示例2：返回类型为double（不同类型运算）
auto add_mixed(int a, double b) {
    return a + b; // int+double → 推导为double
}
// 示例3：返回类型为string
auto concat(string a, string b) {
    return a + b; // 推导为string
}
// 示例4：void返回类型（无return）
auto print_hello() {
    cout << "Hello, C++14!" << endl; // 推导为void
}
cout << add_int(10, 20) << endl;    // 30（int）
cout << add_mixed(5, 3.14) << endl; // 8.14（double）
cout << concat("hello ", "world") << endl; // hello world（string）
print_hello(); // Hello, C++14!（void）
```

**关键**：`auto`仅作为返回类型的 “占位符”，编译器会在编译期确定具体返回类型，推导结果与显式声明完全一致，无运行时开销。

**模板函数返回类型推导**

C++14 的返回类型推导对模板函数的简化效果最显著，彻底替代冗长的`decltype+尾置返回类型`：

```c++
// C++11 模板函数（尾置返回类型）
template <typename T>
auto get_first_cpp11(const vector<T>& vec) -> decltype(vec[0]) {
    return vec[0];
}
// C++14 模板函数（自动推导返回类型）
template <typename T>
auto get_first_cpp14(const vector<T>& vec) {
    return vec[0]; // 推导为const T&（vec[0]的类型）
}
vector<int> vec = {1, 2, 3};
cout << get_first_cpp14(vec) << endl; // 1（const int&）
vector<string> str_vec = {"a", "b", "c"};
cout << get_first_cpp14(str_vec) << endl; // a（const string&）
```

**递归函数的返回类型推导**

C++14 支持递归函数的返回类型推导，但需满足：**至少有一个`return`语句出现在递归调用之前**，让编译器先推导基础返回类型：

```c++
// 递归计算阶乘（返回类型推导为int）
auto factorial(int n) {
    if (n == 0) return 1; // 基础返回类型：int
    return n * factorial(n - 1); // 递归调用，类型兼容
}
cout << factorial(5) << endl; // 120
```

**注意**：若递归调用出现在所有`return`语句之前（如`return factorial(n-1)*n;`且无基础 case 前置），编译器无法推导返回类型，会报错。

**结合`constexpr`的返回类型推导**

C++14 允许`constexpr`函数使用返回类型推导，实现编译期计算：

```c++
// 编译期计算2的n次方（返回类型推导为int）
constexpr auto power_of_two(int n) {
    int res = 1;
    for (int i = 0; i < n; ++i) {
        res *= 2;
    }
    return res;
} 
constexpr int val = power_of_two(10); // 编译期推导为int，值为1024
cout << val << endl; // 1024
```

**返回类型推导与`decltype(auto)`**

C++14 引入`decltype(auto)`，可精准推导返回类型（保留引用 / 值语义），弥补`auto`会剥离引用的不足：

```c++
int global_val = 100;
// auto：推导为int（剥离引用）
auto get_auto() {
    return global_val; // 返回值拷贝，类型为int
}
// decltype(auto)：推导为int&（保留引用）
decltype(auto) get_decltype_auto() {
    return (global_val); // 括号保留引用语义，类型为int&
}
    get_decltype_auto() = 200; // 修改全局变量
    cout << global_val << endl; // 200
    cout << get_auto() << endl; // 200（值拷贝）
```

**核心区别**：

- `auto`：推导为 “值类型”，剥离引用和`const`限定；
- `decltype(auto)`：完全遵循`decltype`规则，保留引用 /`const`语义。

## 核心使用场景

**简化泛型函数 / 模板函数**

最核心场景：替代 C++11 冗长的尾置返回类型，简化模板函数定义

```c++
// C++14 泛型函数：返回两个参数中较大的值
template <typename T, typename U>
auto max_val(T a, U b) {
    // 推导返回类型为a/b中更宽的类型（如int+double→double）
    return (a > b) ? a : b;
}
cout << max_val(10, 20) << endl; // 20（int）
cout << max_val(3.14, 2.71) << endl; // 3.14（double）
cout << max_val(5, 3.5) << endl; // 5→推导为double（3.5的类型）
```

**简化复杂类型的返回值**

当函数返回类型为复杂容器、迭代器等时，推导可避免手写冗长的类型名

```c++
// 推导返回类型为vector<int>
auto create_int_vector() {
    vector<int> vec = {1, 2, 3, 4};
    return vec;
}
// 推导返回类型为map<string, int>::iterator
auto find_map_entry(map<string, int>& m, const string& key) {
    return m.find(key);
}
auto vec = create_int_vector();
for (int i : vec) cout << i << " "; // 1 2 3 4
map<string, int> score = {{"Alice", 90}, {"Bob", 85}};
auto it = find_map_entry(score, "Alice");
cout << "\n" << it->first << ": " << it->second << endl; // Alice: 90
```

**Lambda 与普通函数的统一风格**

返回类型推导让普通函数与 C++14 泛型 Lambda 的语法风格统一，降低代码认知成本

```c++
// 泛型Lambda（C++14）
auto lambda_add = [](auto a, auto b) { return a + b; };
// 普通函数（返回类型推导）
auto func_add(auto a, auto b) { return a + b; }
cout << lambda_add(1, 2) << endl; // 3
cout << func_add(1.5, 2.5) << endl; // 4.0
```

**编译期函数（constexpr）**

结合`constexpr`实现简洁的编译期函数，无需手动指定返回类型：

```c++
// 编译期计算数组大小（推导为size_t）
template <typename T, size_t N>
constexpr auto array_size(const T (&arr)[N]) {
    return N;
}
int arr[] = {1, 2, 3, 4, 5};
constexpr size_t size = array_size(arr); // 编译期推导为5
cout << "数组大小：" << size << endl; // 5
```

## 核心规则与注意事项

1. 推导规则

   - **单 return 语句**：直接推导为`return`表达式的类型；

   - **多 return 语句**：所有返回值必须可隐式转换为同一类型（如`int`和`double`推导为`double`，`int`和`string`编译报错）；

   - **无 return 语句**：推导为`void`（仅适用于无返回值的函数）；

   - **引用 / 指针**：`auto`会剥离引用和`const`，需用`decltype(auto)`保留。

2. 限制场景

   - 以下场景**不支持**返回类型推导：

     1. 函数声明与定义分离（仅定义可推导，声明需显式指定返回类型）；

        ```c++
        // 错误：声明时无法推导，需显式指定
        auto func(int a); 
        // 正确：声明显式指定，定义可推导
        int func(int a);
        auto func(int a) { return a + 1; }
        ```

     2. 虚函数（虚函数的返回类型必须显式指定，确保多态的正确性）；

        ```c++
        class Base {
        public:
            // 错误：虚函数不支持返回类型推导
            auto virtual func() { return 0; }
            // 正确：显式指定
            virtual int func() { return 0; }
        };
        ```

     3. 函数指针 / 函数引用（无法推导，需显式类型）

     4. 模板特化的返回类型（需与主模板一致，无法单独推导）

3. `auto` vs `decltype`(auto)

| 特性        | `auto`                   | `decltype(auto)`                     |
| ----------- | ------------------------ | ------------------------------------ |
| 引用语义    | 剥离引用，返回值拷贝     | 保留引用，返回引用 / 值              |
| `const`限定 | 剥离`const`              | 保留`const`                          |
| 适用场景    | 普通值返回               | 需保留引用 /const 的场景             |
| 示例        | `auto f() { return x; }` | `decltype(auto) f() { return (x); }` |

4. 与 C++11 Lambda 返回类型推导的区别
   - C++11 Lambda 仅支持尾置返回类型推导；
   - C++14 Lambda 默认支持返回类型推导（与普通函数一致）；
   - 普通函数返回类型推导是 C++14 新增，Lambda 推导是 C++14 对 C++11 的增强。

# 上下文相关的转换操作符

C++11 引入、C++14 优化的**上下文相关的转换操作符**（也叫 “显式转换操作符” Explicit Conversion Operators）是对用户定义类型转换的核心增强，允许通过`explicit`关键字限制转换操作符仅在 “上下文相关” 的场景下触发（如直接初始化、条件判断），避免隐式转换带来的意外行为。这解决了 C++98/03 中隐式转换操作符的 “过度转换” 问题，大幅提升了类型转换的安全性和可控性。

上下文相关转换操作符的核心价值：**通过`explicit`关键字让转换操作符仅在特定上下文（直接初始化、条件判断、显式转换）触发**，禁止无意义的隐式转换，平衡类型转换的灵活性与安全性。

## 背景

C++98/03 仅支持**隐式转换操作符**，编译器会在任意场景下自动触发类型转换，导致难以预料的行为：

1. 无意的隐式转换破坏类型安全（如将自定义数值类型隐式转换为`bool`时的逻辑错误）；
2. 转换操作符与重载函数、算术运算符冲突，引发二义性编译错误；
3. 无法区分 “显式需要转换” 和 “隐式自动转换” 的场景，代码逻辑不清晰。

```c++
// C++98 自定义数值类型
class MyInt {
    int val;
public:
    MyInt(int v) : val(v) {}
    // 隐式转换操作符：可被任意场景触发
    operator bool() const { return val != 0; }
    operator int() const { return val; }
};
MyInt a(10);
// C++98 痛点1：无意的隐式转换
if (a) cout << "a非0" << endl; // 合理：转换为bool
int b = a + 5; // 意外：a隐式转换为int，b=15（可能非预期）
MyInt c = a;   // 隐式拷贝（无问题，但转换边界模糊）
// 痛点2：二义性错误（若有重载函数）
void func(int) { cout << "int版本" << endl; }
void func(bool) { cout << "bool版本" << endl; }
// func(a); // 编译报错：无法确定转换为int还是bool
```

## 核心语法与基础使用

上下文相关转换操作符的核心是在转换操作符前添加`explicit`关键字，限制其仅在 “上下文要求特定类型” 时触发：

```c++
// C++11+ 显式转换操作符语法
class Type {
public:
    // 显式转换为bool（仅在布尔上下文触发）
    explicit operator bool() const {
        return /* 转换逻辑 */;
    }
    // 显式转换为T类型（仅在显式转换/直接初始化触发）
    template <typename T>
    explicit operator T() const { // C++14支持泛型转换操作符
        return static_cast<T>(/* 内部值 */);
    }
};
```

**触发上下文**（仅以下场景会调用显式转换操作符）：

1. **布尔上下文**：`if`/`while`条件、逻辑运算符（`&&`/`||`/`!`）、三元运算符条件；
2. **直接初始化**：`T var = static_cast<T>(obj)` 或 `T var(obj)`；
3. **显式转换**：`dynamic_cast<T>(obj)`、`reinterpret_cast<T>(obj)`；
4. `noexcept/constexpr` 判断：编译期上下文的类型检查。

**显式布尔转换**

```c++
class MyInt {
    int val;
public:
    MyInt(int v) : val(v) {}

    // C++11 显式bool转换操作符（上下文相关）
    explicit operator bool() const {
        cout << "触发bool转换" << endl;
        return val != 0;
    }

    // 显式int转换操作符
    explicit operator int() const {
        cout << "触发int转换" << endl;
        return val;
    }
};
MyInt a(10);
// 场景1：布尔上下文（触发bool转换）
if (a) { // 合法：条件判断要求bool类型
    cout << "a的值为：" << static_cast<int>(a) << endl; // 显式转换int
}
// 场景2：直接初始化（触发int转换）
int b(static_cast<int>(a)); // 合法：显式转换
cout << "b = " << b << endl;
// 场景3：禁止隐式转换（编译报错）
// int c = a; // 错误：无法隐式转换MyInt到int
// MyInt d = a + 5; // 错误：无法隐式转换进行算术运算
```

**关键**：`explicit`转换操作符仅在 “必须转换” 的上下文触发，彻底杜绝无意的隐式转换。

**泛型转换操作符（C++14 ）**

C++14 允许转换操作符使用`auto`或模板参数，实现泛型上下文转换

```c++
class GenericType {
    std::string data;
public:
    GenericType(const std::string& s) : data(s) {}

    // C++14 泛型显式转换操作符
    template <typename T>
    explicit operator T() const {
        if constexpr (std::is_same_v<T, std::string>) {
            return data;
        } else if constexpr (std::is_same_v<T, int>) {
            return std::stoi(data);
        } else if constexpr (std::is_same_v<T, double>) {
            return std::stod(data);
        } else {
            static_assert(false, "不支持的转换类型");
        }
    }
};
GenericType gt("123.45");
// 显式转换为不同类型（触发泛型转换）
std::string s = static_cast<std::string>(gt);
int i = static_cast<int>(gt);
double d = static_cast<double>(gt);
cout << "string: " << s << endl;  // 123.45
cout << "int: " << i << endl;      // 123
cout << "double: " << d << endl;   // 123.45
```

**注意**：`if constexpr`是 C++17 特性，用于编译期分支判断，配合 C++14 泛型转换操作符可实现类型安全的多类型转换。

**显式转换操作符与类模板结合**

在类模板中使用显式转换操作符，适配不同模板参数的转换逻辑

```c++
template <typename T>
class Wrapper {
    T value;
public:
    Wrapper(T v) : value(v) {}

    // 显式转换为底层类型T
    explicit operator T() const {
        return value;
    }

    // 显式转换为bool（仅当T为数值类型时）
    template <typename U = T>
    explicit operator bool() const {
        static_assert(std::is_arithmetic_v<U>, "仅数值类型支持bool转换");
        return value != T{};
    }
};
Wrapper<int> w1(0);
if (!w1) { // 触发bool转换（int类型合法）
    cout << "w1的值为0" << endl;
}
Wrapper<std::string> w2("hello");
// if (w2) {} // 编译报错：string类型不支持bool转换（static_assert触发）
// 显式转换为底层类型
int val = static_cast<int>(w1);
cout << "val = " << val << endl; // 0
```

**上下文转换与重载运算符结合**

显式`bool`转换操作符是实现 “可判断空值” 类的标准方式（如智能指针、文件流）

```c++
// 模拟智能指针的可空判断
template <typename T>
class SmartPtr {
    T* ptr;
public:
    SmartPtr(T* p = nullptr) : ptr(p) {}
    ~SmartPtr() { delete ptr; }

    // 显式bool转换：判断指针是否非空（上下文相关）
    explicit operator bool() const {
        return ptr != nullptr;
    }

    T& operator*() const { return *ptr; }
};
SmartPtr<int> sp1(new int(42));
SmartPtr<int> sp2(nullptr);
// 布尔上下文：判断指针是否非空
if (sp1) {
    cout << "*sp1 = " << *sp1 << endl; // 42
}
if (!sp2) {
    cout << "sp2为空指针" << endl;
}
// 禁止隐式转换（如赋值给bool变量需显式转换）
// bool b = sp1; // 错误：隐式转换被禁止
bool b = static_cast<bool>(sp1); // 合法：显式转换
cout << "sp1是否非空：" << boolalpha << b << endl; // true
```

## 核心使用场景

**智能指针 / 资源管理类的空值判断**

这是显式`bool`转换操作符的最经典场景，C++ 标准库的`std::unique_ptr`/`std::shared_ptr`均采用此方式

```c++
std::unique_ptr<int> up1(new int(10));
std::unique_ptr<int> up2(nullptr);
// 布尔上下文：判断智能指针是否持有资源
if (up1) {
    cout << "*up1 = " << *up1 << endl; // 10
}
if (!up2) {
    cout << "up2未持有资源" << endl;
}
```

**自定义数值类型的安全转换**

避免自定义数值类型被无意隐式转换，仅在显式需要时转换

```c++
// 高精度数值类型
class BigInt {
    std::string num;
public:
    BigInt(const std::string& s) : num(s) {}
    // 显式转换为int（仅当数值范围允许时）
    explicit operator int() const {
        if (num.size() > 10) { // 超出int范围
            throw std::out_of_range("数值过大，无法转换为int");
        }
        return std::stoi(num);
    }
    // 显式转换为bool（判断是否非空/非零）
    explicit operator bool() const {
        return !num.empty() && num != "0";
    }
};
BigInt bi1("12345");
BigInt bi2("0");
BigInt bi3("123456789012345"); // 超出int范围
// 布尔上下文：判断是否非零
if (bi1) cout << "bi1非零" << endl;
if (!bi2) cout << "bi2为零" << endl;
// 显式转换为int（合法场景）
int i = static_cast<int>(bi1);
cout << "bi1转换为int：" << i << endl; // 12345
// 转换超出范围的数值（抛出异常）
try {
    int j = static_cast<int>(bi3);
} catch (const std::out_of_range& e) {
    cout << "转换失败：" << e.what() << endl;
}
```

**IO 流的状态判断**

C++ 标准库的`std::iostream`通过显式`bool`转换操作符判断流状态

```c++
std::ifstream file("test.txt");

// 布尔上下文：判断文件是否成功打开
if (file) {
    std::string line;
    while (std::getline(file, line)) { // 循环中判断流是否有效
        cout << line << endl;
    }
} else {
    cout << "文件打开失败" << endl;
}
```

**避免重载函数的二义性**

显式转换操作符可消除隐式转换导致的函数重载二义性

```c++
class MyType {
    int val;
public:
    MyType(int v) : val(v) {}

    // 仅显式转换为int（禁止隐式转换）
    explicit operator int() const { return val; }
    // 无bool转换操作符（避免二义性）
};
void func(int x) { cout << "int: " << x << endl; }
void func(bool b) { cout << "bool: " << boolalpha << b << endl; }
MyType mt(5);
// 无歧义：必须显式指定转换类型
func(static_cast<int>(mt)); // 调用int版本
// func(mt); // 编译报错：无隐式转换，避免二义性
```

## 核心规则与注意事项

**转换触发规则**

| 场景类型               | 是否触发显式转换操作符 | 示例                       |
| ---------------------- | ---------------------- | -------------------------- |
| 布尔上下文（if/while） | 是                     | `if (obj) { ... }`         |
| 显式类型转换           | 是                     | `static_cast<T>(obj)`      |
| 直接初始化             | 是                     | `T var(obj);`              |
| 隐式赋值               | 否                     | `T var = obj;`（编译报错） |
| 算术运算               | 否                     | `obj + 5`（编译报错）      |
| 函数参数隐式传递       | 否                     | `func(obj)`（编译报错）    |

**`explicit` vs `implicit` 转换操作符**

| 特性       | 显式转换操作符（explicit） | 隐式转换操作符（implicit） |
| ---------- | -------------------------- | -------------------------- |
| 触发场景   | 仅上下文相关场景           | 任意场景自动触发           |
| 类型安全性 | 高（避免无意转换）         | 低（易引发意外行为）       |
| 适用场景   | bool 转换、数值类型转换    | 兼容 C++98/03 的旧代码     |
| 二义性风险 | 低                         | 高（重载函数冲突）         |

- **关键限制**

  - C++11 中`explicit`仅支持转换为`bool`的操作符？**错误**：C++11 允许`explicit`用于任意类型的转换操作符，`bool`是最常用场景；

  - 显式转换操作符不能被继承？**错误**：转换操作符的继承规则与普通成员函数一致；

  - 模板转换操作符不能加`explicit`？**错误**：C++14 支持`explicit`模板转换操作符；

  - 显式转换操作符无法返回值？**错误**：转换操作符的返回类型由目标类型决定（如`operator bool()`返回`bool`）。

- **与 C++17 的增强**，进一步优化了上下文转换规则：

  - 允许在`constexpr`函数中使用显式转换操作符；

  - 支持`noexcept`修饰转换操作符，明确异常行为；

  - `if constexpr`配合泛型转换操作符实现编译期类型分支。

# 聚合体拓展

C++14 对**聚合体（Aggregate）** 的定义和使用规则进行了关键拓展，放宽了聚合体的判定条件，同时增强了聚合体的初始化灵活性。这一改进解决了 C++11 中聚合体规则严苛、初始化场景受限的问题，让聚合体的泛型编程和结构化数据处理更简洁、更符合直觉。

聚合体的核心价值：**将简单的结构化数据类型（如纯数据结构体 / 数组）归类为聚合体，支持简洁的聚合初始化语法**，C++14 的拓展进一步扩大了这一语法的适用范围，降低了结构化数据的使用成本。

## 背景

C++11 及更早版本中，聚合体的定义存在严格限制，导致很多直观的 “纯数据结构” 无法被判定为聚合体，无法使用便捷的聚合初始化：

1. 包含**非静态成员初始化器（NSMI）** 的结构体 / 类会被排除在聚合体之外；
2. 聚合体的基类限制模糊，派生类几乎无法被判定为聚合体；
3. 聚合初始化的语法虽便捷，但适用范围过窄，与现代编程中 “数据优先” 的设计理念不符。

```c++
// C++11 痛点：含非静态成员初始化器的结构体不是聚合体，无法聚合初始化
struct Point {
    int x = 0;  // 非静态成员初始化器（NSMI）
    int y = 0;
};
// C++11 编译错误：Point不是聚合体，不能用{}聚合初始化
Point p{10, 20}; 
// 只能手动构造/赋值，代码冗余
Point p;
p.x = 10;
p.y = 20;
cout << p.x << ", " << p.y << endl; // 10, 20
```

## 核心语法与基础使用

**聚合体的核心定义（C++14）**

C++14 重新定义了**聚合体**：满足以下条件的类 / 结构体 / 数组称为聚合体：

1. 没有用户声明的构造函数；
2. 没有私有 / 保护的非静态数据成员；
3. 没有虚函数；
4. 没有虚基类；
5. **C++14 关键放宽**：允许包含**非静态成员初始化器（NSMI）**（即成员变量的就地初始化）。

这意味着：**只要满足前 4 条，即使成员变量有默认初始化值，仍属于聚合体，可使用聚合初始化**。

**基础聚合初始化（C++14 放宽后）**

```c++
// C++14：含非静态成员初始化器的结构体是聚合体
struct Point {
    int x = 0;  // NSMI，C++14 允许
    int y = 0;
};
// 合法：聚合初始化，覆盖默认值
Point p1{10, 20};
cout << "p1: " << p1.x << ", " << p1.y << endl; // 10, 20
// 部分初始化：未指定的成员使用默认值
Point p2{5};
cout << "p2: " << p2.x << ", " << p2.y << endl; // 5, 0
// 空初始化：所有成员使用默认值
Point p3{};
cout << "p3: " << p3.x << ", " << p3.y << endl; // 0, 0
```

**聚合体与继承（C++14 补充规则）**

C++14 明确：**只有当派生类的所有基类都是公有且非虚的，且派生类满足聚合体的其他条件时，派生类才是聚合体**。

```c++
// 基类：聚合体
struct Base {
    int id = 0;
    std::string name = "unknown";
};
// C++14：公有继承Base的派生类，无额外限制 → 仍是聚合体
struct Derived : public Base {
    double score = 0.0; // NSMI 允许
};
// 聚合初始化：先初始化基类成员，再初始化派生类成员
Derived d{101, "Alice", 95.5};
cout << "id: " << d.id << ", name: " << d.name << ", score: " << d.score << endl;
// 输出：id: 101, name: Alice, score: 95.5
```

**数组聚合体的拓展**

数组天然是聚合体，C++14 对数组聚合初始化的支持更灵活，尤其是多维数组和动态数组（结合 `constexpr`）：

```c++
// 多维数组聚合初始化（C++14 更简洁）
int matrix[2][2] = {{1, 2}, {3, 4}};
// 省略内层{}，C++14 仍合法
int matrix2[2][2] = {1, 2, 3, 4};
// constexpr 数组聚合初始化（编译期确定）
constexpr int arr[] = {1, 2, 3, 4, 5};
cout << "arr[2]: " << arr[2] << endl; // 3（编译期计算）
```

## 核心使用场景

**纯数据结构体（POD 增强）**

C++14 聚合体拓展最核心的应用是**纯数据结构体（Plain Old Data）**，无需写构造函数即可实现便捷初始化：

```c++
// 业务场景：用户信息结构体
struct UserInfo {
    std::string username = "guest";  // NSMI
    int age = 0;                     // NSMI
    bool is_vip = false;             // NSMI
};
// 聚合初始化：灵活指定部分/全部成员
UserInfo u1{"admin", 30, true};
UserInfo u2{"user1"}; // 仅指定username，其余用默认值
UserInfo u3{};        // 全用默认值
cout << u1.username << ", " << u1.age << ", " << boolalpha << u1.is_vip << endl;// 输出：admin, 30, true
cout << u2.username << ", " << u2.age << ", " << u2.is_vip << endl;// 输出：user1, 0, false
```

**与 `std::array` 结合的编译期数据**

结合 `constexpr` 和聚合初始化，可在编译期构建结构化数据数组，提升运行时性能：

```c++
// 编译期定义颜色配置
struct Color {
    const char* name = "";
    int r = 0;
    int g = 0;
    int b = 0;
};
// C++14：聚合体数组的constexpr初始化
constexpr std::array<Color, 3> colors = {{
    {"red", 255, 0, 0},
    {"green", 0, 255, 0},
    {"blue", 0, 0, 255}
}};
// 编译期访问
constexpr auto red = colors[0];
cout << red.name << ": (" << red.r << ", " << red.g << ", " << red.b << ")" << endl;// 输出：red: (255, 0, 0)
```

**泛型编程中的聚合体处理**

C++14 聚合体拓展让模板代码能更灵活地处理结构化数据，无需为简单数据结构编写复杂的构造函数：

```c++
// 泛型打印聚合体（简化版）
template <typename T, size_t N>
void print_array(const T (&arr)[N]) {
    for (size_t i = 0; i < N; ++i) {
        cout << arr[i] << " ";
    }
    cout << endl;
}
// 聚合体结构体
struct Data {
    int a = 1;
    double b = 2.5;
};
int main() {
    // 聚合初始化Data数组
    Data data_arr[] = {{3, 4.5}, {5, 6.7}};
    // 泛型打印成员
    for (const auto& d : data_arr) {
        cout << d.a << ", " << d.b << endl;// 输出：3, 4.5 5, 6.7
```

## 核心规则与注意事项

- **聚合体的判定边界**

  - C++14 聚合体仍不允许：
    - 有用户声明的构造函数（包括默认构造函数 `User() = default;` 不算用户声明，但 `User() {}` 算）；
    - 有虚函数 / 虚基类；
    - 有私有 / 保护的非静态数据成员；

  - C++14 聚合体允许：
    - 有非静态成员初始化器（NSMI）；
    - 有公有继承的非虚基类（基类也需是聚合体）；
    - 有静态成员（静态成员不参与聚合初始化）。

- 聚合初始化的规则

  - 聚合初始化使用 `{}`，成员按**声明顺序**初始化，未指定的成员使用默认值（NSMI）或零初始化；

  - 初始化列表的元素个数不能超过聚合体的成员数（数组除外）；

  - 聚合体的静态成员不会被聚合初始化影响（需单独初始化）。

```c++
struct Test {
    static int count; // 静态成员
    int x = 10;
    int y = 20;
};
int Test::count = 0;// 静态成员单独初始化
Test t{100, 200};// 聚合初始化仅影响x、y，count不受影响
cout << t.x << ", " << t.y << ", " << Test::count << endl;
// 输出：100, 200, 0
```

- 与 C++11/C++17 的兼容与演进
  - C++11：含 NSMI 的类不是聚合体，无法聚合初始化；
  - C++14：含 NSMI 的类可成为聚合体，支持聚合初始化（核心拓展）；
  - C++17：进一步放宽聚合体规则，允许基类列表中出现基类的聚合初始化（如 `Derived d{{base_member}, derived_member}`）。

| 特性       | 聚合体                          | 非聚合体                        |
| ---------- | ------------------------------- | ------------------------------- |
| 初始化方式 | 支持 `{}` 聚合初始化            | 需通过构造函数初始化            |
| 成员默认值 | 支持 NSMI，未初始化成员用默认值 | 需在构造函数中指定默认值        |
| 泛型适配   | 无需额外代码，直接适配模板      | 需编写构造函数 / 赋值运算符适配 |
| 编译期优化 | 支持 `constexpr` 编译期初始化   | 需手动声明 `constexpr` 构造函数 |
