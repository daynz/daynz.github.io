# 复杂度分析

## 一、数组 (Array) / 动态数组 (Dynamic Array / ArrayList / Vector / Slice)

*   **访问 (Access) `arr[i]`**： `O(1)` - 直接通过索引计算地址。
*   **搜索 (Search) / 查找元素 (Find)**： `O(n)` - 可能需要遍历整个数组（无序时）。如果有序，可以用**二分查找 (Binary Search)** 达到 `O(log n)`。
*   **插入 (Insertion)**：
    *   **在末尾 (Append)**： `O(1)` **平摊 (Amortized)** - 动态数组在空间不足时扩容（通常是加倍）的成本会分摊到多次`O(1)`的`append`操作上。
    *   **在开头或中间**： `O(n)` - 需要将插入点之后的所有元素向后移动。
*   **删除 (Deletion)**：
    *   **在末尾 (Pop back)**： `O(1)`。
    *   **在开头或中间**： `O(n)` - 需要将被删除元素之后的所有元素向前移动。
*   **空间复杂度**： `O(n)` - 存储`n`个元素。

## 二、链表 (Linked List) - 单链表 (Singly Linked List), 双链表 (Doubly Linked List)

*   **访问 (Access) - 按索引 (By Index)**： `O(n)` - 需要从头（或从尾，如果是双链表且索引靠近尾部）遍历找到目标节点。
*   **访问 (Access) - 头节点 (Head)**： `O(1)`。
*   **访问 (Access) - 尾节点 (Tail)**： `O(1)` （如果维护了尾指针，否则是 `O(n)`）。
*   **搜索 (Search) / 查找元素 (Find)**： `O(n)` - 需要遍历链表。
*   **插入 (Insertion)**：
    *   **在头部 (Prepend)**： `O(1)`。
    *   **在尾部 (Append)**： `O(1)` （如果有尾指针），否则 `O(n)` 找到尾部再插入。
    *   **在已知节点后插入 (After a known node)**： `O(1)` （单/双链表）。
    *   **在已知节点前插入 (Before a known node)**： `O(1)` （**仅双链表**，单链表需要 `O(n)` 找到前驱节点）。
    *   **按索引插入 (By Index)**： `O(n)` - 需要先遍历找到插入位置（或前驱节点）。
*   **删除 (Deletion)**：
    *   **删除头节点 (Remove head)**： `O(1)`。
    *   **删除尾节点 (Remove tail)**： `O(1)` （**仅双链表且维护尾指针**，单链表需要 `O(n)` 找到倒数第二个节点）。
    *   **删除已知节点 (Remove a known node)**： `O(1)` （**仅双链表**，单链表需要 `O(n)` 找到前驱节点）。
    *   **按索引删除 (By Index)**： `O(n)` - 需要先遍历找到目标节点（或前驱节点）。
*   **空间复杂度**： `O(n)` + 指针开销（每个节点需要额外的指针空间）。

## 三、栈 (Stack) - 通常用数组或链表实现

*   **压栈 (Push)**： `O(1)` （数组平摊 `O(1)`，链表 `O(1)`）。
*   **弹栈 (Pop)**： `O(1)`。
*   **查看栈顶 (Peek/Top)**： `O(1)`。
*   **判空 (Is Empty)**： `O(1)`。
*   **空间复杂度**： `O(n)`。

## 四、队列 (Queue) - 通常用链表或循环数组实现

*   **入队 (Enqueue)**： `O(1)` （链表实现，或循环数组平摊 `O(1)`）。
*   **出队 (Dequeue)**： `O(1)` （链表实现，或循环数组 `O(1)`）。
*   **查看队首 (Peek/Front)**： `O(1)`。
*   **判空 (Is Empty)**： `O(1)`。
*   **空间复杂度**： `O(n)`。

## 五、哈希表 (Hash Table) / 字典 (Dictionary) / 映射 (Map) - 通常用数组+链表/树解决冲突

*   **插入 (Insert)**： `O(1)` **平均**， `O(n)` **最坏**（所有键哈希到同一个桶，链表/树退化成线性结构）。
*   **查找 (Lookup)**： `O(1)` **平均**， `O(n)` **最坏**（同上）。
*   **删除 (Delete)**： `O(1)` **平均**， `O(n)` **最坏**（同上）。
*   **空间复杂度**： `O(n)` - 通常需要比元素数量更大的底层数组（负载因子 < 1）。

## 六、树 (Trees)

### 1. 二叉搜索树 (Binary Search Tree - BST) - 普通（非平衡）

*   **搜索 (Search)**： `O(h)`，其中 `h` 是树高。
    *   **平均**： `O(log n)` （如果树相对平衡）。
    *   **最坏**： `O(n)` （树退化成链表）。
*   **插入 (Insert)**： `O(h)` （同上，平均 `O(log n)`，最坏 `O(n)`）。
*   **删除 (Delete)**： `O(h)` （同上，平均 `O(log n)`，最坏 `O(n)`）。
*   **访问最小/最大值 (Min/Max)**： `O(h)` （最左/最右节点）。
*   **空间复杂度**： `O(n)` + 指针开销。

### 2. 平衡二叉搜索树 (Balanced BST - e.g., AVL Tree, Red-Black Tree)

*   **搜索 (Search)**： `O(log n)` **最坏** - 平衡保证树高为 `O(log n)`。
*   **插入 (Insert)**： `O(log n)` **最坏** - 插入后可能需要旋转操作恢复平衡。
*   **删除 (Delete)**： `O(log n)` **最坏** - 删除后可能需要旋转操作恢复平衡。
*   **访问最小/最大值 (Min/Max)**： `O(log n)` **最坏** （虽然最左/最右节点深度最多 `O(log n)`）。
*   **空间复杂度**： `O(n)` + 指针开销（可能还有平衡因子/颜色等额外空间）。

### 3. 堆 (Heap) - 通常用数组实现（二叉堆）

*   **查找最大值/最小值 (Find Max/Min)**： `O(1)` - 根节点就是最大/最小元素（取决于是最大堆还是最小堆）。
*   **插入 (Insert)**： `O(log n)` - 上浮 (sift-up / percolate-up) 操作。
*   **删除最大值/最小值 (Extract Max/Min)**： `O(log n)` - 下沉 (sift-down / heapify-down) 操作。
*   **堆化 (Heapify)**： **从无序数组建堆**： `O(n)` （这是一个重要且常被误解的操作）。
*   **空间复杂度**： `O(n)`。

## 七、图 (Graphs) - 复杂度高度依赖于表示方式（邻接矩阵、邻接表）和具体算法

### 1. 基本图操作 (基于邻接表表示)

*   **添加顶点 (Add Vertex)**： `O(1)` （通常）。
*   **添加边 (Add Edge)**： `O(1)` （邻接表）。
*   **删除顶点 (Remove Vertex)**： `O(V + E)` **最坏** （需要移除所有与该顶点相关的边）。
*   **删除边 (Remove Edge)**： `O(degree(u))` 或 `O(degree(v))` （在顶点 u 或 v 的邻接表中查找并删除）。
*   **查询边是否存在 (Query Edge)**： `O(degree(u))` 或 `O(degree(v))` （邻接表），`O(1)` （邻接矩阵）。
*   **获取邻居 (Get Neighbors)**： `O(degree(v))` （邻接表）。
*   **空间复杂度**：
    *   **邻接矩阵 (Adjacency Matrix)**： `O(V^2)`。
    *   **邻接表 (Adjacency List)**： `O(V + E)`。

### 2. 图遍历算法

*   **广度优先搜索 (BFS)**： `O(V + E)` - 访问所有顶点和边一次。
*   **深度优先搜索 (DFS)**： `O(V + E)` - 访问所有顶点和边一次。

### 3. 最短路径算法 (单源)

*   **Dijkstra (带权图，无负权边)**：
    *   **基于数组/无序集合**： `O(V^2)`。
    *   **基于最小堆 (优先队列)**： `O((V + E) log V)`。
    *   **基于斐波那契堆 (理论最优)**： `O(E + V log V)`。
*   **Bellman-Ford (带权图，允许负权边，检测负权环)**： `O(V * E)`。

### 4. 最短路径算法 (所有点对)

*   **Floyd-Warshall (带权图，允许负权边，但不允许负权环)**： `O(V^3)`。

### 5. 最小生成树 (MST)

*   **Kruskal (基于并查集)**： `O(E log E)` 或 `O(E log V)` （排序边的成本）。
*   **Prim (基于最小堆)**： `O((V + E) log V)` ≈ `O(E log V)` （稠密图）。

## 八、其他重要概念与操作

*   **字符串匹配 (String Matching)**：
    *   **朴素算法 (Naive)**： `O(n * m)`，其中 `n` 是文本长度，`m` 是模式长度。
    *   **KMP (Knuth-Morris-Pratt)**： `O(n + m)` - 预处理模式串 `O(m)`，匹配 `O(n)`。
    *   **Boyer-Moore**： **平均** `O(n/m)`， **最坏** `O(n * m)`。实际中非常高效。
*   **排序 (Sorting)**：
    *   **比较排序下界 (Comparison Sort Lower Bound)**： `Ω(n log n)`。
    *   **快速排序 (Quicksort)**： `O(n log n)` **平均**， `O(n^2)` **最坏**。
    *   **归并排序 (Mergesort)**： `O(n log n)` **最坏**， 需要 `O(n)` 额外空间。
    *   **堆排序 (Heapsort)**： `O(n log n)` **最坏**，原地排序。
    *   **计数排序 (Counting Sort)** / **桶排序 (Bucket Sort)** / **基数排序 (Radix Sort)**： `O(n + k)` / `O(n + k)` / `O(d * (n + k))` (非比较排序，对输入数据有特定要求)。
*   **空间复杂度 (Space Complexity)**： 除了数据结构本身占用的空间 `O(n)`，还要关注算法执行过程中使用的**额外辅助空间 (Auxiliary Space)**。
*   **平摊分析 (Amortized Analysis)**： 用于分析一系列操作的平均成本（如动态数组的 `append`）。
*   **稳定性 (Stability)**： 指算法在多次运行中，对相同输入是否总是表现出相同的时间/空间复杂度（通常讨论最坏情况）。
