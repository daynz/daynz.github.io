# 智能指针基础

本质是**封装了原生指针的类模板**，核心目标是**自动管理内存**，避免手动 `new/delete` 导致的内存泄漏、野指针、重复释放等问题。

它遵循 RAII（资源获取即初始化）原则，利用对象的生命周期（构造时获取资源，析构时释放资源）来保证内存安全。其核心逻辑：

- **构造时**：接管原始指针的所有权，申请动态资源；
- **析构时**：自动释放接管的资源（无需手动调用 `delete`）；
- **使用时**：重载 `operator*` 和 `operator->`，行为与原始指针一致。

| 手动管理内存的问题         | 智能指针的解决方案                            |
| -------------------------- | --------------------------------------------- |
| 忘记 `delete` 导致内存泄漏 | 析构函数自动调用 `delete`                     |
| 多次 `delete` 导致双重释放 | 所有权管理（独占 / 共享），确保资源仅释放一次 |
| 指针悬空（野指针）         | 析构时置空指针，弱指针检测资源是否有效        |
| 异常安全问题               | 析构函数在栈展开时自动执行，保证资源释放      |

## `std::unique_ptr`（独占式智能指针）

`std::unique_ptr` 是通过指针占有并管理另一对象，并在 `unique_ptr` 离开作用域时释放该对象的智能指针。

`std::unique_ptr`表示对资源的**唯一**所有权。同一时间，只能有一个 `unique_ptr` 指向该对象。

发生下列两者之一时用关联的删除器释放对象：

- 销毁了管理的 `unique_ptr` 对象
- 通过 `operator=` 或 `reset()` 赋值另一指针给管理的 `unique_ptr` 对象。

`Deleter` 必须是 *函数对象* 或到 *函数对象*的左值引用或到函数的左值引用，可以 `unique_ptr<T, Deleter>::pointer` 类型参数调用

**特性**：

- **独占所有权**：同一时刻，只有一个 `unique_ptr` 能指向某一资源，不支持拷贝（`copy`），仅支持移动（`move`）；
- **不可拷贝**：拷贝构造函数和拷贝赋值运算符被删除（`= delete`）。你不能复制一个 `unique_ptr`。
- **可移动**：支持移动语义（Move Semantics）。所有权可以通过 `std::move` 转移给另一个 `unique_ptr`。
- **零开销**：在大小和行为上与普通裸指针几乎无异，没有引用计数的开销。
- **自动释放**：离开作用域或调用 `reset()` 时自动 `delete` 对象。
- **支持自定义删除器**：可指定资源释放的方式（如释放数组、文件句柄）。

```c++
// 1. 创建 unique_ptr，管理动态分配的对象
std::unique_ptr<MyClass> ptr1(new MyClass(10));
ptr1->show(); // 用 -> 访问成员，和原生指针一致

// 2. 推荐写法：make_unique（C++14 引入，更安全，避免内存泄漏）
auto ptr2 = std::make_unique<MyClass>(20);
ptr2->show();

// 3. 移动语义（唯一的所有权转移方式）
std::unique_ptr<MyClass> ptr3 = std::move(ptr1); // ptr1 变为空，ptr3 接管对象
if (ptr1 == nullptr) {
	std::cout << "ptr1 已为空" << std::endl;
}
ptr3->show();

// 4. 手动释放资源（一般不需要，析构会自动释放）
ptr3.reset(); // 释放对象，ptr3 变为空
```

**关键说明**

- 禁止拷贝：`std::unique_ptr<MyClass> ptr4 = ptr2;` 会编译报错，因为拷贝构造函数被禁用。

- 适用场景：单个对象的独占管理（如函数返回值、局部动态对象、容器中的独占元素）。

- 容器支持：可作为 `std::vector` 等容器的元素（因为支持移动）。

- 自定义删除器：适用于非 `new` 申请的资源（如 `malloc`、文件句柄）：

  - ```c++
    // 自定义删除器：释放 malloc 申请的内存
    auto del = [](int* p) { free(p); cout << "释放 malloc 内存\n"; };
    unique_ptr<int, decltype(del)> p5((int*)malloc(4), del);
    ```

## `std::shared_ptr`（共享式智能指针）

`std::shared_ptr` 是通过指针保持对象共享所有权的智能指针。多个 `shared_ptr` 对象可占有同一对象。

当多个部分需要同时访问同一个对象，且无法确定谁最后使用它时，使用 `shared_ptr`。它内部维护一个**控制块（Control Block）**，包含**引用计数**。

下列情况之一出现时销毁对象并解分配其内存：

- 最后剩下的占有对象的 `shared_ptr` 被销毁；
- 最后剩下的占有对象的 `shared_ptr` 被通过 `operator=` 或 `reset()` 赋值为另一指针。

用 `delete` 表达式或在构造期间提供给 `shared_ptr` 的定制删除器销毁对象。

**特性**：

- **可拷贝**：拷贝时引用计数 +1。
- **自动释放**：当最后一个指向该对象的 `shared_ptr` 被销毁或重置时（引用计数归零），对象才被删除。
- **线程安全**：**引用计数**的操作是原子操作（线程安全的），但**所指对象本身**的访问不是线程安全的（多线程读写同一对象仍需加锁）。
- **开销**：比 `unique_ptr` 大，因为需要维护引用计数和控制块（通常涉及堆分配和原子操作）。

```c++
// 1. 创建 shared_ptr（推荐用 make_shared，效率更高，内存分配更紧凑）
std::shared_ptr<MyClass> ptr1 = std::make_shared<MyClass>(30);
std::cout << "引用计数：" << ptr1.use_count() << std::endl; // 输出 1

// 2. 拷贝，引用计数+1
std::shared_ptr<MyClass> ptr2 = ptr1;
std::cout << "引用计数：" << ptr1.use_count() << std::endl; // 输出 2

// 3. 多个指针共享同一个对象
ptr1->show();
ptr2->show();

// 4. 重置指针，引用计数-1
ptr1.reset();
std::cout << "引用计数：" << ptr2.use_count() << std::endl; // 输出 1
```

- **避免裸指针重复构造**，用裸指针构造两个 `shared_ptr`（例如 `shared_ptr<int> p1(new int(1)); shared_ptr<int> p2(p1.get());`），`p1.get()` 的作用是**仅返回 `p1` 管理的原始指针**，这会导致双重释放。应该始终从同一个 `shared_ptr` 拷贝，或使用 `make_shared`。
- **避免循环引用**：如果两个对象互相持有对方的 `shared_ptr`，引用计数永远无法归零，导致内存泄漏。需用 `weak_ptr` 解决。

```c++
// 裸指针重复构造
shared_ptr<int> p1(new int(1)); 
shared_ptr<int> p2(p1.get());

// 循环引用示例（错误）
class A;
class B;

class A {
public:
    std::shared_ptr<B> b_ptr;
    ~A() { std::cout << "A 析构" << std::endl; }
};

class B {
public:
    std::shared_ptr<A> a_ptr;
    ~B() { std::cout << "B 析构" << std::endl; }
};

int main() {
    auto a = std::make_shared<A>();
    auto b = std::make_shared<B>();
    a->b_ptr = b; // A 引用 B
    b->a_ptr = a; // B 引用 A
    // 此时 a 和 b 的引用计数都是 2
    return 0; // 函数结束，引用计数各减 1（变为 1），无法析构，内存泄漏
}
```

## `std::weak_ptr`（弱引用智能指针）

`weak_ptr` 是 `shared_ptr` 的辅助工具。它**不拥有**对象，不增加引用计数。主要用于解决 `shared_ptr` 的**循环引用**问题，或者作为“观察者”检查对象是否还存在。

**特性**：

- **弱引用**：不拥有资源所有权，仅观察 `shared_ptr` 管理的资源；
- **不控制生命周期**：它的存在与否不影响对象的销毁。
- **不影响引用计数**：创建 / 拷贝 `weak_ptr` 不会增加 `shared_ptr` 的引用计数；
- **不能直接解引用**：必须先通过 `lock()` 提升为 `shared_ptr`。
- **检查有效性**：`expired()` 方法可判断对象是否已被销毁。

```c++
class A;
class B;

class A {
public:
    shared_ptr<B> b_ptr;
    ~A() { cout << "A 析构\n"; }
};

class B {
public:
    // 改为 weak_ptr 解决循环引用
    weak_ptr<A> a_ptr; 
    ~B() { cout << "B 析构\n"; }
};

int main() {
    // 1. 解决循环引用
    shared_ptr<A> a = make_shared<A>();
    shared_ptr<B> b = make_shared<B>();
    a->b_ptr = b;
    b->a_ptr = a; // weak_ptr 不增加 a 的引用计数

    cout << "a 引用计数：" << a.use_count() << endl; // 输出：1
    cout << "b 引用计数：" << b.use_count() << endl; // 输出：1

    // 2. lock()：获取可用的 shared_ptr（资源有效则返回非空）
    if (shared_ptr<A> a_tmp = b->a_ptr.lock()) {
        cout << "A 资源有效\n";
    } else {
        cout << "A 资源已释放\n";
    }

    // 3. expired()：检测资源是否已释放
    a.reset();
    cout << "A 资源是否过期：" << b->a_ptr.expired() << endl; // 输出：1

    return 0; // a、b 析构，引用计数归 0，资源释放
}
```

**关键方法**

- 不能直接解引用：`weak_ptr` 无 `operator*` 和 `operator->`，需通过 `lock()` 转为 `shared_ptr` 后使用；

- `lock()`：将 `weak_ptr` 转换为 `shared_ptr`，如果对象已销毁，返回空的 `shared_ptr`（安全访问对象的核心方法）；

- `expired()`：检查所指向的对象是否已销毁（引用计数为 0），返回 `bool`。

- ```c++
  auto ptr = std::make_shared<MyClass>(40);
  std::weak_ptr<MyClass> weak_ptr = ptr;
  
  // 安全访问对象
  if (auto shared = weak_ptr.lock()) {
      shared->show(); // 对象存在，正常访问
  } else {
      std::cout << "对象已销毁" << std::endl;
  }
  
  ptr.reset(); // 释放对象
  if (weak_ptr.expired()) {
      std::cout << "对象已销毁" << std::endl;
  }
  ```

## 智能指针的最佳实践

1. **优先使用 `make_unique`/`make_shared`**：

   - 避免直接用 `new` 创建智能指针，`make_xxx` 更安全（防止异常导致内存泄漏），且 `make_shared` 会一次性分配对象内存和引用计数内存，效率更高。
   - **异常安全**：`new T` 和 `shared_ptr` 构造是分开的两步。如果 `new` 成功后，构造 `shared_ptr` 前抛出异常，内存会泄漏。`make_shared` 是一步完成的，完全异常安全。
   - **性能**：`make_shared` 会将对象和控制块分配在同一块内存中，减少一次堆分配，提高缓存命中率。

2. **避免混合使用智能指针和原生指针**：

   - 不要用原生指针访问智能指针管理的对象，更不要手动 `delete` 智能指针管理的原生指针（会导致重复释放）。

3. **自定义删除器**:智能指针不仅限于 `delete`。你可以传入自定义删除器来管理文件、Socket、数据库连接等资源。

   - ```c++
     // 管理 FILE*
     auto fileDeleter = [](FILE* f) { if(f) fclose(f); };
     std::unique_ptr<FILE, decltype(fileDeleter)> fp(fopen("test.txt", "r"), fileDeleter);
     // fp 离开作用域自动 fclose
     ```

4. **`unique_ptr` 作为函数返回值**：

   - 函数返回 `unique_ptr` 时，编译器会自动优化为移动语义，无需手动 `std::move`，简洁且高效。

5. **`weak_ptr` 仅用于解决循环引用**：

   - 不要滥用 `weak_ptr`，它无法直接操作对象，必须通过 `lock()` 转换为 `shared_ptr` 才能访问，适合作为观察者（如缓存、观察者模式）。

# 智能指针原理

## `std::unique_ptr`

### 定义

```c++
template<
	class T,
	class Deleter = std::default_delete<T>
> class unique_ptr;

template <
    class T,
    class Deleter
> class unique_ptr<T[], Deleter>;
```

### 实现细节（伪代码）

```c++
template <typename T, typename Deleter = std::default_delete<T>>
class unique_ptr {
private:
    T* ptr;          // 原始指针
    Deleter del;     // 删除器（可通过空基类优化为零大小）
public:
    // 构造函数：接管原始指针
    explicit unique_ptr(T* p = nullptr) : ptr(p) {}
    // 禁止拷贝
    unique_ptr(const unique_ptr&) = delete;
    unique_ptr& operator=(const unique_ptr&) = delete;
    // 支持移动：转移所有权
    unique_ptr(unique_ptr&& other) noexcept : ptr(other.ptr) { other.ptr = nullptr; } // 原指针置空，避免重复释放
    // 析构函数：自动释放资源
    ~unique_ptr() { if (ptr) del(ptr); } // 通过删除器释放内存
    // 指针操作符重载
    T& operator*() const { return *ptr; }
    T* operator->() const { return ptr; }
    T* get() const { return ptr; }
    // 释放所有权：返回原始指针并置空
    T* release() {
        T* temp = ptr;
        ptr = nullptr;
        return temp;
    }
    // 重置指针：释放当前资源并接管新指针
    void reset(T* p = nullptr) {
        if (ptr) del(ptr);
        ptr = p;
    }
};
```

### 删除器

`unique_ptr`的删除器是**模板参数的一部分**（类型绑定），支持自定义删除逻辑（如管理文件句柄、套接字等非内存资源）。

| 写法               | 适用场景        |
| :----------------- | :-------------- |
| 默认删除器         | 普通 new/delete |
| 函数指针           | C 风格          |
| 函数对象（仿函数） | 常用            |
| Lambda             | 简短逻辑        |
| 有状态删除器       | 需要配置 / 日志 |

```c++
// 自定义删除器：管理FILE*
struct FileDeleter {
    void operator()(FILE* f) const { if (f) fclose(f);  }
};
std::unique_ptr<FILE, FileDeleter> file(fopen("test.txt", "r")); // 使用自定义删除器的unique_ptr
```

#### 函数指针

适合管理 **C 语言资源**（文件、内存、套接字）。

```c++
using FilePtr = unique_ptr<FILE, int(*)(FILE*)>;// 声明删除器类型
FilePtr fp(fopen("test.txt", "r"), fclose);// 使用
```

缺点：有**指针大小开销**（1 个指针），不能空基类优化。

#### 函数对象 / 仿函数

空类会被编译器优化，**内存大小 = 原始指针**。

```c++
struct FileDeleter {
    void operator()(FILE* fp) const { if (fp) fclose(fp); }
};
unique_ptr<FILE, FileDeleter> fp(fopen("test.txt", "r"));// 使用
```

#### Lambda 表达式

必须指定 `decltype`

```c++
auto del = [](FILE* fp) { if (fp) fclose(fp); };
unique_ptr<FILE, decltype(del)> fp(fopen("test.txt", "r"), del);
```

#### 标准库删除器

```c++
unique_ptr<void, decltype(&free)> data(malloc(100), free); // 调用 free() 释放 malloc 分配的内存
unique_ptr<void, decltype(&CloseHandle)> handle(CreateFile(...), CloseHandle); // 调用 CloseHandle 关闭 Windows 句柄
```

#### 有状态删除器

删除器可以**带成员变量**，比如自定义日志、自定义路径。

```c++
struct LogDeleter {
    const char* name;  // 状态
    void operator()(int* p) const {
        printf("delete: %s\n", name);
        delete p;
    }
};
unique_ptr<int, LogDeleter> p(new int(5), LogDeleter{"test"}); // 构造时传入状态
```

### 线程安全

`unique_ptr`本身**不提供线程安全保证**：

- 由于独占所有权，多线程下无需同步引用计数；
- 若需在多线程间转移所有权，需用户自行保证同步。

## `std::shared_ptr`

### 定义

```c++
template< class T > class shared_ptr;
```

### 控制块结构（伪代码）

```c++
struct ControlBlock {
    std::atomic<long> strong_refs;  // 强引用计数（原子操作保证线程安全）
    std::atomic<long> weak_refs;    // 弱引用计数（原子操作）
    void* object;                    // 指向管理的对象
    std::function<void(void*)> deleter;  // 删除器（类型擦除）
    // ... 其他成员（如分配器、自定义数据等）
};
```

### `shared_ptr`的内存布局

每个`shared_ptr`对象仅包含两个指针（内存开销为两个指针大小）：

1. 指向管理对象的原始指针（用于`operator*`、`operator->`）；
2. 指向控制块的指针（用于管理引用计数）。

### 关键操作的实现逻辑

**构造函数**

- 若通过原始指针构造（`shared_ptr<T> p(new T)`）：分配新的控制块，强引用计数初始化为 1；
- 若通过拷贝构造（`shared_ptr<T> p = q`）：共享同一控制块，强引用计数 + 1（原子操作）；
- 若通过移动构造（`shared_ptr<T> p = std::move(q)`）：转移控制块所有权，原`shared_ptr`置空，引用计数不变。

**析构函数**

- 强引用计数 - 1（原子操作）；
- 若强引用计数降为 0：
  1. 调用删除器销毁对象；
  2. 弱引用计数 - 1；
  3. 若弱引用计数也为 0：释放控制块。

**拷贝赋值运算符**

```c++
shared_ptr& operator=(const shared_ptr& other) {
    if (this != &other) {
        // 1. 先增加新控制块的引用计数（避免自赋值时提前释放）
        if (other.control_block) {
            other.control_block->strong_refs.fetch_add(1, std::memory_order_relaxed);
        }
        // 2. 释放当前控制块
        release_current();
        // 3. 指向新控制块
        object_ptr = other.object_ptr;
        control_block = other.control_block;
    }
    return *this;
}
```

**删除器的类型擦除**

与`unique_ptr`不同，`shared_ptr`的删除器**不是模板参数的一部分**，而是通过**类型擦除**存储在控制块中（使用`std::function`或虚函数）。这使得：

- 不同删除器的`shared_ptr<T>`可互相赋值（只要指向同一类型`T`）；
- 删除器可在运行时动态指定，灵活性更高。

### 优化与异常安全

`make_shared<T>(args...)`是创建`shared_ptr`的推荐方式，优势在于：

1. **内存分配优化**：一次性分配对象和控制块的内存（减少一次内存分配，提升性能）；
2. **异常安全**：若对象构造失败，控制块也会被自动释放，避免内存泄漏。

###  线程安全

`shared_ptr`的线程安全分为两层：

1. **引用计数的线程安全**：强 / 弱引用计数的增减通过原子操作（`std::atomic`）实现，多线程下拷贝 / 销毁`shared_ptr`无需同步；
2. **对象访问的线程安全**：`shared_ptr`不保护对象本身的线程安全，若多线程同时读写同一对象，需用户自行加锁。

## `std::weak_ptr`

### 定义

```c++
template< class T > class weak_ptr;
```

### 实现原理

`weak_ptr`与`shared_ptr`共享同一控制块，但仅影响**弱引用计数**：

- 当`shared_ptr`构造`weak_ptr`时，弱引用计数 + 1；
- 当`weak_ptr`析构时，弱引用计数 - 1；
- 当强引用计数降为 0 时，对象被销毁，但控制块需等弱引用计数也为 0 才释放。

### 关键操作

**`lock()`：获取`shared_ptr`**

`weak_ptr`不能直接访问对象，需通过`lock()`方法获取有效的`shared_ptr`：

- 若对象未被销毁：返回指向该对象的`shared_ptr`（强引用计数 + 1）；
- 若对象已被销毁：返回空的`shared_ptr`。

**`expired()`：检查对象是否销毁**

`expired()`等价于`lock() == nullptr`，但更高效（不增加引用计数）。
