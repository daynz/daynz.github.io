# `std::byte`

`std::byte` 是 C++17 引入的**独立字节类型**，专门用来表示**内存中的原始字节（8 位二进制数据）**，而不是字符或数值。

核心价值：**类型安全的原始字节，禁止算术运算，语义纯粹，杜绝隐式转换，让底层内存操作更安全**。

## 背景

在 C++17 之前，表达 “原始字节” 只有两种方案，都有严重缺陷：

1. `char / unsigned char`：

   既是字符又是整数，语义模糊，容易被误用做加减乘除；

2. `uint8_t`：

   本质是整数，支持算术运算，无法区分 “数值” 和 “原始字节”。

```c++
unsigned char buffer[1024];// 问题：语义不清晰，这是数字？字符？还是内存字节？
```

## 核心定义

- **专门表示内存中的 1 字节原始数据**
- **不是字符**、**不是整数**、**不参与数学运算**
- 底层等价于 `unsigned char`，但**强类型、语义纯净**
- 只允许**位运算**（`| & ^ ~`），**禁止加减乘除**
- 头文件：`<cstddef>`

**头文件**

```c++
#include <cstddef>  // std::byte
using namespace std::literals; // 可选：字面量
```

```c++
std::byte b1{ 0x2A };       // 列表初始化（推荐）
std::byte b2 = 0b1010_byte; // C++17 字节字面量
```

| 类型            | 语义                   | 允许运算      | 类型安全 |
| --------------- | ---------------------- | ------------- | -------- |
| **`std::byte`** | **原始字节、内存数据** | 仅**位运算**  | ✅ 最高   |
| `unsigned char` | 字符 / 整数            | 算术 + 位运算 | ❌ 差     |
| `uint8_t`       | 8 位整数               | 算术 + 位运算 | ❌ 差     |

## 核心使用场景

**位运算**

`std::byte` **只支持位操作**，完全禁止算术运算：

```c++
std::byte a{0b0001};
std::byte b{0b0100};
auto c = a | b;    // 或
auto d = a & b;    // 与
auto e = a ^ b;    // 异或
auto f = ~a;       // 取反
a <<= 1;           // 移位
```

**与整数转换**

`std::byte` **不会隐式转换**，必须显式转换：

```c++
std::byte b{ 0x10 };
int val = std::to_integer<int>(b);// byte → 整数
std::byte b2{ 5 };// 整数 → byte
```

## 注意事项

1. **纯语义类型**：只代表内存字节，不代表数值 / 字符
2. **禁止算术运算**：从根源避免错误
3. **无隐式转换**：必须显式转换
4. **底层兼容**：与 `unsigned char` 布局完全一致
5. **大小固定 1 字节**

# `std::invoke`

`std::invoke` 是 C++17 引入的**通用可调用对象包装器**，它提供了**统一、透明、一致**的方式来调用**任何可调用对象**：普通函数、函数指针、lambda、`std::function`、**成员函数、成员变量**。

核心价值：**用同一套接口调用一切可调用对象，自动处理成员函数指针、成员变量、对象引用 / 指针 / 智能指针，代码极度通用**。

## 背景

在 C++ 里，调用不同可调用对象的语法**完全不一样**，写泛型代码非常痛苦：

1. 普通函数：`func(args...)`
2. 成员函数：`(obj.*func)(args...)`
3. 成员函数（指针）：`(obj->*func)(args...)`
4. 仿函数 /lambda：`obj(args...)`

写一个通用调用器非常麻烦，**`std::invoke` 直接统一所有语法**。

## 核心定义

```c++
#include <functional>   // 头文件
```

```c++
std::invoke(可调用对象, 对象/参数...);
```

**完美支持所有 C++ 可调用类型**

| 可调用对象      | 用法                                   |
| --------------- | -------------------------------------- |
| 普通函数        | `invoke(func, args...)`                |
| lambda / 仿函数 | `invoke(func, args...)`                |
| 成员函数        | `invoke(&T::func, obj, args...)`       |
| 成员变量        | `invoke(&T::var, obj)`                 |
| 对象指针        | `invoke(&T::func, ptr, args...)`       |
| 智能指针        | `invoke(&T::func, smart_ptr, args...)` |

## 核心使用场景

**调用普通函数 /lambda**

```c++
auto add = [](int a, int b) { return a + b; };
int sum = std::invoke(add, 1, 2); // 3
```

**调用成员函数**

```c++
struct Foo {
    int f(int x) { return x * 2; }
};
Foo obj;
int res = std::invoke(&Foo::f, obj, 10);  // 20
```

**直接访问成员变量**

```c++
struct Foo { int x = 42; };
Foo obj;
int val = std::invoke(&Foo::x, obj); // 42
```

**支持指针 / 智能指针**

```c++
Foo* p = &obj;
int val = std::invoke(&Foo::x, p); // 42
```

**能接受任何函数 / 成员函数，不用区分语法**

```c++
template <typename Callable, typename... Args>
decltype(auto) call(Callable&& cb, Args&&... args) {
    return std::invoke(std::forward<Callable>(cb), 
                       std::forward<Args>(args)...);
}
```

**`std::invoke_result`：获取返回值类型**

```c++
using Ret = std::invoke_result_t<decltype(add), int, int>; // 获取调用结果类型
// Ret = int
```

# `std::apply`

`std::apply` 是 C++17 引入的**元组展开工具**，它的作用只有一个：

**把一个 `std::tuple` 里的所有元素，自动展开成函数的实参，并调用该函数。**

核心价值：**一键将 tuple 解包为函数参数**，完美解决元组与函数参数之间的转换问题，是处理批量参数、绑定、反射的神器。

## 背景

在 C++17 之前，想把 `std::tuple` 里的参数传给函数**极其麻烦**：

- 必须手写递归展开
- 代码冗长、容易出错
- 无法直观实现 `func(tuple_args...)`

```c++
// 有个函数
void func(int, double, std::string);
// 有个 tuple
std::tuple tp{1, 3.14, "hello"};
// C++14：无法直接写 func(tp) ❌
// 必须手写复杂的模板展开
```

## 核心语法

**头文件**

```c++
#include <tuple>
```

```c++
std::apply(函数, 元组) → 调用函数(元组第1项, 元组第2项, ...)
```

- 接收：**任意可调用对象**（函数、lambda、成员函数）
- 接收：**`std::tuple` / `std::pair` / `std::array`**
- 行为：**自动展开元组 → 调用函数**
- 返回：函数的返回值

```c++
void print(int a, double b, const std::string& c) {
    std::cout << a << " " << b << " " << c << "\n";
}
std::tuple<int, double, std::string> tp = {10, 3.14, "test"};// 自动把 tuple 展开成三个参数传给 print
std::apply(print, tp); //10 3.14 test
```

## 核心使用场景

**最常用场景：lambda + apply**

```c++
std::tuple tp{2, 3, 4};
int sum = std::apply([](auto... args) { // 展开后求和
    return (args + ...); // 折叠表达式
}, tp);// sum = 9
```

**支持 pair /array**

```c++
std::pair p{1, 2};
std::apply([](auto a, auto b) {
    std::cout << a + b; // 3
}, p);
```

**`std::apply` + `std::invoke`**

把 tuple 展开成成员函数的参数

```c++
struct Foo {
    int add(int a, int b) { return a + b; }
};
Foo obj;
auto args = std::make_tuple(1, 2);
// 调用 obj.add(1,2)
int res = std::apply(
    [&](auto&&... args) {
        return std::invoke(&Foo::add, obj, args...);
    },
    args
);
```

C++20 甚至有 `std::invoke_r` 可以进一步简化

## 核心用途

1. **把 tuple 变成函数参数**
2. **批量参数传递、序列化、反序列化**
3. **函数绑定、回调、反射系统**
4. **配合折叠表达式处理任意参数**
5. **解包 pair /array**

# `std::make_from_tuple`

`std::make_from_tuple` 是 C++17 引入的**元组构造工具**，作用是：

**将一个 `std::tuple` 中的元素自动展开，作为构造函数的参数，直接构造出一个对象。**

核心价值：**一行代码用 tuple 里的参数构造对象**，完美解决 “参数存在 tuple 里，怎么传给构造函数” 的问题，是序列化、反射、工厂模式的神器。

## 背景

你经常会遇到这种场景：

- 把构造参数存在了 `tuple` 里
- 想直接用这个 tuple 构造一个对象

**C++14 无法直接做到**，必须手写复杂的模板展开。

```c++
struct Person {
    Person(int age, std::string name) : age(age), name(name) {}
    int age; std::string name;
};
std::tuple<int, std::string> args{20, "Alice"};
// C++14：无法直接写 Person p{args};
```

## 核心语法

**头文件**

```c++
#include <tuple>
```

```c++
std::make_from_tuple<T>(元组);
T(std::get<0>(tuple), std::get<1>(tuple), ...);//等价
```

- 作用：**解包 tuple → 传给 T 的构造函数 → 返回 T 对象**
- 返回：**构造好的 T 实例**

```c++
struct Person {
    Person(int age, std::string name) : age(age), name(name) {}
    int age;
    std::string name;
};
auto args = std::make_tuple(25, "Bob");// 参数存在 tuple 里
Person p = std::make_from_tuple<Person>(args);// 直接用 tuple 构造 Person 对象
Person p{25, "Bob"};//等价
```

**与 `std::apply` 的关系**

`make_from_tuple` 本质就是 **`apply` 的构造专用版**：

- `std::apply(函数, tuple)` → 调用函数
- `std::make_from_tuple<T>(tuple)` → 调用 T 的构造函数

内部实现几乎一样，只是专门给**构造对象**使用。

| 工具                   | 作用                      |
| ---------------------- | ------------------------- |
| `std::apply`           | 把 tuple 传给**函数**     |
| `std::make_from_tuple` | 把 tuple 传给**构造函数** |

## 核心使用场景

**工厂模式 + 参数包**

从配置 / 序列化数据中批量构造对象：

```c++
template <typename T, typename Tuple>
T create_object(Tuple&& tuple) {
    return std::make_from_tuple<T>(std::forward<Tuple>(tuple));
}
auto p = create_object<Person>(std::make_tuple(18, "Charlie"));
```

**反射 / 解序列化**

把网络 / 文件读取的参数 tuple，直接还原成对象：

```c++
auto params = parse_to_tuple(data);// 从数据流解析出参数 tuple
auto obj = std::make_from_tuple<MyClass>(params);// 直接构造目标对象
```

**配合完美转发**

高效转发参数，无拷贝：

```c++
auto args = std::make_tuple(1, "test");
auto obj = std::make_from_tuple<MyClass>(std::move(args));
```

## 支持的类型

- `std::tuple`
- `std::pair`
- `std::array`
- 自定义的 tuple-like 类型

```c++
auto p = std::make_from_tuple<std::pair<int, int>>(std::make_tuple(1,2));// pair 也可以
```

# `std::conjunction`, `std::disjunction`, `std::negation`

这三个是 C++17 新增的**编译期逻辑运算元工具**，专门用于**模板元编程中对多个 `type_traits`（类型特性）进行 与、或、非 逻辑运算**。

核心价值：**简化复杂类型判断，短路求值，更清晰、更高效、更标准的编译期逻辑**。

## 核心语法与基础使用

**头文件**

```c++
#include<type_traits>
```

| 工具                   | 逻辑          | 含义                            |
| ---------------------- | ------------- | ------------------------------- |
| **`std::conjunction`** | **AND（与）** | 所有条件都为 true → 最终 true   |
| **`std::disjunction`** | **OR（或）**  | 任意一个条件为 true → 最终 true |
| **`std::negation`**    | **NOT（非）** | 条件取反                        |

**`conjunction` —— 逻辑与（AND）**

**所有条件都满足才为真**，支持**短路求值**（遇到 false 立即停止）。

```c++
template <typename T>
using is_int_and_float = conjunction<is_same<T, int>, is_same<T, float>>;// false
```

**`disjunction` —— 逻辑或（OR）**

**任意一个条件满足就为真**，支持**短路求值**（遇到 true 立即停止）。

```c++
template <typename T>
using is_int_or_float = disjunction<is_same<T, int>, is_same<T, float>>; // int → true float → true
```

**`negation` —— 逻辑非（NOT）**

**对结果取反**。

```c++
template <typename T>
using is_not_int = negation<is_same<T, int>>;
```

## 核心使用场景

**短路求值（Short-Circuit）**

这是它们比直接用 `_v && ...` 更强大的地方：

- `conjunction`：遇到第一个 `false` 就**停止实例化后续模板**
- `disjunction`：遇到第一个 `true` 就**停止实例化后续模板**

可以避免不必要的编译期计算，甚至避免编译错误。

```c++
conjunction<is_pointer<T>, is_const_v<remove_pointer_t<T>>>// 如果 T 不是指针，就不会执行 is_const_v
```

**`enable_if` 类型约束**

```c++
template <typename T>// T 必须是整数且无符号
enable_if_t<
    conjunction_v<is_integral<T>, is_unsigned<T>>
> func(T) { }
template <typename T>// T 是 int 或 float 或 double
constexpr bool is_numeric_v =
    disjunction_v<
        is_same<T, int>,
        is_same<T, float>,
        is_same<T, double>
    >;
template <typename T>// T 不是 void
constexpr bool is_not_void_v = negation_v<is_same<T, void>>;
```

**后缀 `_v` 简化版**

C++17 提供了 `_v` 变量模板，更简洁：

```c++
conjunction_v<...>   // 等价于 conjunction<...>::value
disjunction_v<...>
negation_v<...>
```

# `std::uncaught_exceptions`

`std::uncaught_exceptions` 是 C++17 引入的**异常处理工具**，用于**获取当前线程中 “已抛出但尚未捕获” 的异常数量**。

它**完全替代了 C++11 的 `std::uncaught_exception`（不带 s）**，解决了旧版在**析构函数中检测是否因异常退出**时的重大缺陷。

核心价值：**让析构函数能安全、准确地判断：当前是否正在因异常而退出作用域**，从而实现安全的**事务型对象（Scope Guard）**。

## 背景

C++11 的 `std::uncaught_exception()` 只能返回 **bool**（是否有异常），**无法处理嵌套场景**：

- 如果在**析构函数中又抛出异常**，旧版会直接误判，导致逻辑错误。

因此 C++17 新增了**带复数 s**的版本：**`std::uncaught_exceptions()`**，返回 **int** 计数。

## 核心语法与基础使用

**头文件**

```c++
#include <exception>
```

**区别**

- **C++11 废弃**：`bool std::uncaught_exception()`
- **C++17 推荐**：`int std::uncaught_exceptions()` **返回当前未捕获的异常个数。**

**Scope Guard（作用域守护）**

这是它唯一的核心用途：

**判断对象是 “正常离开作用域”，还是 “因异常离开作用域”**，从而决定：

- 正常 → **提交（commit）**
- 异常 → **回滚（rollback）**

```c++
struct ScopeGuard {
    const int exceptions_on_enter = std::uncaught_exceptions();// 记录构造时的异常数量
    ~ScopeGuard() {// 如果离开时异常变多 → 正在因异常销毁
        if (std::uncaught_exceptions() > exceptions_on_enter) {// 发生了异常 → 回滚、清理、失败处理
        } else {// 正常退出 → 提交
        }
    }
};
```

**为什么必须用 `uncaught_exceptions()`（带 s）**

- 旧版 `uncaught_exception()`：只要有异常就返回 true，嵌套析构中会误判。
- 新版 `uncaught_exceptions()`：用计数差判断，100% 准确，无论嵌套多少层。

```c++
struct Guard {
    const int count = std::uncaught_exceptions();
    ~Guard() {
        if (std::uncaught_exceptions() > count) { std::cout << "因异常退出 → 回滚\n"; } 
        else { std::cout << "正常退出 → 提交\n"; }
    }
};
void test() {
    Guard g;
    throw 1; // 抛出异常
}
try { test(); } catch (...) {}
```

# `std::is_final`

`std::is_final` 是 C++17 引入的**类型特性（type trait）**，用于**在编译期判断一个类是否被声明为 `final`**（禁止被继承）。

核心价值：**编译期检测类是否禁止继承**，用于元编程、模板约束、类型校验。

## 核心语法

头文件：`<type_traits>`

功能：判断类型 `T` 是否是 **`final` 类 / 结构体 **

返回：**编译期常量 `bool`**

- `std::is_final_v<T>` → `true` / `false`

```c++
// 普通类
class A {};
// final 类（不能被继承）
class B final {};
// 编译期判断
constexpr bool a_is_final = std::is_final_v<A>; // false
constexpr bool b_is_final = std::is_final_v<B>; // true
//可用于：类、结构体、union
struct S final {};
union U final {};
std::is_final_v<S>; // true
std::is_final_v<U>; // true
```

**重要规则**

1. 只对类类型有效`int`、`double`、指针、引用 → 都是 `false`
2. 编译期常量可用于 `constexpr`、`if constexpr`、模板参数
3. 不会忽略 cv 限定符
   - `std::is_final_v<const B>` → **`false`**
   - 要正确判断必须用 `std::remove_cv_t`

```c++
std::is_final_v<std::remove_cv_t<const B>>; // true
```

## 核心使用场景

**静态断言（static_assert）**

确保某个类一定是 / 不是 final

```c++
static_assert(std::is_final_v<B>, "B 必须是 final");
```

**模板约束（if constexpr /enable_if）**

```c++
template <typename T>
void test() {
    if constexpr (std::is_final_v<T>) { } // T 是 final
        else { } // 可以被继承
}
```

**SFINAE 重载**

```c++
template <typename T>
std::enable_if_t<std::is_final_v<T>> func() {}
```

# `std::launder`

`std::launder` 是 C++17 新增的**内存模型工具函数**，用于 **解决 “在原有对象内存上创建新对象后，正确访问新对象”** 的问题。

核心价值：**修复 “内存重用、placement new、联合体、const 成员” 场景下的未定义行为，让指针指向新对象合法化**。

当你**在一块内存上，用 new 创建了一个新对象**（覆盖了旧对象），

## 核心语法与基础使用

**原来的指针不能直接用了**，必须用 `std::launder` “清洗” 一下，才能安全访问新对象。

C++ 有严格的对象生存期规则：

- 一块内存同一时间**只能有一个活跃对象**
- 如果你用 **placement new** 在旧内存上创建了**新对象**
- **旧指针 / 引用不会自动指向新对象**
- 直接使用会触发**未定义行为（UB）**

`std::launder` 的作用就是：**告诉编译器：这里已经是新对象了，请用这个指针访问它。**

```c++
#include <new>
T* new_ptr = std::launder(旧指针);
```

**作用**：返回一个**指向新对象**的合法指针。

## 核心使用场景

**包含 const / 引用成员的对象**

如果类里有 **const 成员** 或 **引用成员**，

placement new 后**必须 launder**，否则直接 UB。

```c++
struct X { const int a; };
X x{10};
new (&x) X{20};  // 覆盖创建新对象
std::cout << x.a;// ❌ 错误：直接用 x 访问新的 const 对象
X* p = std::launder(&x);// 正确：用 launder “清洗”指针
std::cout << p->a;
```

**联合体中切换活跃成员**

在 union 里切换对象，必须 launder。

```c++
union U { int a; std::string b; };
U u = {0};
new (&u.b) std::string{"hello"};
std::cout << u.b;// 错误
auto* p = std::launder(&u.b);// 正确
```

**通过旧指针访问 placement new 后的新对象**

```c++
int* p = new int{1};
new (p) int{2};
int val = *std::launder(p);// 安全写法
```
