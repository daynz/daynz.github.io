# 三、编译期特性

这类特性将计算 / 检查逻辑提前到编译阶段，减少运行期开销、提前暴露错误：

## `constexpr` 与字面类型

### `constexpre`

`constexpr`的核心目标是：**强制表达式在编译期求值**，让 “常量计算” 从运行时提前到编译期

**基本定义与核心规则**

`constexpr` 修饰的变量 / 函数满足：

- **变量**：编译期初始化，值不可变，可用于所有编译期常量场景（数组长度、模板参数、枚举值等）；
- **函数**：编译期可调用，返回值可作为编译期常量（需满足 “纯 `constexpr` 条件”）；
- C++11 对`constexpr`函数限制严格（单返回语句），C++14 放宽为 “可包含多条语句、局部变量”。

| 特性       | `constexpr`                                  | `const`                      |
| ---------- | -------------------------------------------- | ---------------------------- |
| 核心语义   | 编译期常量 / 编译期可计算                    | 运行时常量（不可修改）       |
| 变量初始化 | 必须编译期表达式初始化                       | 可编译期 / 运行期初始化      |
| 函数       | 支持（编译期可调用）                         | 不支持（仅修饰成员函数）     |
| 类构造函数 | 支持（编译期创建对象）                       | 不支持                       |
| 适用场景   | 编译期常量（数组长度、模板参数）、编译期计算 | 运行时常量（不可修改的变量） |

### 字面类型

「字面类型」是能用于`constexpr`上下文的类型，即：**该类型的对象可在编译期创建、初始化、计算**。C++11 定义了以下几类字面类型：

| 类型类别                  | 示例                             | 核心条件                                                     |
| ------------------------- | -------------------------------- | ------------------------------------------------------------ |
| 基本类型                  | `int、double、char、bool`        | 所有基本类型都是字面类型                                     |
| 指针 / 引用类型           | `int*、const char&`              | 指针指向编译期可见的内存（如全局变量、字符串字面量），引用绑定到字面类型对象 |
| 聚合类型（数组 / 结构体） | `int[5]、struct {int x; int y;}` | 所有成员都是字面类型，无虚函数、无虚基类                     |
| 带 `constexpr` 构造的类   | 上文的 Point 类                  | 有 `constexpr` 构造函数，所有非静态成员都是字面类型，无虚函数 |

**字面类型的判定条件（C++11）**

一个类型是字面类型，需满足：

1. 有**平凡的析构函数**（编译器自动生成，或`= default`）；
2. 满足以下条件之一：
   - 是标量类型（基本类型、指针、引用、枚举）；
   - 是聚合类型（数组、无自定义构造 / 析构 / 赋值、无虚函数的结构体 / 类）；
   - 是带`constexpr`构造函数的类，且所有非静态数据成员 / 基类都是字面类型。

## 编译期断言`static_assert`（基于 Boost 库）

`static_assert` 是 C++11 引入的**编译期断言机制**，核心作用是在**编译阶段**检查常量表达式的真假，若条件不满足则直接终止编译并输出自定义错误信息。它解决了传统运行时断言（`assert`）的局限性 ——`assert` 仅在运行时触发，且 Release 模式下可能被禁用，而`static_assert` 能在编译期暴露问题，更早发现错误。

**传统断言（assert）核心问题**：

1. `assert` 是**运行时断言**，编译阶段无法发现错误；
2. Release 模式下`NDEBUG`宏会禁用`assert`，导致错误被隐藏；
3. 仅能检查运行时表达式，无法检查编译期常量（如模板参数、数组长度）。

**`static_assert` 核心语法与规则**

```c++
// 语法1：带自定义错误信息（推荐）
static_assert(常量表达式, "错误提示字符串");

// 语法2：无错误信息（C++17支持，不推荐，信息不明确）
static_assert(常量表达式);
```

**核心规则**：

1. 第一个参数必须是**编译期可计算的常量表达式**（如`constexpr`变量、字面量、模板参数）；
2. 若表达式为`true`，编译正常通过；若为`false`，编译终止并输出错误信息；
3. `static_assert` 可出现在**全局作用域、命名空间、类、函数**等任意位置（无作用域限制）；
4. 错误信息字符串是编译期常量（C++11 要求字符串字面量，C++17 放宽为任意常量表达式）。

**应用**

- **检查模板参数**（最常用）`static_assert` 是模板编程的 “安全卫士”，可强制模板参数满足特定条件

```c++
#include <type_traits> // 类型特性判断（如is_integral）
using namespace std;
// 模板：仅允许整数类型作为参数
template <typename T>
T add(T a, T b) {
    // 检查T是否为整数类型（编译期）
    static_assert(is_integral<T>::value, "add函数仅支持整数类型！");
    return a + b;
}
```

- **检查编译环境 / 编译器特性**

```c++
// 检查C++标准版本（C++11及以上才支持static_assert）
static_assert(__cplusplus >= 201103L, "请使用C++11及以上标准编译！");
// 检查编译器类型（GCC）
#ifdef __GNUC__
static_assert(__GNUC__ >= 4, "GCC版本需≥4.0！");
#endif
// 检查平台（64位）
static_assert(sizeof(void*) == 8, "仅支持64位平台！");
```

- **检查类 / 类型特性**

```c++
// 检查类型是否为POD类型
struct PODType { int a; double b; };
struct NonPODType { int a; virtual void func() {} };
static_assert(is_pod<PODType>::value, "PODType必须是POD类型！"); // 合法
// static_assert(is_pod<NonPODType>::value, "NonPODType必须是POD类型！"); // 编译报错
```

- **与 `constexpr` 结合（编译期计算后断言）**

```c++
template <typename T>
class MyClass {
public:
    MyClass() {
        // 禁止T为float类型
        static_assert(!is_same<T, float>::value, "MyClass不支持float类型！");
    }
};
```

| 特性     | static_assert（静态断言）       | assert（运行时断言）          |
| -------- | ------------------------------- | ----------------------------- |
| 检查时机 | 编译期                          | 运行期                        |
| 检查条件 | 仅支持编译期常量表达式          | 支持运行时表达式              |
| 生效范围 | 所有编译模式（Debug/Release）   | 仅 Debug 模式（Release 禁用） |
| 错误处理 | 终止编译，输出自定义信息        | 触发后终止程序，输出默认信息  |
| 作用域   | 全局 / 命名空间 / 类 / 函数均可 | 仅函数内                      |
| 性能影响 | 无（编译期处理）                | Debug 模式有轻微开销          |

**进阶：C++17 扩展**

C++17 对`static_assert`做了小幅扩展：

- 允许省略错误信息字符串（仅保留常量表达式）

```c++
static_assert(sizeof(int) == 4); // C++17合法，C++11报错
```

- 错误信息支持非字符串字面量的常量表达式（如`constexpr`字符串）

```c++
constexpr const char* err_msg = "int应为4字节";
static_assert(sizeof(int) == 4, err_msg); // C++17合法
```

## `alignof` 与 `alignas`（编译期确定内存对齐）

`alignof`（对齐值查询）和 `alignas`（对齐值指定）是 C++11 引入的关键字，用于**编译期控制和查询内存对齐**。内存对齐是计算机硬件的底层要求（如 CPU 读取数据时按固定字节数对齐更高效）。

C++11 前只能通过编译器扩展（如 GCC 的`__attribute__((aligned))`、MSVC 的`__declspec(align)`）控制对齐，而`alignof` / `alignas`是标准化的解决方案，跨平台更通用。

| 功能       | C++11 标准语法 | GCC 扩展                      | MSVC 扩展              |
| ---------- | -------------- | ----------------------------- | ---------------------- |
| 查询对齐值 | `alignof(T)`   | `__alignof__(T)`              | `__alignof(T)`         |
| 指定对齐值 | `alignas(n)`   | `__attribute__((aligned(n)))` | `__declspec(align(n))` |

### 内存对齐的基础概念

先理解 “内存对齐” 的核心：

- **对齐值（Alignment）**：一个类型 / 变量的对齐值是其内存地址必须是该值的整数倍（如`int`的对齐值通常为 4，即`int`变量的地址必须是 4 的倍数）；
- **自然对齐**：编译器默认的对齐规则（如基本类型的对齐值等于其大小，`char=1`、`int=4`、`double=8`）；
- **过度对齐（Over-alignment）**：手动指定比自然对齐更大的对齐值（如将`int`对齐到 16 字节），用于硬件加速（如 SIMD 指令）、内存映射等场景。

### `alignof`（查询对齐值）

```c++
alignof(类型/表达式)
```

- `alignof` 接收**类型**（如`int`、`struct A`）或**表达式**（如变量名），返回该类型 / 变量的**最小对齐值**（编译期常量，类型为`std::size_t`）；
- 结果是编译期可计算的常量，可用于`constexpr`、`static_assert`、模板参数等编译期场景；
- 对于数组，`alignof(数组类型)` 等于数组元素类型的对齐值；
- 对于引用，`alignof(引用类型)` 等于被引用类型的对齐值。

```c++
// 自定义结构体（自然对齐：按最大成员的对齐值对齐）
struct MyStruct {
    char c;    // 对齐值1
    int i;     // 对齐值4
    double d;  // 对齐值8
}; // 整体对齐值为8（最大成员的对齐值）
int main() {
    // 1. 查询基本类型的对齐值
    cout << "char对齐值：" << alignof(char) << endl;     // 输出：1
    cout << "int对齐值：" << alignof(int) << endl;       // 输出：4（32/64位通常为4）
    cout << "double对齐值：" << alignof(double) << endl; // 输出：8
    // 2. 查询自定义类型的对齐值
    cout << "MyStruct对齐值：" << alignof(MyStruct) << endl; // 输出：8
    // 3. 查询数组/引用的对齐值
    int arr[5];
    cout << "int数组对齐值：" << alignof(arr) << endl; // 输出：4（等于int的对齐值）
    int& ref = arr[0];
    cout << "int引用对齐值：" << alignof(ref) << endl; // 输出：4
    // 4. 结合static_assert检查对齐
    static_assert(alignof(int) == 4, "int的对齐值应为4！");
    return 0;
}
```

**`alignof` vs `sizeof`（核心区别）**

- `sizeof`：返回类型 / 变量占用的**总字节数**（包含填充字节）；
- `alignof`：返回类型 / 变量的**最小对齐值**（地址需是该值的整数倍）。

```c++
struct Test {
    char c; // 1字节
    int i;  // 4字节（编译器会在c后填充3字节，保证i对齐到4）
};
cout << "sizeof(Test)：" << sizeof(Test) << endl; // 输出：8（1+3填充+4）
cout << "alignof(Test)：" << alignof(Test) << endl; // 输出：4（最大成员int的对齐值）
```

### `alignas`（指定对齐值）

```c++
// 语法1：修饰类型/变量（指定对齐值）
alignas(对齐值) 类型 变量名;
alignas(类型) 类型 变量名; // 等价于alignas(alignof(类型))
// 语法2：修饰结构体/类（指定整体对齐值）
struct alignas(对齐值) 结构体名 { ... };
```

- `alignas` 的参数必须是**2 的幂次**（如 1、2、4、8、16，否则编译报错）；
- 若同时指定多个`alignas`，编译器取**最大的对齐值**；
- 不能指定比编译器默认对齐值更小的对齐值（仅能增大或等于）；
- 可用于变量、结构体 / 类、数组、枚举等，不可用于函数 / 参数。

**指定变量的对齐值**

```c++
// 默认对齐：int对齐到4字节
int a;
cout << "a的对齐值：" << alignof(a) << endl; // 4
// 手动指定：将b对齐到16字节（过度对齐）
alignas(16) int b;
cout << "b的对齐值：" << alignof(b) << endl; // 16
// 用类型指定对齐值（等价于alignof(double)=8）
alignas(double) int c;
cout << "c的对齐值：" << alignof(c) << endl; // 8
```

**指定结构体的对齐值**

```c++
// 默认对齐：int对齐到4字节
int a;
cout << "a的对齐值：" << alignof(a) << endl; // 4

// 手动指定：将b对齐到16字节（过度对齐）
alignas(16) int b;
cout << "b的对齐值：" << alignof(b) << endl; // 16

// 用类型指定对齐值（等价于alignof(double)=8）
alignas(double) int c;
cout << "c的对齐值：" << alignof(c) << endl; // 8
```

**指定数组的对齐值**

```c++
// 数组整体对齐到32字节（每个元素int对齐到4，数组整体对齐到32）
alignas(32) int arr[10];
cout << "arr的对齐值：" << alignof(arr) << endl; // 32
```

**进阶场景：硬件加速（SIMD）**

```c++
// AVX指令要求数据对齐到32字节
alignas(32) float data[8]; // 8个float=32字节，对齐到32字节
// 使用AVX指令加载数据（需对齐，否则崩溃）
__m256 vec = _mm256_load_ps(data);
```

**错误示例（避坑）**

```c++
// 错误1：对齐值不是2的幂次（3不是）
alignas(3) int a; // 编译报错
// 错误2：指定比默认更小的对齐值（int默认4，2更小）
alignas(2) int b; // 编译报错
// 错误3：重复指定但取最大值（合法，无报错）
alignas(4) alignas(8) int c; // 最终对齐到8
```

### `std::aligned_storage`

`std::aligned_storage` 是 C++11 提供的模板，结合`alignof`/`alignas`实现 “指定对齐的内存缓冲区”，常用于自定义内存池、容器等场景。

```c++
#include <type_traits> // std::aligned_storage
// 定义一个对齐到16字节、大小为32的内存缓冲区
using AlignedBuffer = std::aligned_storage<32, 16>::type;
int main() {
    AlignedBuffer buf;
    cout << "buf大小：" << sizeof(buf) << endl;       // 32
    cout << "buf对齐值：" << alignof(buf) << endl;     // 16
    // 在缓冲区上构造int（放置new）
    int* p = new (&buf) int(100);
    cout << *p << endl; // 100
    return 0;
}
```

## `noexcept` 说明符

`noexcept` 说明符是 C++11 引入的特性，用于**显式声明函数是否会抛出异常**，核心作用是给编译器提供异常行为的提示，帮助编译器优化代码（如移动构造 / 赋值的优化），同时明确函数的异常安全契约。

**核心作用**

- 明确异常契约，提升代码可读性
- 编译器优化
  - **省略异常处理代码**：`noexcept` 函数内部无需生成栈展开（stack unwinding）的异常处理逻辑，执行效率更高；
  - **容器优先使用移动操作**：`std::vector`/`std::string` 等容器在扩容、元素移动时，若元素的移动构造 / 赋值函数标记为 `noexcept`，容器会优先选择移动而非拷贝；若未标记，容器会退化为拷贝（避免移动过程中抛异常导致数据丢失）。
- 违反 `noexcept` 契约的后果
  - 若标记为 `noexcept` 的函数实际抛出了异常，C++ 标准规定会直接调用 `std::terminate()` 终止程序（而非栈展开），因此**必须确保 `noexcept` 函数内不会抛异常**。

**`noexcept` 说明符的使用场景**

- 移动构造 / 移动赋值函数：让容器 / 算法优先使用移动，避免退化为拷贝
- 析构函数：C++11 后析构函数默认隐式 `noexcept (true)`，无需手动写（除非显式声明 noexcept (false)）
- 简单访问器（getter/setter）
- 资源释放函数：释放资源不能抛异常，否则会导致内存泄漏 / 资源泄漏

##  `noexcept` 运算符

`noexcept` 运算符是**编译期表达式**，用于判断 “某个表达式是否会抛出异常”，返回布尔常量（`true`/`false`），常和模板、条件编译结合使用。

```c++
noexcept(表达式)
```

- 结果：若表达式在编译期确定不会抛异常，返回 `true`；否则返回 `false`；
- 特性：**不会执行表达式**，仅做编译期类型检查。

**核心用法**

- 动态标记函数的 `noexcept` 说明符，可让函数的异常契约 “跟随其他函数”

  - ```c++
    // 模板函数：异常契约跟随 Func 的调用结果
    template <typename Func, typename... Args>
    auto Wrapper(Func&& func, Args&&... args) 
        noexcept(noexcept(func(std::forward<Args>(args)...))) // 动态判断
    -> decltype(func(std::forward<Args>(args)...)) {
        return func(std::forward<Args>(args)...);
    }
    
    // 测试函数1：不抛异常
    void Func1() noexcept {}
    // 测试函数2：可能抛异常
    void Func2() {}
    
    int main() {
        // 编译期判断：Wrapper(Func1) 是 noexcept(true)
        static_assert(noexcept(Wrapper(Func1)), "Wrapper(Func1) should be noexcept");
        // 编译期判断：Wrapper(Func2) 是 noexcept(false)
        static_assert(!noexcept(Wrapper(Func2)), "Wrapper(Func2) should not be noexcept");
        return 0;
    }
    ```

- 编译期条件分支（结合 SFINAE）：在模板中根据函数是否 `noexcept `做不同的逻辑处理

  - ```c++
    // 重载1：处理 noexcept 的函数
    template <typename T>
    std::enable_if_t<noexcept(T{}) && std::is_default_constructible_v<T>, void>
    CreateObject() {
        // 无异常风险，直接构造
        T obj;
        std::cout << "创建对象（noexcept 版本）" << std::endl;
    }
    // 重载2：处理可能抛异常的函数
    template <typename T>
    std::enable_if_t<!noexcept(T{}) && std::is_default_constructible_v<T>, void>
    CreateObject() {
        // 有异常风险，加 try-catch
        try {
            T obj;
            std::cout << "创建对象（带异常处理版本）" << std::endl;
        } catch (...) {
            std::cerr << "创建对象失败" << std::endl;
        }
    }
    // 测试类1：默认构造 noexcept
    class A {
    public:
        A() noexcept {}
    };
    // 测试类2：默认构造可能抛异常
    class B {
    public:
        B() { throw std::runtime_error("error"); }
    };
    int main() {
        CreateObject<A>(); // 调用 noexcept 版本
        CreateObject<B>(); // 调用带异常处理版本
        return 0;
    }
    ```

- 判断标准库函数的异常行为

  - ```c++
    // 判断 std::vector<int>::push_back 是否 noexcept（取决于元素类型）
    std::vector<int> vec;
    static_assert(noexcept(vec.push_back(10)), "push_back 是 noexcept"); // 成立
    // 判断 std::vector<int>::resize 是否 noexcept（可能抛内存异常，不成立）
    static_assert(!noexcept(vec.resize(100)), "resize 不是 noexcept");
    ```

## 属性

C++ 属性是 C++11 引入的标准化语法，用于**向编译器传递额外的语义信息**（而非执行逻辑），核心目标是：

- 指导编译器优化（如 `[[likely]]`/`[[unlikely]]`）；
- 标记代码特性（如 `[[nodiscard]]` 强制检查返回值）；
- 抑制编译器警告（如 `[[maybe_unused]]`）；
- 适配平台 / 编译器特性（如 `[[gnu::aligned(16)]]`）。
