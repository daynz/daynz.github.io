# C++ 对象模型

[toc]

## 引言

C++ 对象模型是编译器为实现**封装、继承、多态**等核心语言特性而设计的底层内存布局与运行时机制。其核心目标是在语言灵活性与运行时性能、内存效率之间取得平衡。深入理解对象模型，对编写高性能、低内存占用且行为正确的 C++ 代码至关重要。

## 基础对象布局

### 非静态数据成员的排列

- 成员按**声明顺序**依次存储在对象内存中。
- 第一个成员的偏移量（offset）为 0。

### 内存对齐

内存对齐是提升硬件访问效率的关键机制，多数 CPU 要求数据地址必须为其大小的整数倍（如 `int` 需 4 字节对齐）。

- **成员对齐**：每个成员的偏移量必须是其自身对齐要求（通常等于其大小）的整数倍。
- **整体对齐**：类的总大小必须是其**最严格对齐成员的对齐值**（即具有最大 `alignof` 值的成员）的整数倍。

```cpp
class Simple {
    char a;   // 偏移0
    int b;    // 偏移4（因char占1字节，需填充3字节以满足int的4字节对齐）
    short c;  // 偏移8
};
// sizeof(Simple) = 12（最大成员为int，其对齐值为4，故总大小需为4的倍数，8+2=10后填充2字节）

class AlignExample {
    char a;       // 偏移0
    long double b; // 偏移16（若alignof(long double)=16，则填充15字节）
};

```

### 空类

空类（无任何非静态数据成员）的大小为**1 字节**，以确保不同对象拥有不同的内存地址。

#### 空基类优化 EBCO

当空类作为基类时，编译器可优化掉其 1 字节开销，使派生类大小仅包含自身成员。C++11 起标准明确允许此优化，C++17 还引入 `[[no_unique_address]]` 属性，用于优化空类成员的内存占用。

```cpp
class Empty {}; // sizeof(Empty) = 1

class NoOptimization {
    Empty e;
    int x;
}; // sizeof(NoOptimization) = 8（1字节Empty + 3字节填充 + 4字节int）

class WithEBCO : public Empty { // 空基类优化
    int x;
}; // sizeof(WithEBCO) = 4（Empty的1字节被优化）

class WithAttribute {
    [[no_unique_address]] Empty e; // C++17属性优化空成员
    int x;
}; // sizeof(WithAttribute) = 4
```

### 构造函数的异常安全与对象模型

当构造函数抛出异常时，对象模型会执行**部分构造回滚**：

- 已构造完毕的**基类子对象**和**成员子对象**按构造相反顺序自动析构。
- 当前对象的**内存会被释放**（若通过 `new` 分配）。
- **vptr 回滚**：在进入构造函数体前，vptr 已设置为当前类的虚表。异常抛出后，不会再次修改 vptr（对象已视为未完全构造），但析构已构造的子对象时，虚函数调用将绑定到当前类版本。

```cpp
class Member {
public:
    Member() { cout << "Member ctor\n"; }
    ~Member() { cout << "Member dtor\n"; }
};

class Base {
public:
    Base() { cout << "Base ctor\n"; }
    ~Base() { cout << "Base dtor\n"; }
};

class Derived : public Base {
    Member m;
public:
    Derived() {
        cout << "Derived ctor start\n";
        throw 1; // 抛出异常
    }
    ~Derived() { cout << "Derived dtor\n"; }
};

int main() {
    try {
        Derived d;
    } catch(...) {}
    // 输出：
    // Base ctor
    // Member ctor
    // Derived ctor start
    // Member dtor   （成员析构）
    // Base dtor     （基类析构）
    // 注意：Derived析构函数未调用
}
```

## 静态成员的处理

### 静态数据成员

- **存储位置**：全局/静态存储区（程序生命周期内持续存在）。
- **访问方式**：通过类名（`Class::static_member`）或对象（`obj.static_member`）访问，二者本质相同。
- **`sizeof` 影响**：不包含在类对象的大小中。

### 静态成员函数

- 无 `this` 指针，无法直接访问非静态成员（非静态成员依赖对象实例）。
- 存储于代码段，与普通函数无异，仅作用域限制在类内。

### 成员指针底层模型

成员指针是 C++ 中特殊的指针类型，其底层实现与普通指针差异显著。

#### 数据成员指针

存储的是**成员在对象中的偏移量**（而非绝对地址），偏移量为 `size_t` 类型。若类含虚函数，第一个数据成员的偏移量为 `vptr` 大小（如 64 位系统下 8 字节）。

**注意**：获取偏移量的常见技巧 `(size_t)&(((MyClass*)nullptr)->*data_ptr)` 属于**未定义行为**（解引用空指针），虽多数实现可行，但不应在生产代码中使用。标准布局类型可使用 `offsetof` 宏。

```cpp
class MyClass {
public:
    int data; // 若类含vptr，偏移量为8；否则为0
};
int main() {
    int MyClass::*data_ptr = &MyClass::data;
    // 以下为依赖实现的技巧，非标准行为
    cout << "Offset of data: " << reinterpret_cast<size_t>(&(((MyClass*)nullptr)->*data_ptr)) << endl;
    return 0;
}
```

#### 成员函数指针

成员函数指针的大小和结构因**继承关系**而异（以 Itanium ABI 64 位为例）：

- **单继承非虚函数**：通常存储函数地址，大小 8 字节。
- **多继承/虚继承非虚函数**：需存储函数地址 + `this` 指针调整量，大小 16 字节。
- **虚函数**：存储虚表索引（而非地址），大小 8 或 16 字节。

```cpp
class MyClass {
public:
    void func() {}
    virtual void virtual_func() {}
};

int main() {
    void (MyClass::*func_ptr)() = &MyClass::func; // 成员函数指针
    MyClass obj;
    (obj.*func_ptr)(); // 调用成员函数

    // 打印大小（依赖实现）
    cout << "Size of member function pointer: " << sizeof(func_ptr) << endl;
    return 0;
}
```

**进阶补充：`.*` 与 `->*` 的底层调用细节**  

成员指针的解引用操作并非简单的 `call [address]`。在汇编层面：

- 对于**非虚函数**，若为单继承，指令类似于 `lea rax, [obj+offset]` 计算 this，然后 `call func_addr`。
- 对于**多继承**，编译器会生成调整 this 的代码，通常在调用前利用成员函数指针中存储的 `this_adjustment` 字段：`add rdi, this_adjustment` 后再 `call`。
- 对于**虚函数**，成员指针存储的是虚表索引。调用时伪代码为：`mov rax, [rdi]` (取 vptr)，`call [rax + index*8]`。这比直接调用虚函数多了一层间接，因为索引是在运行时从成员指针中加载的。

## 虚函数与动态绑定机制

### 虚函数的核心语义

虚函数是 C++ 实现**运行时多态（动态绑定）**的基石，其核心语义是：通过基类指针或引用调用虚函数时，实际执行的函数由指针/引用所指向对象的**实际类型**决定，而非指针/引用的静态类型。

#### 虚函数默认参数的静态绑定陷阱

虚函数的**默认参数是静态绑定**的（编译期确定），仅由指针/引用的静态类型决定，与动态绑定的函数体无关，是高频易错点。

```cpp
class Base {
public:
    virtual void func(int x = 10) { // 基类默认参数x=10
        cout << "Base::func, x = " << x << endl;
    }
};

class Derived : public Base {
public:
    void func(int x = 20) override { // 派生类默认参数x=20
        cout << "Derived::func, x = " << x << endl;
    }
};

int main() {
    Base* ptr = new Derived();
    ptr->func(); // 输出：Derived::func, x = 10
    // 函数体动态绑定到Derived::func，但默认参数静态绑定到Base的x=10
    delete ptr;
    return 0;
}
```

#### 声明与重写规范

- **虚函数声明**：在基类中使用 `virtual` 关键字声明成员函数（仅需在声明处加 `virtual`，定义处可省略）。
- **重写（Override）**：派生类中声明与基类虚函数**签名完全一致**（函数名、参数列表、**const/volatile 属性**、引用限定符）的函数，自动成为虚函数（建议显式加 `override` 关键字，由编译器检查重写正确性）。
- **最终（Final）**：使用 `final` 关键字可禁止虚函数被进一步重写，或禁止类被继承。

**进阶补充：const 与 volatile 对虚函数的影响**

函数签名包含 `const` 或 `volatile` 限定符。`void func() const` 与 `void func()` 是**两个不同的虚函数**，在虚表中占据不同的槽位。

```cpp
class Base {
public:
virtual void f() const { cout << "Base::f const\n"; }
virtual void f()       { cout << "Base::f non-const\n"; }
};
```
对于 `volatile` 对象，若类定义了 `volatile` 版本的虚函数，调用时会绑定到该版本；否则编译报错（不会绑定到非 volatile 版本，因为 this 指针 cv 限定不匹配）。这确保了即使在多线程或内存映射 I/O 场景下，虚函数调用的语义仍然一致。

##### 纯虚函数 & 抽象类底层

- **纯虚函数**：在基类中声明为 `= 0` 的虚函数，其在虚表中存储的是 `&__cxa_pure_virtual`（运行时调用会直接崩溃）。
- **抽象类**：包含纯虚函数的类，无法实例化（因虚表中存在未实现的纯虚函数入口）。
- **陷阱**：在基类构造函数或析构函数中调用纯虚函数是未定义行为（通常崩溃），因为此时 vptr 指向基类虚表，而纯虚函数槽位为 `__cxa_pure_virtual`。

```cpp
class Abstract {
public:
    virtual void pure_virtual() = 0; // 纯虚函数
    // 虚表中pure_virtual位置存储&__cxa_pure_virtual
};
// Abstract a; // 编译错误：无法实例化抽象类

class Concrete : public Abstract {
public:
    void pure_virtual() override { /* 实现纯虚函数 */ }
};
```

##### 协变返回类型

派生类重写虚函数时，返回值类型可改为**基类返回值类型的派生类指针/引用**（仅适用于指针/引用），此为合法的重写例外，称为“协变返回类型”。

```cpp
class BaseReturn {};
class DerivedReturn : public BaseReturn {}; // 派生类返回类型

class Base {
public:
    virtual BaseReturn* func() { return new BaseReturn(); }
};

class Derived : public Base {
public:
    DerivedReturn* func() override { // 协变返回：返回DerivedReturn*
        return new DerivedReturn();
    }
};
```

#### 静态绑定与动态绑定

- **静态绑定**：非虚函数的调用在**编译期**确定，根据指针/引用的静态类型选择函数。
- **动态绑定**：虚函数的调用在**运行期**确定，根据对象的实际类型选择函数。

#### 虚析构函数的必要性

当通过基类指针删除派生类对象时，若基类析构函数非虚，则仅调用基类析构函数，导致派生类资源泄漏。因此，若类可能被继承，其析构函数应声明为虚函数。

```cpp
class Base {
public:
    virtual ~Base() = default; // 虚析构函数
};
class Derived : public Base { /* 持有资源 */ };

Base* ptr = new Derived();
delete ptr; // 正确：先调用Derived::~Derived()，再调用Base::~Base()
```

### 对象切片（Slicing）——多态第一大坑

多态仅对**指针/引用**生效；若通过**值拷贝**将派生类对象赋值给基类对象，会发生“切片”：

1. 派生类成员被截断，仅保留基类子对象。
2. vptr 被重置为基类的虚表，无法触发多态。

```cpp
class Base {
public:
    virtual void func() { cout << "Base::func" << endl; }
    int x = 1;
};

class Derived : public Base {
public:
    void func() override { cout << "Derived::func" << endl; }
    int y = 2;
};

void slice_example(Base b) { // 值传递，发生切片
    b.func(); // 调用Base::func（vptr被重置）
    cout << b.x << endl; // 仅输出x，y被截断
}

int main() {
    Derived d;
    slice_example(d); // 切片发生
    return 0;
}
```

### 虚表的结构与生成

虚表（Virtual Table，简称 vtable）是编译器为每个**包含虚函数的类**生成的一个**全局只读函数指针数组**，用于存储该类所有虚函数的地址。

#### Itanium ABI 下的虚表布局

Itanium ABI（GCC/Clang 采用）的虚表结构如下（从低地址到高地址）：

| 偏移（相对于 vptr） | 内容                 | 说明                                                         |
| ------------------- | -------------------- | ------------------------------------------------------------ |
| -2                  | 虚基类偏移量数组指针 | 仅当类有虚基类时存在，存储虚基类子对象相对于 vptr 的偏移量   |
| -1                  | `type_info*`         | 指向类的 RTTI（运行时类型信息）对象，用于 `typeid` 和 `dynamic_cast` |
| 0                   | 第一个虚函数指针     | 指向类中第一个声明的虚函数（或重写的基类虚函数）             |
| 1                   | 第二个虚函数指针     | 依此类推                                                     |
| ...                 | ...                  | ...                                                          |

**关键说明**：

- 虚指针（vptr）指向虚表的**索引 0 位置**，因此 RTTI 和虚基类偏移量需通过**负索引**访问（如 `vptr[-1]`）。
- 虚表中虚函数的顺序与类中虚函数的**声明顺序**一致。

#### 虚表的生成与存储

- **生成时机**：编译器在编译期为每个包含虚函数的类生成唯一的虚表。
- **存储位置**：虚表通常存储在程序的**只读数据段（.rodata）**，确保运行时不可修改，提升安全性。
- **唯一性**：同一类的所有对象共享同一个虚表。

#### 单继承下的虚表示例

```cpp
class Base {
public:
    virtual void f() {}
    virtual void g() {}
    int x;
};

class Derived : public Base {
public:
    void f() override {} // 重写Base::f
    virtual void h() {} // 新增虚函数
    int y;
};
```

**虚表布局（示意）**：

- `Base` 的 vtable：`[ &Base::f, &Base::g ]`（vptr 指向此处）
- `Derived` 的 vtable：`[ &Derived::f, &Base::g, &Derived::h ]`（vptr 指向此处）
  - `Derived::f` 覆盖了原 `Base::f` 的位置
  - 新增的 `Derived::h` 追加到虚表末尾

### 虚指针的完整生命周期

虚指针（Virtual Pointer，简称 vptr）是编译器为每个**包含虚函数的类的对象**插入的一个**隐藏指针成员**，指向该类的虚表。

#### 对象构造中的 vptr 初始化

对象构造时，vptr 的初始化严格遵循以下顺序（以派生类对象为例）：

1. **分配内存**：为对象分配足够的内存空间（包含 vptr、基类成员、派生类成员）。
2. **基类构造**：
   - 调用基类的构造函数。
   - 基类构造函数首先将 vptr 设置为**基类的虚表**。
   - 初始化基类的非静态数据成员。
3. **派生类构造**：
   - 派生类构造函数将 vptr**重置为派生类的虚表**（确保后续虚函数调用指向派生类版本）。
   - 初始化派生类的非静态数据成员。

#### 对象析构中的 vptr 重置

对象析构时，vptr 的重置顺序与构造顺序**相反**：

1. **派生类析构**：
   - 执行派生类析构函数体。
   - 将 vptr 重置为**派生类的虚表**（确保析构过程中调用的虚函数是派生类版本）。
   - 销毁派生类的非静态数据成员。
2. **基类析构**：
   - 调用基类的析构函数。
   - 将 vptr 重置为**基类的虚表**。
   - 销毁基类的非静态数据成员。

#### 构造/析构中调用虚函数的行为

由于构造/析构时 vptr 处于“逐步初始化/重置”状态，**此时调用虚函数不会触发多态**，仅调用当前类的版本（而非派生类）。

```cpp
class Base {
public:
    Base() { func(); } // 调用Base::func
    virtual ~Base() { func(); } // 调用Base::func
    virtual void func() { cout << "Base::func" << endl; }
};

class Derived : public Base {
public:
    Derived() { func(); } // 调用Derived::func
    ~Derived() { func(); } // 调用Derived::func
    void func() override { cout << "Derived::func" << endl; }
};

int main() {
    { Derived d; }
    // 输出顺序：
    // Base::func → Base构造时vptr指向Base虚表
    // Derived::func → Derived构造时vptr重置为Derived虚表
    // Derived::func → Derived析构时vptr仍指向Derived虚表
    // Base::func → Base析构时vptr重置为Base虚表
    return 0;
}
```

**进阶补充：Placement New 与 vptr 初始化**  
Placement new 不分配内存，仅在已有内存上构造对象。其 vptr 初始化流程与常规 new 完全相同：
1. 如果该内存原本存有对象，必须**手动调用析构函数**（`obj.~Class()`）以重置 vptr 和释放资源。
2. Placement new 调用构造函数，会**无条件覆盖**内存区域，包括将 vptr 写入对象头部。
3. 这意味着 placement new 可以用于在缓冲区中“激活”一个具有虚函数的对象，正确设置 vptr，使多态生效。

#### 虚指针的位置与对象布局

- **Itanium ABI**：虚指针位于对象内存布局的**起始位置**（偏移 0）。
- **MSVC ABI**：简单继承下 vptr 位于起始位置；但在**包含虚基类**的布局中，MSVC 可能插入 **vbptr（虚基类表指针）**，且 vptr 和 vbptr 的相对位置由编译器决定，与 Itanium 有较大差异。

### 动态绑定的实现流程

#### 编译器视角：代码生成

当编译器遇到“通过基类指针/引用调用虚函数”的代码时，会生成以下步骤的伪代码：

```cpp
// 原始代码
Base* ptr = new Derived();
ptr->f(); // 虚函数调用

// 编译器生成的伪代码（示意）
using FuncPtr = void (*)(Base*); // 虚函数指针类型（隐含this指针参数）

// 1. 获取对象的vptr
void** vptr = *(void***)ptr; // vptr位于对象起始位置，解引用得到vtable地址

// 2. 从vtable中获取对应虚函数的指针
// 假设f()在vtable中的索引为0（编译期即可确定索引）
FuncPtr func = (FuncPtr)vptr[0];

// 3. 调用虚函数，将对象指针作为this参数传入
func(ptr);
```

**关键说明**：

- 虚函数在 vtable 中的**索引在编译期即可确定**（基于声明顺序），因此运行时仅需一次数组索引访问。
- 虚函数的第一个隐含参数是 `this` 指针，指向调用对象。

#### 运行时视角：完整调用链

1. **对象创建**：`Derived` 对象的 vptr 指向 `Derived` 的 vtable。
2. **指针赋值**：`Base* ptr` 指向 `Derived` 对象的起始地址（即 vptr 的位置）。
3. **虚函数调用**：
   - 通过 `ptr` 解引用得到 vptr。
   - 通过 vptr 找到 `Derived` 的 vtable。
   - 根据索引 0 找到 `Derived::f` 的地址。
   - 调用 `Derived::f`，传入 `ptr` 作为 `this` 指针。

## 复杂继承场景：多继承

### 多 `vptr` 与 `Thunk` 技术

在多继承中，派生类对象包含**多个基类子对象**，每个有虚函数的基类都有独立的 vptr。此时需解决两个问题：

1. 派生类对象有多个 `vptr`，分别指向不同的“子虚表”。
2. 当通过不同基类指针调用同一个派生类虚函数时，`this` 指针需调整为指向派生类对象的起始位置。

**解决方案：`Thunk` 技术**
`Thunk` 是一段编译器生成的小型辅助代码，用于在调用虚函数前**调整 `this` 指针**。

```cpp
class Base1 {
public:
    virtual void f() {}
    int x;
};

class Base2 {
public:
    virtual void g() {}
    int y;
};

class Derived : public Base1, public Base2 {
public:
    void f() override {} // 重写Base1::f
    void g() override {} // 重写Base2::g
    int z;
};
```

**Derived 对象的内存布局**：

```
偏移0:  Base1::vptr (指向Derived的Base1子虚表)
偏移4:  Base1::x
偏移8:  Base2::vptr (指向Derived的Base2子虚表)
偏移12: Base2::y
偏移16: Derived::z
```

**虚表结构**：

- `Derived` 的 `Base1` 子虚表：`[ &Derived::f ]`
- `Derived` 的 `Base2` 子虚表：`[ &Thunk_for_Derived::g ]`

**Thunk 的工作原理**：
当通过 `Base2*` 调用 `g()` 时，`this` 指针初始指向 `Base2` 子对象（偏移 8）。Thunk 会先将 `this` 指针**减去 8 字节**，使其指向 `Derived` 对象的起始位置，再调用 `Derived::g`。

```cpp
// Thunk_for_Derived::g的伪代码
void Thunk_for_Derived::g(Base2* this_base2) {
    Derived* this_derived = (Derived*)((char*)this_base2 - 8); // 调整this指针
    Derived::g(this_derived); // 调用实际的派生类函数
}
```

## 虚基类

### 菱形继承问题的解决

虚基类用于解决**菱形继承（Diamond Inheritance）**中的二义性和数据冗余问题，确保最顶层基类在派生类中仅有一份实例。

### 实现机制

#### Itanium ABI（GCC/Clang）

- 虚基类子对象相对于 vptr 的偏移量存储在虚表的负索引处（`vptr[-2]` 指向偏移量数组）。
- 派生类通过虚表获取偏移量来访问虚基类子对象。

#### MSVC ABI

- MSVC 使用独立的 **虚基类表（vbtable）** 和 **虚基类表指针（vbptr）**。
- 每个包含虚基类继承的类对象中会插入一个 vbptr，指向一个存储各虚基类偏移量的数组。
- 该机制使得对象布局与 Itanium 有显著不同：vbptr 通常紧跟 vptr 之后放置，且虚基类子对象可能位于对象中部而非末尾。

### 对象布局特点

- Itanium ABI：虚基类子对象通常位于派生类对象的**末尾**（非虚基类在前，虚基类在后）。
- MSVC ABI：布局由编译器决定，可能将虚基类放置在中间区域以减少偏移量计算开销。

```cpp
class Top { public: int t; };
class Left : virtual public Top { public: int l; };
class Right : virtual public Top { public: int r; };
class Bottom : public Left, public Right { public: int b; };

// Bottom对象布局示意（Itanium ABI）：
// [Left::vptr (含Top偏移量), Left::l, 
//  Right::vptr (含Top偏移量), Right::r, 
//  Bottom::b, Top::t]
// Top::t仅存在一份，通过Left/Right的vptr中存储的偏移量访问。
```

### 虚继承构造强制规则

虚基类的构造函数**必须由最派生类直接调用**，**中间类对虚基类构造函数的调用会被忽略**（因虚基类仅有一份实例，需由最终派生类统一初始化）。若最派生类未显式调用虚基类构造函数，编译器会隐式调用虚基类的**默认构造函数**。

```cpp
class Top {
public:
    Top(int t) : t(t) {}
    int t;
};

class Left : virtual public Top {
public:
    Left(int t, int l) : Top(t), l(l) {} // 中间类的Top构造会被忽略
    int l;
};

class Right : virtual public Top {
public:
    Right(int t, int r) : Top(t), r(r) {} // 中间类的Top构造会被忽略
    int r;
};

class Bottom : public Left, public Right {
public:
    // 最派生类必须直接调用Top的构造函数
    Bottom(int t, int l, int r, int b) : Top(t), Left(t, l), Right(t, r), b(b) {}
    int b;
};

int main() {
    Bottom b(10, 20, 30, 40);
    cout << b.t << endl; // 10，由Bottom直接初始化Top
    return 0;
}
```

## RTTI 与运行时类型识别

### type_info 类

- 每个类对应一个 `type_info` 对象，存储类的类型信息（如类名）。
- 存储位置：Itanium ABI 中，`type_info` 指针位于虚表的**负索引处**（`vptr[-1]`）。

### typeid 运算符

- 对**多态类型**（含虚函数的类）的对象/指针/引用使用时，返回**实际类型**的 `type_info`（动态绑定）。
- 对非多态类型使用时，返回**静态类型**的 `type_info`（编译时确定）。

### dynamic_cast 转型

- 用于安全的**向下转型**（基类→派生类）或**交叉转型**（多继承中不同基类间转换）。
- 实现原理：利用 RTTI 和虚表中存储的继承层次信息，检查转换是否合法；若合法，调整 `this` 指针并返回目标类型指针；否则返回 `nullptr`（指针）或抛出 `bad_cast` 异常（引用）。

## 标准布局与平凡可复制类型

C++11 引入的类型属性对对象模型有严格约束，直接影响与 C 语言的互操作性及底层操作的安全性。

### 标准布局（Standard Layout）

满足以下条件的类为**标准布局**：

- 所有非静态数据成员具有相同的访问控制（`public` / `protected` / `private`）。
- 无虚函数或虚基类。
- 所有非静态数据成员和基类自身也是标准布局。
- 继承树中最多只有一个类有非静态数据成员。

标准布局类型的对象地址就是其第一个成员的地址，可使用 `offsetof` 宏，且与 C 结构体内存兼容。

### 平凡可复制（Trivially Copyable）

满足以下条件的类为**平凡可复制**：

- 无用户提供的拷贝构造、移动构造、拷贝赋值、移动赋值、析构函数。
- 无虚函数或虚基类。
- 所有非静态数据成员和基类也是平凡可复制。

平凡可复制类型的对象可以使用 `memcpy` 安全复制，且可在 `std::atomic` 中使用。

```cpp
#include <type_traits>

struct StandardLayout {
    int a;
    double b;
}; // 标准布局、平凡可复制

struct NonStandard {
private:
    int a;
public:
    int b;
}; // 非标准布局（访问控制不同）
```

## 虚函数在共享库边界的问题

当基类定义在动态库 A 中，派生类定义在动态库 B 中时，若库 A 升级后**虚表布局发生变化**（如增加虚函数、改变继承顺序），而库 B 未重新编译，则库 B 中的派生类虚表索引将与库 A 基类预期的不匹配，导致运行时崩溃或错误调用。

**解决方法**：

- **保持接口稳定**：对外暴露的类不使用虚函数，或使用纯虚接口类（如 COM 技术）并固定其虚表顺序。
- **符号版本管理**：在 Linux 下利用 `-fvisibility` 和版本脚本控制符号导出。
- **重新编译所有依赖**：升级库时确保所有下游依赖重新编译。

## 性能分析与工程实践

### 虚函数的开销量化

虚函数的开销主要体现在三个方面：

1. **内存开销**：
   - 每个对象多一个 vptr（32 位系统 4 字节，64 位系统 8 字节）。
   - 每个类多一个虚表（存储函数指针，通常可忽略，因全局共享）。
2. **时间开销**：
   - 每次虚函数调用需多 2-3 次内存访问（vptr→vtable→函数指针）。
   - 无法内联（因运行时才确定函数地址，编译器难以在编译期内联）。
3. **微架构开销**：
   - 间接跳转指令（如 `call [rax]`）会**清空 CPU 流水线**，造成流水线停顿。
   - 若虚表地址未在缓存中，将引发**缓存未命中（Cache Miss）**。
   - 频繁虚函数调用可能导致**分支目标缓冲（BTB）预测失败**，加重性能损耗。

### 优化策略

1. **避免不必要的虚函数**：若类无需被继承，或函数无需重写，不要声明为虚函数。
2. **使用 `final` 关键字**：对无需重写的虚函数或类加 `final`，编译器可能优化掉动态绑定（如直接内联）。
3. **CRTP（奇异递归模板模式）**：实现**静态多态**，无运行时开销。

```cpp
// CRTP示例：静态多态
template <typename Derived>
class Base {
public:
    void func() {
        // 静态转换为派生类指针，调用派生类的func_impl
        static_cast<Derived*>(this)->func_impl();
    }
};

class Derived : public Base<Derived{
public:
    void func_impl() { /* 派生类实现 */ }
};

Base<Derived>* ptr = new Derived();
ptr->func(); // 编译期绑定，直接调用Derived::func_impl，无虚函数开销
```

4. **虚函数集中调用**：若需批量调用虚函数，尽量集中调用，减少缓存未命中。
5. **PGO 优化**：利用 Profile-Guided Optimization 帮助编译器内联热路径虚函数。

**进阶补充：RVO/NRVO 与对象模型的交互** 

返回值优化（RVO/NRVO）允许编译器直接在调用方的栈帧上构造返回值对象，从而消除拷贝/移动构造函数的调用。对于具有虚函数的类：

- **不影响 vptr 正确性**：因为对象是在最终位置直接构造的，构造流程完整，vptr 会被正确初始化为返回类型的虚表。
- **不干扰多态**：即便发生了 RVO，返回基类类型时依然可能发生对象切片。例如 `Base createDerived() { return Derived(); }` 仍然会切片，vptr 重置为 Base 的虚表。优化仅省略了中间拷贝，语义不变。

### 设计准则

- **需要运行时多态**：通过基类接口操作不同派生类对象，且对象类型在运行时才能确定。
- **可扩展性优先**：未来可能新增派生类，且需通过基类接口统一调用。
- **性能可接受**：虚函数的开销在当前场景下可忽略（如非高频调用的函数）。
