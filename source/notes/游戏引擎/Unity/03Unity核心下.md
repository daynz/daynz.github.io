# Unity核心
## 资源管理
### 资源管线
- 资源管线是Unity**从外部原始资源到引擎运行时可实例化、可渲染、可逻辑调用资源的全生命周期底层处理子系统**，贯穿**编辑器导入预处理、离线编译烘焙、序列化归档、打包分包、运行时加载解析、内存驻留与卸载**全链路。
- 底层依托引擎C++内核完成资源格式解析、数据转码、压缩编码、依赖拓扑计算、内存布局分配；C#托管层仅负责配置参数暴露、回调监听、业务层资源调度，不参与底层核心运算。
- 其底层核心依赖**文件流解析器、序列化二进制协议、资源依赖拓扑算法、异步任务调度器、内存池管理器**，是Unity AssetBundle、`Addressables`、热更新、分包加载、跨平台资源适配的底层核心支撑。

#### 底层架构与核心运行模型
##### 分层架构划分
资源管线底层采用**四层隔离架构**，C++内核承载底层能力，托管层做配置与调度，层级职责严格拆分：
1. **原始资源层**：外部原生资源文件（FBX、PNG、WAV、Shader源码、动画剪辑源文件、场景源文件），仅做磁盘原始存储，不具备引擎运行时识别能力。
2. **导入编译层（C++内核）**：引擎内置解析器对原始资源进行**格式解析、结构拆解、参数校验**，执行网格拓扑重构、贴图压缩转码、Shader语法编译、音频采样率重采样、动画曲线烘焙，输出引擎中间资源数据。
3. **序列化归档层（C++内核）**：将编译后的中间资源按Unity**专用二进制序列化协议**序列化，生成`.meta`元数据文件、Library库缓存资源、场景/预制体序列化数据，建立资源唯一ID与依赖索引映射。
4. **运行时调度层**：编辑器模式下走本地Library缓存加载；真机运行时通过**AssetBundle/`Addressables`**读取打包二进制流，完成反序列化、内存映射、依赖递归加载、资源实例化，接入引擎渲染、物理、逻辑系统。

##### 核心运行模型
采用**离线预处理+运行时轻量化解析**的核心模型：

- 编辑器阶段完成**全量耗时运算**（格式转码、烘焙、压缩、依赖计算、冗余剔除），生成可跨平台的标准化缓存资源；
- 运行时仅做**二进制流读取、反序列化、内存地址绑定、依赖队列调度**，避免真机进行高耗时资源处理，保证帧率稳定。
- 同时底层内置**资源脏标记机制**，检测原始资源修改后仅增量重新导入变更部分，全局缓存复用，大幅降低编辑器资源刷新开销。

#### 核心实体分类
| 实体类型 | 底层作用 | 内核运行逻辑 |
| ---- | ---- | ---- |
| 原始资源文件 | 外部资源源载体，存储原生美术/配置数据 | C++文件流模块按后缀匹配专属解析器，逐字节读取文件结构，校验文件头与版本合法性，不做格式修改 |
| .meta元数据文件 | 存储资源导入配置、唯一GUID、依赖关系、平台适配参数 | 以文本格式序列化导入设置，底层通过GUID建立原始资源与Library缓存的映射，变更配置触发重新编译 |
| Library缓存资源 | 编辑器编译后的引擎原生资源缓存，避免重复导入 | 按资源类型分目录存储二进制编译结果，底层做哈希校验，资源无变更时直接复用缓存，跳过重新解析编译 |
| AssetBundle包体 | 跨平台打包后的资源二进制归档包，支持分包与热更 | 底层按**依赖拓扑排序**打包，自动合并冗余共享资源，采用LZ4/原生压缩算法，记录包内资源偏移量与索引表 |
| `Addressables`资源定位器 | 抽象资源寻址层，脱离路径依赖做资源管理 | 底层维护**资源地址-GUID-包体路径**映射表，通过异步加载调度器统一分发资源请求，自动处理分包、本地/远端资源切换 |
| 运行时资源实例 | 加载完成后驻留内存的网格、贴图、材质、Shader等实例 | C++内存池分配固定内存块，托管层仅持有对象引用，底层自动维护引用计数，用于资源自动卸载与内存回收 |

#### 底层完整流程
##### 编辑器导入编译流程
1. 外部原始资源放入项目Assets目录，底层文件监控模块检测文件新增/修改/删除，触发资源导入事件。
2. 按资源后缀匹配**内置专属解析器**（FBX解析器、贴图解析器、音频解析器、**Shader编译器**），C++内核完成原始数据结构解析与合法性校验。
3. 读取对应`.meta`配置，按平台设定执行贴图压缩、网格简化、音频格式转码、Shader变体预编译、动画曲线烘焙。
4. 底层**依赖拓扑算法**扫描当前资源引用的其他资源（材质依赖贴图、预制体依赖网格/材质），构建资源依赖有向图。
5. 将编译完成的资源数据序列化，写入Library缓存目录，同步更新GUID映射表与依赖索引表，生成完整元数据。

##### 资源打包归档流程
1. 打包工具遍历目标资源列表，底层依据**资源依赖图谱**递归收集所有依赖资源，剔除重复冗余资源。
2. 按分包策略、共享资源规则进行资源分组，底层计算资源二进制大小与引用频次，自动合并高频共享资源。
3. 对分组资源执行二进制打包，写入**AssetBundle**索引表、资源偏移地址、校验码，选择压缩算法生成包体文件。
4. 生成打包清单与版本manifest文件，记录包体哈希、资源GUID、依赖关系，为热更与增量更新提供底层校验依据。

##### 运行时加载与卸载流程
1. 业务层发起资源加载请求（同步/异步），请求传入托管层，转发至C++异步任务调度器进入加载队列。
2. 底层通过GUID/地址定位资源所在包体，读取二进制流并做校验码校验，防止资源损坏。
3. 按依赖拓扑顺序**递归反序列化**依赖资源，完成内存映射与内存池分配，创建底层资源内核对象。
4. 托管层接收内核对象引用，生成C#可调用资源实例，接入渲染管线、物理系统、动画系统完成业务使用。
5. 资源使用结束后，底层通过**引用计数机制**检测无任何引用时，触发内存回收，释放内存池块，彻底卸载资源。

#### 子系统专属关键模块
##### 资源依赖图谱机制
底层以**有向无环图**数据结构管理所有资源引用关系，每个资源为节点，引用关系为边。自动识别Prefab、场景、材质、贴图间双向依赖，导入时自动刷新图谱，打包时基于图谱做依赖剔除与分包，加载时按图谱顺序递归加载，从底层杜绝资源缺失、引用悬空问题。

##### 脏标记增量导入机制
底层为每一个资源维护修改时间戳与哈希值，开启**脏标记**状态位。仅当原始资源内容或导入配置变更时，才触发重新导入编译；无变更资源直接复用Library缓存，跳过全流程解析编译，大幅提升大项目编辑器资源刷新效率。

##### Shader专属编译与变体烘焙
资源管线内置**Shader底层编译器**，解析`ShaderLab`语法与HLSL源码，按目标平台（安卓/iOS/PC）编译为对应平台GPU汇编指令。同时预烘焙Shader所有Keyword变体，离线生成变体缓存，运行时直接匹配变体，避免真机实时编译卡顿。

##### 异步加载队列与优先级调度
底层维护多线程异步加载队列，按**资源类型、加载优先级、场景预加载规则**排序任务。拆分IO读取、反序列化、实例化多阶段异步执行，不阻塞主线程；同时限制同时加载任务数量，避免瞬间IO风暴与内存峰值过高。

##### 内存引用计数与自动卸载
引擎C++内核为所有运行时资源维护**引用计数**，托管层创建/销毁引用时自动增减计数。计数归零时底层自动执行资源内存释放、缓存清理，无需业务手动管理卸载，兼顾内存利用率与开发效率，适配移动端内存受限场景。

#### 底层设计价值
- 资源管线作为Unity全引擎的**资源中枢系统**，底层通过标准化导入编译、依赖拓扑管理、序列化归档、异步调度与内存管控，实现了**跨平台资源自动适配、增量导入减少编辑器开销、分包打包支撑热更新、异步加载保障运行时帧率、引用计数实现内存自动化管理**五大核心优势。
- 与引擎**渲染管线、物理系统、导航系统、动画系统、网络系统**深度协同：为渲染提供标准化贴图/网格/Shader资源，为物理提供碰撞网格烘焙资源，为导航提供`NavMesh`烘焙资源，为网络同步提供资源ID统一寻址依据。
- 在工业化游戏开发中，资源管线是**大项目版本管理、多平台适配、热更新架构、分包瘦身、内存优化**的底层基石，屏蔽了底层文件格式、平台差异、资源依赖复杂度，让业务层仅关注资源配置与业务调用，大幅降低大型项目的资源管理与跨平台开发成本。

### 资源管理

- 资源管理是Unity引擎**运行时内存调度与全生命周期管控**的核心子系统，底层核心定位为统一托管层与非托管显存、堆内存的分配、复用、回收与泄漏防护。
- 底层依托**引用计数机制、内存池架构、资源状态机**三大内核能力，核心功能覆盖资源加载调度、内存分区隔离、重复资源去重、显存/堆内存统一回收、自动卸载与泄漏规避；
- 深度依赖引擎C++内核内存管理器、异步任务调度器、AssetBundle底层解析模块，是游戏移动端控内存、防卡顿、规避资源泄漏、支撑工业化分包与热更的底层基础。

#### 底层架构与核心运行模型
资源管理底层采用**三层分层架构**，严格划分C++内核层与C#托管层职责：
- 内核底层：负责**引用计数维护、内存池块分配、显存申请释放、资源状态流转、内存碎片整理**，承担所有底层运算与内存管控逻辑。
- 调度中间层：维护**资源加载队列、优先级排序、同步/异步任务分发、延迟卸载计时**，统一调度各类资源加载与回收任务。
- 托管业务层：仅暴露资源加载API、卸载接口、常驻资源配置，只做参数配置与业务回调，不参与底层内存运算。

核心运行模型遵循**复用优先、按需加载、计数回收、分区隔离**原则：

- 优先复用内存池已有资源实例，避免重复创建；按场景流程按需预加载与延迟卸载；
- 依靠引用计数自动判定资源存活状态；
- 按资源类型做内存分区隔离，杜绝常驻资源与临时资源互相挤占，从底层压低整机内存峰值。

#### 核心实体分类
| 实体类型 | 底层作用 | 内核运行逻辑 |
| ---- | ---- | ---- |
| 常驻全局资源 | 全局常驻内存，跨场景不卸载（公共Shader、通用图集、基础音效） | 底层标记为**永久常驻**，引用计数锁定不递减，跳过自动卸载逻辑，全程驻留内存池复用 |
| 场景独占资源 | 单个场景专属网格、贴图、灯光烘焙资源，随场景生命周期绑定 | 内核绑定场景ID，场景退出时批量清零引用计数，触发批量回收，自动清理独占内存分区 |
| 临时瞬时资源 | 特效贴图、临时音效、一次性预制体实例，生命周期短 | 放入临时内存分区，启用**延迟卸载+超时回收**，无引用后快速归还内存池，减少内存驻留 |
| AssetBundle包体资源 | 分包/热更二进制资源载体，包含网格、材质、Shader变体 | 底层记录包体引用计数，包内资源被引用时锁定包体，无外部引用时整包内存统一释放 |
| 显存非托管资源 | 纹理、渲染目标、网格显存缓冲区，不归属C#托管堆 | 引擎统一接管**显存生命周期**，不受GC管控，随资源引用计数归零同步释放显存地址 |

#### 底层完整流程
1. 业务层发起资源同步/异步加载请求，托管层转发至C++底层任务调度队列，按优先级进行排队排序。
2. 底层先检索**资源内存池**与全局资源注册表，判断资源是否已加载存在，命中则直接返回引用，完成**重复资源去重**。
3. 若无缓存命中，走资源管线加载流程，完成反序列化、内存池块分配、显存申请，创建底层资源内核对象。
4. 内核自动为资源初始化**引用计数**，托管层获取对象引用时自动递增计数，业务销毁引用时自动递减计数。
5. 资源引用计数归零后，底层标记为可回收状态，根据资源类型执行即时回收或**延迟卸载**策略。
6. 可回收资源归还对应内存池，内存块标记为空闲等待复用；显存、非托管堆内存同步释放，合并内存碎片，更新内存分区占用统计。
7. 场景切换时，底层按场景ID批量清理独占资源，自动清空失效引用，规避悬空引用与内存泄漏。

#### 子系统专属关键模块
##### 引用计数管控机制
- 引擎为每一类运行时资源内置**内核级引用计数**，完全由C++底层维护，不受C#GC干扰。
- 资源被实例化、被预制体/场景引用、被脚本持有引用时计数自增；
- 引用失效、对象销毁、包体卸载时计数自减。计数归零时触发回收判定，从底层杜绝人为漏卸载导致的资源泄漏。

##### 内存池复用机制
- 内部划分多规格**固定大小内存池**，针对纹理、网格、音频、预制体实例做分类池化管理。
- 资源释放后不直接归还系统内存，而是放回内存池空闲列表；
- 新资源请求优先从池内取用空闲块，减少频繁malloc/free开销，**降低内存碎片与GC触发频率**，适配移动端低内存、低卡顿需求。

##### 内存分区隔离机制
- 底层把内存划分为**全局常驻区、场景独占区、临时资源区、显存非托管区**四大隔离分区。
- 各分区内存占用独立统计、回收策略独立配置，互不侵占内存空间；
- 可精准监控各类型资源内存占比，便于做内存裁剪与性能优化。

##### 加载队列与优先级调度
- 内置**异步加载任务队列**，支持划分高优先级（场景关键资源）、普通优先级（美术资源）、低优先级（后台预加载资源）。
- 底层多线程拆分IO读取、反序列化、实例化流程，主线程只做最终对象回调，避免同步大资源加载造成帧率卡顿。

##### 延迟卸载与自动清理机制
- 支持配置资源**延迟卸载窗口期**，短时间内重复复用的资源不立即回收，避免反复加载卸载造成IO与性能损耗；
- 场景销毁、AB包卸载、资源引用失效时，底层自动批量清理失效资源与悬空引用，实现无业务侵入式内存管理。

#### 底层设计价值
- 资源管理作为引擎内存调度的核心中枢，底层以**引用计数+内存池+分区管控**为核心，实现了资源自动生命周期管理、内存复用降碎片、显存与托管内存统一管控、自动防泄漏四大核心能力。
- 与**资源管线、渲染管线、物理系统、场景管理、网络系统**深度协同：为渲染提供稳定显存资源生命周期，为场景切换做批量内存清理，为AB包热更提供包体引用与回收支撑，为动画、音频系统提供池化资源复用能力。
- 在工业化游戏开发中，该系统屏蔽了底层内存分配、显存管理、资源卸载的复杂细节，降低业务层内存管理成本；同时从引擎底层严控内存峰值、减少GC卡顿、规避资源泄漏，是移动端大型项目性能优化、版本迭代、热更新架构落地的关键底层支撑。

## 性能与优化工具
### Profiler

- Profiler 是 Unity 引擎**内置全链路底层性能采样、时序采集、指标统计与瓶颈定位**的核心诊断子系统。
- 底层核心定位为引擎全线程、全子系统的**高精度埋点采样器**，核心功能是逐帧采集 CPU/GPU 耗时、内存分配、线程调度、渲染提交、资源加载、GC 回收等原始底层数据；
- 底层依赖**高精度硬件时钟、引擎内核埋点探针、多线程数据采集队列、时序帧缓冲区**，可穿透主线程、渲染线程、物理线程、Job 工作线程、音频线程全链路，是游戏**卡顿定位、内存泄漏排查、帧率优化、CPU/GPU 瓶颈分析、GC 卡顿治理**的底层基础工具。

#### 底层架构与核心运行模型
Profiler 底层采用**内核埋点采集 + 中转缓存 + 上层解析可视化**三段式架构，严格区分 C++ 内核采样层与 C# 托管展示层：
- 内核采集层：引擎在**物理、渲染、资源、脚本、网络、动画**等所有子系统关键逻辑节点预埋底层探针，以硬件纳秒级时间戳记录函数起止耗时、内存申请释放、线程切换、锁等待、DrawCall 提交等原始数据，不干扰主线程正常逻辑。
- 数据缓存层：开辟独立环形缓冲区，多线程异步批量暂存采样原始数据，避免高频采样造成主线程阻塞，同时做数据压缩与帧对齐。
- 托管解析层：接收缓冲区上传的采样数据流，做帧重组、层级聚合、耗时占比计算、内存指标统计，转换为可可视化的时序视图、层级明细、内存报表，仅负责展示与业务分析，不参与底层采样运算。

核心运行模型为**无侵入埋点 + 帧级时序采样 + 异步批量上报**：引擎运行时每帧按生命周期阶段自动触发埋点记录，采样数据先写入内核环形缓存，再异步推送至编辑器 Profiler 窗口，做到**采样精度高、对游戏运行耗时干扰极小**。

#### 核心实体分类
| 实体类型 | 底层作用 | 内核运行逻辑 |
| ---- | ---- | ---- |
| 引擎内置埋点探针 | 各子系统性能数据采集入口，覆盖全引擎生命周期 | C++ 内核静态埋点，函数进入记录时间戳与栈帧，退出计算耗时并写入采样缓冲区，零业务侵入 |
| 帧时序采样节点 | 按 Unity 帧生命周期划分标准采样阶段 | 底层固定划分**Initialization、GameLogic、Physics、Animation、Rendering、GC、ResourceLoad** 等标准阶段，逐帧标记阶段起止时序 |
| 多线程采样器 | 独立采集渲染线程、Job 线程、物理后台线程数据 | 为每类工作线程分配独立采样上下文，线程本地存储时序数据，避免多线程采样冲突与数据错乱 |
| 内存采样监视器 | 监控托管堆、原生内存、显存、GC Alloc 分配 | 内核拦截**内存申请/释放、纹理显存分配、托管堆对象分配**，实时记录内存大小、分配栈帧、触发频次 |
| 网络与IO采样单元 | 采集网络收发、资源IO读取、AB包加载耗时 | 底层拦截网络套接字收发、文件流读写、资源反序列化流程，记录吞吐、延迟、IO 阻塞时长 |
| 采样环形缓冲区 | 临时缓存原始采样数据，解耦采集与上报 | 固定大小循环内存块，写入指针与读取指针分离，多线程异步写入、批量读出，防止数据丢失与主线程阻塞 |

#### 底层完整流程
1. 游戏启动开启 Profiler 采样模式，底层初始化硬件高精度时钟、采样缓冲区与各线程采样上下文，注册全子系统埋点探针。
2. 游戏每帧开始，内核按**引擎生命周期顺序**依次进入各逻辑阶段，埋点探针自动记录起始时间戳、当前线程、栈帧信息。
3. 执行脚本更新、物理步进、动画计算、渲染管线提交、资源加载、网络消息处理等逻辑，每一个函数节点自动结算耗时，写入环形缓冲区。
4. 内存监视器实时拦截对象分配、显存申请、堆内存扩容，记录**GC Alloc 大小、分配位置、原生内存占用、显存峰值**。
5. 后台异步线程定时从缓冲区批量读取原始采样数据，做帧对齐、数据压缩，通过进程通信推送至编辑器 Profiler。
6. 编辑器端对原始数据做聚合计算：统计单帧总耗时、各阶段占比、平均耗时、峰值尖峰、内存增长曲线，重构时间线与层级调用树。
7. 自动识别**帧卡顿点、CPU 耗时峰值、频繁 GC、内存持续上涨、线程锁阻塞、DrawCall 冗余**等异常特征，支撑性能问题溯源定位。

#### 子系统专属关键模块
##### 高精度时序采样机制
依托硬件**高分辨率计时器**，底层以纳秒级精度记录代码执行耗时，不受游戏帧率波动影响；支持精细到单个 C# 函数、内核底层函数的耗时拆解，可精准定位微秒级耗时瓶颈。

##### 多线程隔离采样机制
主线程、渲染线程、物理 Job 线程采用**独立采样上下文与本地存储**，互不干扰时序记录；底层自动标记线程切换、等待阻塞、自旋锁耗时，可排查多线程竞争、等待卡顿问题。

##### GC 与内存追踪机制
底层精准捕获**托管堆对象分配、临时 GC Alloc、堆扩容、垃圾回收触发时刻与耗时**，记录分配堆栈与频次；同时统计引擎原生内存、纹理网格显存、Audio 内存、AB 包内存，完整还原整机内存构成与泄漏路径。

##### 渲染链路专项采样
深度对接渲染管线底层，采样**DrawCall 数量、批处理合并效率、Shader 变体切换、渲染状态切换、RT 分配、OverDraw 隐含耗时**，完整还原 CPU 提交到 GPU 渲染全链路瓶颈。

##### 远程真机采样机制
支持**真机远程 Profiling**，底层通过网络小包低功耗传输采样数据，不占用游戏业务带宽；真机端仅做轻量采样与缓存，复杂解析与可视化全部放在编辑器完成，保证真机运行性能不受影响。

##### 采样负载抑制机制
底层内置采样频率自适应与数据抽稀策略，高负载时自动降低非关键节点采样精度，优先保证游戏主线程帧率稳定；同时限制缓冲区最大占用，避免 Profiler 自身造成内存上涨。

#### 底层设计价值
- Profiler 作为 Unity 全引擎**统一性能诊断中枢**，底层通过内核无侵入埋点、高精度时序采样、多线程隔离采集、内存与渲染全链路监控，实现了**全线程耗时分析、帧卡顿溯源、内存泄漏定位、GC 卡顿治理、渲染与物理瓶颈排查**核心能力。
- 与**资源管线、资源管理、物理系统、渲染管线、网络系统、Job 任务系统**深度协同：采集各子系统内部逻辑耗时与资源开销，把底层黑盒运行状态转化为可视化可量化指标。
- 在工业化游戏开发与性能优化中，Profiler 是**版本性能验收、移动端适配调优、大型项目帧稳定、内存管控、架构性能复盘**的必备底层支撑，让开发者从表层帧率深入到底层函数、线程、内存、渲染的根因定位，大幅降低性能排查与优化成本。

### Burst 编译器

- Burst 编译器是 Unity 面向**Job System 与高性能数值计算**的专属静态编译子系统，底层核心定位为托管高性能代码的**跨平台静态优化编译器**。
- 核心功能是对标记 `[BurstCompile]` 的**Job 任务、数学运算逻辑、结构化数值代码**做离线静态编译、深度指令优化、跨平台原生机器码生成；
- 底层深度依赖**LLVM 编译后端、Unity 数学库静态类型系统、Job 内存隔离模型**，彻底脱离 .NET 托管运行时 JIT 与 GC 体系，是 Unity 物理并行计算、大规模寻路、动画批量插值、粒子模拟、ECS 业务逻辑高性能落地的底层编译基石。

#### 底层架构与核心运行模型
Burst 底层采用**托管源码解析 → 中间IR生成 → LLVM优化 → 平台机器码输出**四阶段静态编译架构，清晰隔离 C# 托管层与 Burst 编译内核：
- 源码解析层：读取带 `[BurstCompile]` 特性的**结构体 Job、静态数学函数**，做语法树拆解与类型合法性校验，禁止解析含托管引用、类对象、GC 分配的代码。
- IR 中间层：将合法 C# 数值逻辑转为**LLVM 中间表示**，剥离 .NET 元数据、反射、异常捕获等托管层冗余逻辑。
- 优化调度层：依托 LLVM 后端执行全局代码优化，完成常量传播、死代码消除、循环重构、寄存器分配、指令重排。
- 机器码生成层：按目标平台（PC/安卓/iOS）编译为**原生硬件机器码**，独立指令集运行，不依赖 Mono/.NET 托管运行时。

核心运行模型遵循**静态离线编译 + 运行时直接调用**：编辑器/打包阶段提前完成全量编译与优化，运行时仅做原生函数地址跳转执行，无即时编译开销、无JIT延迟、无托管运行时调度损耗。

#### 核心实体分类
| 实体类型 | 底层作用 | 内核运行逻辑 |
| ---- | ---- | ---- |
| Burst Job 结构体 | 承载并行计算逻辑的最小执行单元，纯值类型隔离托管引用 | 底层强制校验仅含**值类型、数学结构体、原生数组**，禁止class、string、托管引用，违规直接编译报错 |
| 静态数学函数 | 可被Burst编译的无GC纯计算工具方法 | 编译时内联展开、常量折叠，消除函数调用开销，适配SIMD向量化指令 |
| 只读/可读写原生数组 | Burst 并行计算的数据载体，脱离托管数组GC管控 | 底层映射为**原生内存指针**，取消数组边界检查、托管元数据开销，直接内存寻址访问 |
| LLVM 优化单元 | Burst 核心代码优化与指令生成后端 | 内置多级优化策略，自动做循环展开、公共子表达式消除、常量传播、死代码剔除 |
| 平台指令集适配器 | 按硬件架构生成对应最优机器码 | 自动识别 X86、ARM 架构，适配 **SIMD/Neon** 向量指令、CPU 特殊扩展指令，最大化硬件算力 |

#### 底层完整流程
1. 代码标记 `[BurstCompile]` 特性，Burst 编译内核扫描程序集，筛选合法 Job 结构体与静态计算函数。
2. 底层做**类型严格校验**，检测是否存在托管类引用、装箱拆箱、GC 分配、反射、try-catch 等非法语法，存在则编译失败回退至托管执行。
3. 合法代码转换为 LLVM 中间 IR，剥离 .NET 托管层附加逻辑，保留纯数值运算与内存读写逻辑。
4. 执行多层全局优化：常量传播、死代码剔除、循环合并与展开、寄存器优化、函数内联。
5. 针对目标平台架构，启用 **SIMD/Neon 向量指令** 做向量化重构，生成硬件最优原生机器码。
6. 编译结果缓存入库，打包时嵌入平台专属机器码；运行时 Job System 直接调用原生函数地址，无托管跳转、无GC、无额外开销。
7. 多线程调度时，Burst 机器码在工作线程独立执行，完全脱离主线程与托管运行时调度。

#### 子系统专属关键模块
##### 严格托管隔离机制
Burst 底层强制**禁止任何托管引用与GC分配**，仅允许值类型、原生数组、`Unity.Mathematics` 数学类型。编译阶段静态校验，从语法层面杜绝隐式装箱、临时托管对象分配，保证编译后代码**零`GC Alloc`**。

##### LLVM 全局代码优化
内置高阶优化策略：常量折叠、循环不变量外提、死代码删除、跨函数内联、栈内存优化。大幅精简指令数量，消除托管代码自带的边界检查、元数据读取等冗余开销，逼近 C++ 执行效率。

##### SIMD 向量化加速
底层自动识别并行数值计算逻辑，自动重构为**SIMD/ARM Neon 向量指令**，单指令多数据批量完成向量、矩阵、大规模数组运算，大幅提升物理、寻路、粒子批量计算吞吐。

##### 编译缓存与增量编译
对已编译合法 Job 做机器码缓存，代码无变更时直接复用缓存，跳过全编译流程；仅修改部分逻辑时做**增量重编译**，大幅降低编辑器与打包编译耗时。

##### 安全内存别名检测
底层内置**内存别名分析**，自动检测多 Job 间内存读写冲突、越界访问风险，在编译阶段提前报错，规避并行计算野指针与内存踩踏问题，兼顾高性能与运行稳定性。

##### 平台自适应指令裁剪
自动适配不同 CPU 架构与指令集，按需启用高级扩展指令，低端设备降级兼容、高端设备拉满算力，做到跨平台性能自适应。

#### 底层设计价值
- Burst 编译器作为 Unity 高性能并行计算的**编译底层底座**，以 LLVM 为后端实现托管数值代码静态编译、深度指令优化、平台原生机器码生成，实现**零GC开销、消除托管损耗、SIMD硬件加速、接近C++执行性能**四大核心能力。
- 与 **Job System、ECS、物理系统、导航寻路、动画系统、粒子系统** 深度协同：为所有大规模并行数值计算提供高性能编译能力，支撑海量实体物理迭代、批量寻路计算、动画插值、粒子动力学模拟的低耗时运行。
- 在工业化游戏与高性能项目开发中，Burst 屏蔽了底层编译原理、平台指令集差异与托管运行时缺陷，让开发者用 C# 编写逻辑即可获得原生级高性能，是大型开放世界、海量实体模拟、移动端性能极限优化的关键底层支撑。

# Unity核心子系统
### Job System
- Job System 是 Unity 引擎**跨线程并行任务调度与多核算力利用**的底层架构子系统。
- 底层核心定位为**安全可控的多线程任务分发器**，核心功能是将主线程繁重的数值计算、批量逻辑运算拆解为独立 Job，调度至后台线程池并行执行；
- 底层依赖**全局线程池、任务依赖图、内存安全屏障、读写冲突检测**，强制约束数据访问规范，配合**Burst编译器**实现高性能无GC并行计算。
- Job System 是引擎物理迭代、导航寻路、动画骨骼批量计算、场景裁剪、粒子模拟、ECS海量实体运算的多线程底层支撑。

#### 底层架构与核心运行模型
Job System 底层采用**任务抽象层 + 依赖调度层 + 线程池执行层**三层架构，严格区分托管层配置与C++内核调度：
- 任务抽象层：C# 托管侧以**结构体Job**作为最小任务单元，仅允许值类型数据，禁止MonoBehaviour、类引用、托管对象，从源头隔离多线程内存风险。
- 依赖调度层：内核维护**任务有向依赖图**，自动解析Job之间只读/可读写依赖关系，构建执行先后顺序，有依赖任务串行执行、无依赖任务并行调度。
- 线程池执行层：引擎内置固定数量后台工作线程，底层维护**任务环形队列**，自动做负载均衡、任务窃取、空闲线程休眠，实现多核CPU算力最大化利用。

核心运行模型遵循**数据隔离、依赖串行、无冲突并行、主线程回调**原则：通过**只读/只写Native容器**隔离多线程内存读写，依靠内存屏障避免竞态条件；自动编排任务执行时序，后台线程完成计算后统一切回主线程完成业务回调，不允许工作线程直接操作引擎场景对象。

#### 核心实体分类
| 实体类型 | 底层作用 | 内核运行逻辑 |
| ---- | ---- | ---- |
| 普通Job结构体 | 承载单次串行计算逻辑，基础任务执行单元 | 托管侧纯值类型定义，底层入队后由工作线程轮询取出执行，可配合Burst编译生成原生机器码 |
| `IJobParallelFor` 并行Job | 面向大规模数组批量循环计算的并行任务 | 底层自动对索引区间分片，分发到多个工作线程同时执行，自动均分计算负载，适配海量数值遍历 |
| `NativeArray` / `NativeList` | 多线程安全的数据容器，脱离托管堆GC管控 | 底层映射**原生非托管内存**，由引擎内核管理内存分配与释放，强制读写权限标记，防止多线程踩踏 |
| `Job依赖句柄 JobHandle` | 标识任务执行状态与依赖关系的内核句柄 | 底层记录任务完成标记、前置依赖列表，调度器依据句柄阻塞后续任务，等待前置Job执行完毕 |
| 全局工作线程池 | 后台并行执行载体，复用线程避免频繁创建销毁 | 引擎启动时初始化固定线程数量，维护任务抢占队列，空闲线程休眠、有任务时唤醒，降低线程调度开销 |
| 内存安全屏障 | 多线程读写冲突防护底层机制 | 底层自动检测同一块内存**同时写、读写并发**场景，插入内存屏障强制串行执行，规避数据竞态与脏数据 |

#### 底层完整流程
1. 业务层定义**值类型Job结构体**，填充Native容器数据，声明数据只读/可读写权限。
2. 调度器接收Job提交请求，底层生成**`JobHandle`**，将任务加入全局任务队列。
3. 内核解析当前Job的前置依赖句柄，校验依赖任务是否完成；未完成则进入等待队列，等待依赖解除。
4. 线程池空闲工作线程从队列抢占任务，若无依赖冲突则多线程并行执行；存在读写依赖则按依赖顺序串行执行。
5. 若标记`[BurstCompile]`，任务交由**Burst编译器**生成原生机器码执行，零托管开销、零GC；普通Job以托管模式在工作线程运行。
6. Job执行完成后，底层标记句柄为完成状态，释放占用的Native内存访问权限。
7. 主线程通过`Complete()`接口等待任务全部完成，同步读取计算结果，回到主线程执行业务逻辑、对象赋值与渲染刷新。
8. 任务生命周期结束，手动释放Native容器原生内存，避免非托管内存泄漏。

#### 子系统专属关键模块
##### 任务依赖与调度编排
底层以**有向无环图**管理所有Job依赖关系，自动识别数据读写依赖，无需手动硬编码执行顺序。调度器智能合并无依赖任务、串行编排有依赖任务，兼顾并行效率与执行正确性。

##### 多线程内存安全隔离
强制采用**值类型Job + Native原生容器**模型，禁止工作线程访问任何Unity引擎托管对象、场景实体。底层做静态读写权限校验，同一内存块禁止多线程同时写入，从架构层面杜绝竞态条件、野指针与内存踩踏。

##### 任务窃取与负载均衡
工作线程采用**任务窃取调度机制**，空闲线程主动从繁忙线程的任务队列尾部窃取任务执行，自动均衡多核CPU负载，避免部分线程过载、部分线程空闲的算力浪费。

##### 与Burst深度协同机制
Job天然适配**Burst编译器**，结构体Job经标记后可静态编译为平台原生机器码，剥离托管边界检查、元数据、装箱拆箱开销，并行计算性能逼近C++；且编译阶段做内存别名检测，提前规避并行内存风险。

##### 主线程安全同步机制
严格限制工作线程只做纯数值计算，**禁止操作`Transform`、`GameObject`、渲染组件**等引擎对象。所有场景变更、组件赋值必须等待Job完成后切回主线程执行，保证引擎对象生命周期与线程安全。

##### 批量并行分片机制
`IJobParallelFor` 底层自动对数组索引做**均等分片**，按CPU核心数拆分任务区间，每个线程负责一段索引范围，无需业务手动分片，极简实现大规模循环并行计算。

#### 底层设计价值
- Job System 是 Unity 引擎**释放多核CPU、解耦主线程耗时、实现安全并行计算**的核心调度底座，以**线程池调度、依赖图编排、内存隔离屏障、任务负载均衡**为核心，实现了主线程降压、多核算力利用、多线程安全可控、配合Burst达成高性能计算四大核心能力。
- 与 **Burst编译器、物理系统、导航寻路、动画系统、渲染管线、ECS架构、Profiler** 深度协同：承接物理步进、寻路采样、动画骨骼烘焙、视锥体裁剪、ECS实体遍历等繁重逻辑的并行化拆分，为各子系统提供安全高效的多线程执行能力。
- 在工业化游戏开发中，Job System 屏蔽了多线程原生开发的线程创建、锁机制、竞态处理、负载调度等底层复杂度，让业务以极简结构体写法实现安全并行计算，是开放世界、海量NPC、大规模特效、移动端帧率稳定优化的必备底层架构支撑。
