std::optional<T>

std::optional<T> 是 C++17 引入的可空（可选）值包装器，用于表示 “有值 / 无值”两种状态，专门替代指针判空、哨兵值、错误码等不安全的 “空值” 表达方案，是现代 C++ 处理**可选返回值、可选参数 ** 的标准工具。

核心价值：类型安全表达 “有 / 无值”，明确语义、避免空指针、消除魔数（-1、nullptr），代码可读性与安全性大幅提升。

背景

传统表达 “可选值” 的方式全是缺陷：

  1. 用指针：T* func() → 空指针风险、内存泄漏、语义模糊；
  2. 用哨兵值：返回 -1/0/"" 表示失败 → 易误用、语义不明确；
  3. 用布尔 + 输出参数：bool get(T& out) → 代码臃肿、无法链式调用。

核心语法与基础使用

std::optional<T> 是一个值类型（不是指针），内部存储：

  • 要么：一个合法的 T 实例（有值）
  • 要么：无任何值（空状态）

它不分配堆内存，直接在内部存储对象，零额外开销。

操作 作用
std::optional<T> opt{} 创建空 optional
std::optional<T> opt{t} 创建有值 optional
opt.has_value() / if(opt) 判断是否有值
*opt 直接取值（无值则未定义行为）
opt.value() 取值，无值抛 std::bad_optional_access
opt.value_or(def) 有值返回值，无值返回默认值 def
opt.reset() 清空为无值

核心规则与注意事项

  • optional 是值语义，拷贝、移动和 T 一致；
  • 可存储任何类型（基础类型、结构体、对象）

std::variant<T...>

std::variant<T...> 是 C++17 引入的类型安全联合体（Type-Safe Union），用于表示一组指定类型中的 “某一种”，同一时刻只存储其中一种类型的值。

它完全替代了 C 风格的 union，没有未定义行为、自动管理生命周期、类型安全、支持复杂对象，是现代 C++ 处理多类型值的标准方案。

核心价值：类型安全的 “多类型二选一 / 多选一”，替代不安全 union，明确持有类型，不悬空、不泄漏、不崩溃。

背景

传统 union 只能存简单类型，不支持构造 / 析构函数，极易踩坑：

问题：

  1. 不支持非平凡类型（string、vector、自定义对象）
  2. 不知道当前存储的是什么类型
  3. 手动管理生命周期，极易内存泄漏 / 崩溃

核心语法与基础使用

std::get<index>(v) 按索引获取值
std::get_if<T>(&v) 返回指针，错误返回 nullptr
v.index() 返回当前类型的索引（0,1,2…）
std::monostate 空状态，用于解决无默认构造问题
  • std::variant<T1, T2, T3,...>：能持有类型列表中的某一种
  • 同一时刻只存一个值
  • 类型安全：永远知道当前存储的类型
  • 自动管理内存：正确构造 / 析构，支持任意复杂类型

std::any

std::any 是 C++17 引入的类型安全的任意类型容器，提供了一种可存储任意单一类型值、且能在运行时安全获取与检查的机制，彻底解决了传统 void* 无类型检查、不安全、易造成未定义行为的痛点。

核心价值：安全存储任意类型值 + 运行时类型检查 + 自动内存管理，替代不安全的 void*，用于需要存储未知 / 任意类型的场景。

std::any 就是 类型安全版的 void\*。

背景

在没有 std::any 前，C++ 想存储 “任意类型” 只能用 void\*，但问题极大：

  1. 完全无类型安全：不知道原始类型，强转错误直接崩溃
  2. 手动管理内存：容易泄漏、悬空指针
  3. 不支持复杂对象：无法正确构造 / 析构

核心语法与基础使用

操作 作用
std::any a 创建空实例
a.has_value() 是否有值
a.type() 返回 std::type_info，可判断类型
std::any_cast<T>(&a) 安全指针形式，失败返回 nullptr（推荐）
std::any_cast<T>(a) 值形式，失败抛异常
a.reset() 清空，释放内部对象
  • 可以存储任何类型（int、string、自定义类、指针…）
  • 是值类型，会拷贝 / 移动存储的对象
  • 自动管理生命周期，无需手动释放
  • 运行时记录类型信息，错误转换会抛异常而非崩溃
  • 不属于模板，是通用类型（这一点和 variant 不同）

  4. 存储值语义对象，会自动拷贝 / 析构
  5. 不能存储引用，但可存储指针

std::string_view

std::string_view 是 C++17 引入的字符串只读视图，本质是 **“指针 + 长度”的轻量级结构，用于安全、高效、零拷贝 ** 读取字符串数据。

核心价值：只读字符串的 “零成本封装”，完美解决 const char* 不安全、std::string 传参拷贝开销大的痛点，是现代 C++ 字符串只读参数的首选类型。

背景

处理只读字符串时，传统方式有严重缺陷：

  1. const char\*：无长度信息，极易越界，不安全；
  2. const std::string&：传字符串字面量 / 字符数组时，会隐式构造临时 string，产生内存分配 + 拷贝，性能损耗大。

核心语法与基础使用

操作 作用
str.size() 获取长度（O (1)，不含\0）
str.data() 获取原始指针
str[i] 访问第 i 个字符
str.substr(pos, len) 取子串 （零拷贝！）
str.empty() 判断空
str.remove_prefix(n) 前缀跳过 n 字符
str.remove_suffix(n) 后缀截断 n 字符
  • 轻量级结构：仅含 const char*（数据指针）+ size_t（长度）；
  • 只读视图：不可修改原始字符串，仅用于读取；
  • 零拷贝：不分配内存、不拷贝数据，仅包装已有字符串；
  • 通用接口：拥有和 std::string 几乎一致的读取接口，使用成本极低。

  • 字符串视图不拥有数据，生命周期由外部保证：不要返回局部 string 的 string_view

并行算法 (Parallel Algorithms)

C++17 为 STL 算法（如 std::sort/std::for_each/std::transform）引入了并行执行策略，让你仅加一个参数，就能自动利用多核 CPU 加速，无需手动写线程、锁、线程池。

核心价值：一行代码让 STL 算法自动多核并行，无痛加速 CPU 密集型任务，是现代 C++ 性能优化的最简单利器。

核心概念

C++17 做了两件事：

  1. 给所有 STL 算法增加了并行版本
  2. 新增 3 种执行策略，你只需要传给算法即可

完全兼容原有代码，只多一个参数。

std::execution::seq 串行（和原来一样） 单线程顺序执行
std::execution::par 并行 多核并行执行（最常用）
std::execution::par_unseq 并行 + 向量化 多核 + SIMD 指令级并行

支持的 STL 算法

所有常用算法都支持并行（几乎全覆盖）：

  • for_each
  • sort / stable_sort
  • transform
  • find_if / count_if
  • replace / fill
  • reduce（并行版累加）
  • inclusive_scan 等

注意事项

  • 函数不能有数据竞争

    • 并行同时执行，不能写共享变量（不加锁会崩溃）

  • 函数不能依赖顺序

    • 执行顺序不确定

  • 不能抛异常

    • 并行异常行为复杂

  • 纯函数最好：只读写自己的元素

  • 必须链接 TBB 或 使用 GCC 并行库

嵌套命名空间定义

C++17 引入了嵌套命名空间简写语法，允许一行直接定义多层命名空间，彻底告别传统繁琐的逐层嵌套写法，让命名空间代码更简洁、清爽、易维护。
