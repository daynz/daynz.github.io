std::byte

std::byte 是 C++17 引入的独立字节类型，专门用来表示内存中的原始字节（8 位二进制数据），而不是字符或数值。

核心价值：类型安全的原始字节，禁止算术运算，语义纯粹，杜绝隐式转换，让底层内存操作更安全。

背景

在 C++17 之前，表达 “原始字节” 只有两种方案，都有严重缺陷：

  1. char / unsigned char：

    既是字符又是整数，语义模糊，容易被误用做加减乘除；

  2. uint8_t：

    本质是整数，支持算术运算，无法区分 “数值” 和 “原始字节”。

核心定义

  • 专门表示内存中的 1 字节原始数据
  • 不是字符、不是整数、不参与数学运算
  • 底层等价于 unsigned char，但强类型、语义纯净
  • 只允许位运算（| & ^ ~），禁止加减乘除
  • 头文件：<cstddef>

头文件

类型 语义 允许运算 类型安全
std::byte 原始字节、内存数据 仅位运算 ✅ 最高
unsigned char 字符 / 整数 算术 + 位运算 ❌ 差
uint8_t 8 位整数 算术 + 位运算 ❌ 差

std::invoke

std::invoke 是 C++17 引入的通用可调用对象包装器，它提供了统一、透明、一致的方式来调用任何可调用对象：普通函数、函数指针、lambda、std::function、成员函数、成员变量。

核心价值：用同一套接口调用一切可调用对象，自动处理成员函数指针、成员变量、对象引用 / 指针 / 智能指针，代码极度通用。

背景

在 C++ 里，调用不同可调用对象的语法完全不一样，写泛型代码非常痛苦：

  1. 普通函数：func(args...)
  2. 成员函数：(obj.*func)(args...)
  3. 成员函数（指针）：(obj->*func)(args...)
  4. 仿函数 /lambda：obj(args...)

写一个通用调用器非常麻烦，std::invoke 直接统一所有语法。

核心定义

完美支持所有 C++ 可调用类型

可调用对象 用法
普通函数 invoke(func, args...)
lambda / 仿函数 invoke(func, args...)
成员函数 invoke(&T::func, obj, args...)
成员变量 invoke(&T::var, obj)
对象指针 invoke(&T::func, ptr, args...)
智能指针 invoke(&T::func, smart_ptr, args...)

核心使用场景

调用普通函数 /lambda

调用成员函数

直接访问成员变量

支持指针 / 智能指针

能接受任何函数 / 成员函数，不用区分语法

std::invoke_result：获取返回值类型

std::apply

std::apply 是 C++17 引入的元组展开工具，它的作用只有一个：

把一个 std::tuple 里的所有元素，自动展开成函数的实参，并调用该函数。

核心价值：一键将 tuple 解包为函数参数，完美解决元组与函数参数之间的转换问题，是处理批量参数、绑定、反射的神器。

背景

在 C++17 之前，想把 std::tuple 里的参数传给函数极其麻烦：

  • 必须手写递归展开
  • 代码冗长、容易出错
  • 无法直观实现 func(tuple_args...)

核心语法

头文件

  • 接收：任意可调用对象（函数、lambda、成员函数）
  • 接收：std::tuple / std::pair / std::array
  • 行为：自动展开元组 → 调用函数
  • 返回：函数的返回值

核心使用场景

最常用场景：lambda + apply

支持 pair /array

std::apply + std::invoke

把 tuple 展开成成员函数的参数

C++20 甚至有 std::invoke_r 可以进一步简化

核心用途

  1. 把 tuple 变成函数参数
  2. 批量参数传递、序列化、反序列化
  3. 函数绑定、回调、反射系统
  4. 配合折叠表达式处理任意参数
  5. 解包 pair /array

std::uncaught_exceptions

std::uncaught_exceptions 是 C++17 引入的异常处理工具，用于获取当前线程中 “已抛出但尚未捕获” 的异常数量。

它完全替代了 C++11 的 std::uncaught_exception（不带 s），解决了旧版在析构函数中检测是否因异常退出时的重大缺陷。

核心价值：让析构函数能安全、准确地判断：当前是否正在因异常而退出作用域，从而实现安全的事务型对象（Scope Guard）。

背景

C++11 的 std::uncaught_exception() 只能返回 bool（是否有异常），无法处理嵌套场景：

  • 如果在析构函数中又抛出异常，旧版会直接误判，导致逻辑错误。

因此 C++17 新增了带复数 s的版本：std::uncaught_exceptions()，返回 int 计数。

核心语法与基础使用

头文件

区别

  • C++11 废弃：bool std::uncaught_exception()
  • C++17 推荐：int std::uncaught_exceptions() 返回当前未捕获的异常个数。

Scope Guard（作用域守护）

这是它唯一的核心用途：

判断对象是 “正常离开作用域”，还是 “因异常离开作用域”，从而决定：

  • 正常 → 提交（commit）
  • 异常 → 回滚（rollback）

为什么必须用 uncaught_exceptions()（带 s）

  • 旧版 uncaught_exception()：只要有异常就返回 true，嵌套析构中会误判。
  • 新版 uncaught_exceptions()：用计数差判断，100% 准确，无论嵌套多少层。

std::is_final

std::is_final 是 C++17 引入的类型特性（type trait），用于在编译期判断一个类是否被声明为 final（禁止被继承）。

核心价值：编译期检测类是否禁止继承，用于元编程、模板约束、类型校验。

核心语法

头文件：<type_traits>

功能：判断类型 T 是否是 **final 类 / 结构体 **

返回：编译期常量 bool

  • std::is_final_v<T> → true / false

重要规则

  1. 只对类类型有效int、double、指针、引用 → 都是 false
  2. 编译期常量可用于 constexpr、if constexpr、模板参数
  3. 不会忽略 cv 限定符
    • std::is_final_v<const B> → false
    • 要正确判断必须用 std::remove_cv_t

核心使用场景

静态断言（static_assert）

确保某个类一定是 / 不是 final

模板约束（if constexpr /enable_if）

SFINAE 重载

核心语法与基础使用

原来的指针不能直接用了，必须用 std::launder “清洗” 一下，才能安全访问新对象。

C++ 有严格的对象生存期规则：

  • 一块内存同一时间只能有一个活跃对象
  • 如果你用 placement new 在旧内存上创建了新对象
  • 旧指针 / 引用不会自动指向新对象
  • 直接使用会触发未定义行为（UB）

std::launder 的作用就是：告诉编译器：这里已经是新对象了，请用这个指针访问它。

作用：返回一个指向新对象的合法指针。
