左值与右值

左值（Lvalue）

定义（C++17 起）：

左值是指向内存中某个确定存储位置、可以取地址的表达式（L 代表 Location，强调其拥有可标识的存储位置）。左值不一定能被赋值（例如 const 变量、函数名、数组名均为左值但不可赋值），赋值能力是左值的子集属性，而非核心定义。

特征：

  • 拥有名称，生命周期通常较长（变量、对象、返回左值引用的函数等）。
  • 非 const 左值可以出现在赋值运算符 = 的左侧；所有左值都可以出现在赋值运算符的右侧。

右值（Rvalue）

定义（C++17 起）：

非左值的表达式即为右值。C++20 对临时对象的生命周期规则做了进一步细化，但未引入破坏性变更。

细分：

  • 纯右值（Prvalue）：字面量（如 10、"hello"）、表达式计算结果（如 a + b）、返回非引用类型的函数调用结果等。纯右值不具名，生命周期仅限于当前完整表达式。
  • 将亡值（Xvalue）：标识一个即将被销毁、但其资源可被安全转移的对象。典型来源包括 std::move 转换后的左值、返回右值引用的函数调用等。

特征：

  • 纯右值通常无法取地址（临时值无持久存储位置）；将亡值标识的对象本身拥有地址，但作为表达式通常不允许直接取地址（&std::move(a) 非法）。
  • 无名称，生命周期短暂（纯右值在表达式结束时销毁，将亡值对象处于“可转移”状态）。
  • 仅能出现在赋值运算符 = 的右侧，不能出现在左侧。

右值引用

右值引用（C++11 引入，C++17 完成标准化优化）是 C++ 针对值类别设计的引用类型，核心目标是避免不必要的拷贝、提升性能，同时也是移动语义与完美转发的基石。

应用：移动语义

移动语义的核心思想是：用“移动”替代“拷贝”，避免临时对象的深拷贝开销（尤其对于大对象，如 std::string、std::vector 或游戏开发中的纹理、资源数据等）。

移动语义是 C++11 引入的关键特性，其本质是一种高效的资源转移机制——借助右值引用识别出“即将销毁的临时对象（右值）”，直接“窃取”（接管）该对象的底层资源（如堆内存、文件句柄、网络连接），而非执行耗时的深拷贝，从而在保证资源安全的前提下显著提升程序性能。C++20 扩展了 constexpr 上下文中对移动语义的支持。

深拷贝与浅拷贝

拷贝的根本目的是：创建一个新对象，使其内容与原对象相同。根据实现方式的不同，分为浅拷贝和深拷贝。

  • 浅拷贝

    • 定义：逐字节拷贝对象的所有成员变量——只拷贝“表面”的数值（如指针的地址值、基础类型值），不拷贝指针所指向的底层资源（如堆内存、文件句柄）。
    • 本质：新对象与原对象共享同一份底层资源，仅拷贝了资源的“引用”（指针/句柄），未创建新资源。
    • C++ 编译器自动生成的默认拷贝构造函数和默认拷贝赋值运算符均执行浅拷贝。
    • 适用场景：当对象不管理任何底层资源（无堆内存、句柄等）时，浅拷贝是高效且安全的；若对象管理资源，浅拷贝会引发双重释放、野指针等严重问题。

  • 深拷贝

    • 定义：不仅拷贝对象的成员变量，还会拷贝指针所指向的底层资源——新对象拥有独立的资源副本，与原对象完全隔离。
    • 本质：新对象与原对象“内容相同，但资源独立”：
      • 基础类型成员：直接拷贝值；
      • 指针/资源句柄：重新申请一块新资源，并将原资源的内容完整复制过去。
    • 适用场景：深拷贝是管理底层资源的类（如字符串、容器、智能指针）的标配，用于保证对象独立性与资源安全。
特性 浅拷贝（Shallow Copy） 深拷贝（Deep Copy）
拷贝内容 仅拷贝成员变量的值（如指针地址） 拷贝成员变量 及 指针所指向的底层资源
资源独立性 新对象与原对象共享同一份资源 新对象与原对象拥有独立的资源副本
内存开销 低（无需申请新资源） 高（需申请新内存并拷贝数据）
安全性 在资源管理类中易导致双重释放、数据干扰 安全，对象独立，无资源冲突
实现方式 编译器默认生成（无需手动编写） 必须手动实现拷贝构造函数与拷贝赋值运算符
适用场景 无底层资源的简单类（如 Point、int） 管理底层资源的类（如 String、Vector）

移动构造函数与移动赋值运算符

移动操作通常应标记为 noexcept，这对于 C++17 标准库的异常安全保证至关重要（C++20 支持 constexpr 移动函数）：

  • noexcept 的重要性：
    std::vector 在扩容时，仅当元素类型的移动构造函数带有 noexcept 声明时，才会采用移动方式迁移元素（高效且提供强异常安全保证）；若移动构造函数可能抛出异常，vector 将退化为拷贝方式（较慢，但保证原容器在扩容失败时保持不变）。

std::move

std::move 是定义于 <utility> 中的标准库工具函数（C++17/20 保持接口稳定，C++20 起支持 constexpr 使用）。其核心功能是将左值强制转换为右值引用，以触发移动语义（注意：std::move 本身不执行任何移动操作，仅“告知”编译器该对象可被移动）。

  • 注意事项
    • 被 std::move 转移资源后，原对象处于有效但未定义状态：可被安全析构或赋予新值，不应再读取其原有内容。
    • const 对象无法被移动：std::move(const_obj) 返回 const T&&，无法匹配 T&& 形参的移动构造函数，因此会退化为拷贝。

应用：完美转发

在泛型编程（模板）中，常常需要编写一个包装函数，将接收到的参数原封不动地转发给另一个函数。传统手段难以同时保留参数的值类别（左值/右值）：

  • 若使用 const T& 接收，所有参数都被视为左值，无法触发移动语义；
  • 若使用 T 按值接收，则会引发不必要的拷贝。

完美转发的目标是：将参数连同其左值/右值属性一并转发给下游函数。这依赖于右值引用的“引用折叠”规则（C++17 标准化推导规则，C++20 进一步优化了模板与模块中的适配性）。

  • 在模板中，T&& 被称为万能引用（或转发引用），可绑定左值或右值。万能引用的条件是：T 为模板参数，且形参类型严格为 T&&（无 const 修饰）。

    • 若传入左值，T 推导为 U&，经引用折叠 U& && → U&（左值引用）。
    • 若传入右值，T 推导为 U，T&& 保持为 U&&（右值引用）。

  • 非模板上下文中的 T&& 则是普通的右值引用。

引用折叠规则（C++17 标准）

当多个引用修饰符（& 与 &&）在模板实例化或类型别名中叠加时，编译器按以下规则简化为单一引用类型：

只要任一引用为左值引用（&），结果即为左值引用；只有全部为右值引用（&&），结果才为右值引用。

原始组合 折叠结果 说明
T& & T& 左值引用 + 左值引用 = 左值引用
T& && T& 左值引用 + 右值引用 = 左值引用
T&& & T& 右值引用 + 左值引用 = 左值引用
T&& && T&& 右值引用 + 右值引用 = 右值引用

std::forward

std::forward 是 C++11 引入的关键工具（C++17 优化实现，C++20 支持 constexpr），它与右值引用和引用折叠规则协同，实现完美转发——将函数参数原样转发给另一个函数，完整保留其左值/右值属性以及 const/volatile 限定。

std::forward 的本质是：根据模板参数 T 的推导结果，将参数“还原”为其原始值类别，从而解决“具名右值引用变量是左值”这一矛盾。

右值引用与其他特性

右值引用与异常安全

移动操作通常被声明为 noexcept，这对 C++17 标准库行为有决定性影响。

  • std::vector 扩容策略：
    • 若元素类型的移动构造函数为 noexcept，vector 将使用移动（高效且强异常安全）。
    • 若移动构造函数可能抛出异常，为保证强异常安全（扩容中途失败时原容器必须保持不变），vector 会退化为使用拷贝（较慢，但拷贝失败不会破坏原数据）。
  • C++20 中 constexpr 移动函数同样支持 noexcept 修饰。

C++17 强制拷贝消除（RVO）

C++17 将返回值优化（RVO） 提升为强制性标准，编译器会直接在调用方构造临时对象，消除多余的拷贝或移动操作，与移动语义互为补充，进一步提升性能。C++20 在此基础上进一步优化了临时对象的生命周期管理。

C++20 补充优化（概括）

C++20 进一步将 constexpr 支持扩展到移动构造函数、std::move 和 std::forward，允许在编译期使用移动语义；同时对模块、范围库（Ranges）中的完美转发机制进行了完善，使相关设施更加统一、高效。
