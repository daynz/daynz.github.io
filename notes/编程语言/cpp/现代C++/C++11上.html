委托与继承的构造函数

委托构造函数

  • 语法：在构造函数的初始化列表中，直接调用同类的其他构造函数（而非初始化成员变量）。

  • 核心规则：

    1. 委托构造函数不能同时初始化成员变量（初始化列表只能写委托的构造函数）；
    2. 委托构造函数的函数体在被委托的构造函数执行完成后才会执行；
    3. 不能形成构造函数委托环（如 A 委托 B，B 又委托 A），否则编译报错。

继承构造函数

  • 语法：using 基类名::基类名;（在派生类的公有区域声明）。

  • 核心规则：

    1. 继承的是基类的所有重载构造函数（除了拷贝 / 移动构造）；
    2. 派生类继承的构造函数会自动初始化基类部分，派生类新增的成员需通过类内初始值或其他方式初始化；
    3. 如果派生类自定义了与基类构造函数签名相同的构造函数，继承的构造函数会被覆盖（优先使用派生类自定义的）。

花括号或等号初始化器

C++11 引入了统一初始化语法（Uniform Initialization），核心是通过{}（花括号）或=结合{}的方式，为变量、对象、数组、容器等提供一致的初始化方式，解决了传统初始化（括号、等号混用）的语法歧义与不一致问题；而=初始化器则是对传统拷贝初始化的兼容与扩展。

初始化方式 语法示例 适用场景
花括号初始化（直接） T a{值}; / T a={值}; 所有类型（变量、对象、数组等）
等号 + 花括号（拷贝） T a = {值}; 兼容传统写法，等价于直接花括号
  • 核心特性与优势
    1. 消除语法歧义：解决了传统()初始化的 “最令人头痛的解析”（Most Vexing Parse）问题；
    2. 禁止窄化转换：花括号初始化会严格检查类型转换，不允许 “不安全的窄化”（如 double→int、int→char）；
    3. 统一适用所有类型：变量、数组、类对象、STL 容器、动态分配内存均可用{}初始化。

  • 类对象：空列表初始化调用默认构造函数；

范围 for

  • 核心规则：

    1. “可迭代对象” 需满足：有begin()/end()成员（或全局begin()/end()函数），且返回的迭代器支持++/*/!=操作；
    2. 遍历顺序：从第一个元素到最后一个元素，不可反向 / 跳步；
    3. 若需修改元素，需将 “变量名” 声明为引用（&）。

final 与 override

final

  • 作用
    • 禁止类继承（加在类名后）
    • 禁止虚函数重写（加在函数后）
  • 使用规则
    1. final 修饰类时，类的所有成员函数（包括虚函数）都无法被派生类重写；
    2. final 修饰虚函数时，仅禁止该函数被重写，类仍可被继承，其他函数可正常重写；
    3. final 不能用于非虚函数（无意义，编译器可能警告）。

overrider

  • 作用
    • 显式标记派生类中的函数是对基类虚函数的重写，编译器会强制检查：
      1. 基类中是否存在该签名的虚函数；
      2. 派生类函数的签名（返回值、参数、const/volatile 属性）是否与基类完全一致。若不满足，直接编译报错，避免 “意外重载而非重写” 的隐蔽错误。
  • 使用规则
    1. 仅能用于派生类的虚函数重写，非虚函数 / 基类函数加override会报错；
    2. override 是 “说明符”，不是函数签名的一部分，不影响函数重载；
    3. 推荐所有重写基类虚函数的场景都加override，强制编译器校验。

预置与弃置的函数

预置default

显式要求编译器生成该函数的默认版本，即使类中存在其他自定义构造 / 成员函数（打破 “自定义构造后编译器不生成默认构造” 的规则）。

default 仅能用于编译器可自动生成的特殊成员函数（默认构造、析构、拷贝 / 移动构造 / 赋值）

弃置delete

显式禁止编译器生成某个函数（通常是拷贝构造、赋值运算符），也可用于禁止特定重载版本的函数，比传统 “私有化且不实现” 更直观、更安全。

delete 可用于任意函数（特殊成员函数 / 普通函数），不限于编译器自动生成的函数；被 delete 的函数仍会参与重载决议，但选中后会直接编译报错；

应用

  • 禁止类的拷贝 / 移动
  • 禁止特定重载版本的函数
  • 禁止隐式类型转换

有作用域枚举

有作用域枚举（也叫强类型枚举，enum class/enum struct）是 C++11 对传统枚举（enum）的升级，核心解决了传统枚举的作用域污染、隐式类型转换、底层类型不固定三大问题，让枚举类型更安全、更规范。

  • 特性
    • 作用域隔离，避免命名冲突。枚举值不再暴露到全局作用域，必须通过枚举名::枚举值访问
    • 禁止隐式类型转换，强类型安全。有作用域枚举的枚举值不能直接转换为整数，也不能与整数比较，必须显式转换
    • 显式指定底层类型，提升跨平台一致性
    • 可前置声明（传统枚举需指定底层类型才能前置声明）
特性 传统枚举（enum） 有作用域枚举（enum class）
作用域 枚举值暴露到全局 枚举值仅在枚举作用域内
类型转换 隐式转换为整数 禁止隐式转换，需显式 cast
底层类型 编译器自动选择 默认 int，可显式指定
命名冲突 不同枚举不能有同名值 支持同名值，无冲突
前置声明 需指定底层类型 可直接前置声明

类型别名

C++11 对 “类型别名” 提供了两种方式：传统的 typedef 和新增的 using 别名声明（using = 语法）。其中 using 是对 typedef 的升级，解决了 typedef 在模板场景下的语法缺陷，核心目的是为复杂类型（如指针、数组、模板）起简洁、易读的别名，提升代码可读性和维护性。

typedef 的核心缺陷：typedef 无法直接为模板类型起别名（需借助模板特化，语法繁琐）

场景 typedef 写法 using 写法（推荐）
基本类型 typedef int Int; using Int = int;
指针类型 typedef int* IntPtr; using IntPtr = int*;
模板类型（C++11） 不支持（需模板特化） template<typename T> using Vec = vector<T>;
  • 模板别名（类型别名模板）：using 可直接为模板类型起别名，无需模板特化
  • 简化嵌套命名空间 / 类的类型
  • 与尾置返回类型配合（简化函数返回类型）
特性 typedef using（C++11）
基本类型别名 支持 支持（语法更直观）
复杂类型别名（指针 / 数组） 支持（语法反直觉） 支持（语法更清晰）
模板别名（类型别名模板） 不支持（需模板特化） 原生支持（核心优势）
可读性 差（别名在末尾） 优（“别名 = 原类型” 符合直觉）

变参数模板

变参数模板是 C++11 引入的核心特性，允许模板接受数量不确定、类型不确定的模板参数（包括类型参数和非类型参数），彻底解决了传统模板 “参数数量固定” 的限制，是实现泛型可变参数功能（如std::tuple、std::make_shared）的基础。

核心概念与语法

  • 变参数模板的核心是参数包（Parameter Pack）
  • 类型参数包：typename... Args / class... Args，表示任意数量（0 个或多个）的类型参数；
  • 非类型参数包：T... Args（T 为非类型类型，如 int、指针），表示任意数量的非类型参数；
  • 展开参数包：通过...运算符将参数包 “展开” 为单个参数，是变参数模板的核心操作。

核心使用场景与实现原理

变参数模板函数（递归展开）

  • （递归展开）最基础的参数包展开方式，分为两步：
    1. 递归函数：处理参数包的第一个参数，剩余参数递归传递；
    2. 终止函数：处理参数包为空的情况（递归出口）。

变参数模板类（递归特化）

C++17 折叠表达式（简化参数包展开）

C++17 引入折叠表达式（Fold Expression），无需递归即可展开参数包，语法大幅简化，支持+/*/,/&&/||等运算符。

变参数模板与 std::forward（完美转发）

变参数模板常与std::forward结合，实现完美转发（保留参数的左值 / 右值属性），是std::make_shared、std::emplace_back的核心实现原理。

变参数模板的核心规则

  • 参数包的限制：

    • 参数包必须是模板参数列表的最后一个参数（如template <typename T, typename... Args>合法，template <typename... Args, typename T>非法）；

    • 参数包可包含 0 个参数（如print()调用终止函数）；

  • 展开时机：参数包仅能通过...展开，未展开的参数包无法直接使用；

  • 兼容性：递归展开兼容 C++11/14，折叠表达式仅支持 C++17 及以上；

  • 非类型参数包：支持数值、指针、引用等非类型参数，示例：

    • // 非类型参数包（int类型）
template <int... N>
int sum_nums() {
    return (N + ...); // C++17折叠表达式
}

nullptr

nullptr 是 C++11 引入的专门用于表示 “空指针” 的关键字，核心解决了传统 C++ 中用 NULL/0 表示空指针的类型歧义问题，让空指针的表达更精准、类型更安全。

在 C++11 前，程序员通常用 NULL 或 0 表示空指针，但二者存在严重的类型歧义：

  • NULL 本质是宏定义，通常展开为 0（整数）或 ((void*)0)（void 指针）；
  • 在函数重载、模板推导等场景中，0/NULL 会被解析为整数而非指针，导致不符合预期的行为。
  • 0/NULL 是整数类型，而非指针类型，编译器优先匹配int重载版本，违背了 “传递空指针” 的本意。

基本定义与类型

  • nullptr 是 C++11 关键字，专属表示 “空指针”，其类型为 std::nullptr_t（一种独立的指针类型）；
  • nullptr_t 可隐式转换为任意指针类型（如char*、int*、void*），但不能转换为整数类型，彻底解决类型歧义。
特性 0（整数） NULL（宏） nullptr（C++11 关键字）
类型 int（整数） 通常为 int（0）或 void* std::nullptr_t（指针类型）
隐式转换 可转换为任意整数 / 指针 可转换为整数 / 指针（歧义） 仅转换为指针类型（无歧义）
函数重载匹配 优先匹配 int，不匹配指针 同 0（歧义） 仅匹配指针重载

语义 整数 0（非专属空指针） 空指针的 “妥协表示” 专属空指针（语义精准）
