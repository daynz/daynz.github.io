三、编译期特性

这类特性将计算 / 检查逻辑提前到编译阶段，减少运行期开销、提前暴露错误：

constexpr 与字面类型

constexpre

constexpr的核心目标是：强制表达式在编译期求值，让 “常量计算” 从运行时提前到编译期

基本定义与核心规则

constexpr 修饰的变量 / 函数满足：

  • 变量：编译期初始化，值不可变，可用于所有编译期常量场景（数组长度、模板参数、枚举值等）；
  • 函数：编译期可调用，返回值可作为编译期常量（需满足 “纯 constexpr 条件”）；
  • C++11 对constexpr函数限制严格（单返回语句），C++14 放宽为 “可包含多条语句、局部变量”。
特性 constexpr const
核心语义 编译期常量 / 编译期可计算 运行时常量（不可修改）
变量初始化 必须编译期表达式初始化 可编译期 / 运行期初始化
函数 支持（编译期可调用） 不支持（仅修饰成员函数）
类构造函数 支持（编译期创建对象） 不支持
适用场景 编译期常量（数组长度、模板参数）、编译期计算 运行时常量（不可修改的变量）

字面类型

「字面类型」是能用于constexpr上下文的类型，即：该类型的对象可在编译期创建、初始化、计算。C++11 定义了以下几类字面类型：

类型类别 示例 核心条件
基本类型 int、double、char、bool 所有基本类型都是字面类型
指针 / 引用类型 int*、const char& 指针指向编译期可见的内存（如全局变量、字符串字面量），引用绑定到字面类型对象
聚合类型（数组 / 结构体） int[5]、struct {int x; int y;} 所有成员都是字面类型，无虚函数、无虚基类
带 constexpr 构造的类 上文的 Point 类 有 constexpr 构造函数，所有非静态成员都是字面类型，无虚函数

字面类型的判定条件（C++11）

一个类型是字面类型，需满足：

  1. 有平凡的析构函数（编译器自动生成，或= default）；
  2. 满足以下条件之一：
    • 是标量类型（基本类型、指针、引用、枚举）；
    • 是聚合类型（数组、无自定义构造 / 析构 / 赋值、无虚函数的结构体 / 类）；
    • 是带constexpr构造函数的类，且所有非静态数据成员 / 基类都是字面类型。

编译期断言static_assert（基于 Boost 库）

static_assert 是 C++11 引入的编译期断言机制，核心作用是在编译阶段检查常量表达式的真假，若条件不满足则直接终止编译并输出自定义错误信息。它解决了传统运行时断言（assert）的局限性 ——assert 仅在运行时触发，且 Release 模式下可能被禁用，而static_assert 能在编译期暴露问题，更早发现错误。

传统断言（assert）核心问题：

  1. assert 是运行时断言，编译阶段无法发现错误；
  2. Release 模式下NDEBUG宏会禁用assert，导致错误被隐藏；
  3. 仅能检查运行时表达式，无法检查编译期常量（如模板参数、数组长度）。

static_assert 核心语法与规则

核心规则：

  1. 第一个参数必须是编译期可计算的常量表达式（如constexpr变量、字面量、模板参数）；
  2. 若表达式为true，编译正常通过；若为false，编译终止并输出错误信息；
  3. static_assert 可出现在全局作用域、命名空间、类、函数等任意位置（无作用域限制）；
  4. 错误信息字符串是编译期常量（C++11 要求字符串字面量，C++17 放宽为任意常量表达式）。

应用

  • 检查模板参数（最常用）static_assert 是模板编程的 “安全卫士”，可强制模板参数满足特定条件
  • 检查编译环境 / 编译器特性
  • 检查类 / 类型特性
  • 与 constexpr 结合（编译期计算后断言）
特性 static_assert（静态断言） assert（运行时断言）
检查时机 编译期 运行期
检查条件 仅支持编译期常量表达式 支持运行时表达式
生效范围 所有编译模式（Debug/Release） 仅 Debug 模式（Release 禁用）
错误处理 终止编译，输出自定义信息 触发后终止程序，输出默认信息
作用域 全局 / 命名空间 / 类 / 函数均可 仅函数内
性能影响 无（编译期处理） Debug 模式有轻微开销

进阶：C++17 扩展

C++17 对static_assert做了小幅扩展：

  • 允许省略错误信息字符串（仅保留常量表达式）
  • 错误信息支持非字符串字面量的常量表达式（如constexpr字符串）

alignof 与 alignas（编译期确定内存对齐）

alignof（对齐值查询）和 alignas（对齐值指定）是 C++11 引入的关键字，用于编译期控制和查询内存对齐。内存对齐是计算机硬件的底层要求（如 CPU 读取数据时按固定字节数对齐更高效）。

C++11 前只能通过编译器扩展（如 GCC 的__attribute__((aligned))、MSVC 的__declspec(align)）控制对齐，而alignof / alignas是标准化的解决方案，跨平台更通用。

功能 C++11 标准语法 GCC 扩展 MSVC 扩展
查询对齐值 alignof(T) __alignof__(T) __alignof(T)
指定对齐值 alignas(n) __attribute__((aligned(n))) __declspec(align(n))

内存对齐的基础概念

先理解 “内存对齐” 的核心：

  • 对齐值（Alignment）：一个类型 / 变量的对齐值是其内存地址必须是该值的整数倍（如int的对齐值通常为 4，即int变量的地址必须是 4 的倍数）；
  • 自然对齐：编译器默认的对齐规则（如基本类型的对齐值等于其大小，char=1、int=4、double=8）；
  • 过度对齐（Over-alignment）：手动指定比自然对齐更大的对齐值（如将int对齐到 16 字节），用于硬件加速（如 SIMD 指令）、内存映射等场景。

alignof（查询对齐值）

  • alignof 接收类型（如int、struct A）或表达式（如变量名），返回该类型 / 变量的最小对齐值（编译期常量，类型为std::size_t）；
  • 结果是编译期可计算的常量，可用于constexpr、static_assert、模板参数等编译期场景；
  • 对于数组，alignof(数组类型) 等于数组元素类型的对齐值；
  • 对于引用，alignof(引用类型) 等于被引用类型的对齐值。

alignof vs sizeof（核心区别）

  • sizeof：返回类型 / 变量占用的总字节数（包含填充字节）；
  • alignof：返回类型 / 变量的最小对齐值（地址需是该值的整数倍）。

alignas（指定对齐值）

  • alignas 的参数必须是2 的幂次（如 1、2、4、8、16，否则编译报错）；
  • 若同时指定多个alignas，编译器取最大的对齐值；
  • 不能指定比编译器默认对齐值更小的对齐值（仅能增大或等于）；
  • 可用于变量、结构体 / 类、数组、枚举等，不可用于函数 / 参数。

noexcept 说明符

noexcept 说明符是 C++11 引入的特性，用于显式声明函数是否会抛出异常，核心作用是给编译器提供异常行为的提示，帮助编译器优化代码（如移动构造 / 赋值的优化），同时明确函数的异常安全契约。

核心作用

  • 明确异常契约，提升代码可读性
  • 编译器优化
    • 省略异常处理代码：noexcept 函数内部无需生成栈展开（stack unwinding）的异常处理逻辑，执行效率更高；
    • 容器优先使用移动操作：std::vector/std::string 等容器在扩容、元素移动时，若元素的移动构造 / 赋值函数标记为 noexcept，容器会优先选择移动而非拷贝；若未标记，容器会退化为拷贝（避免移动过程中抛异常导致数据丢失）。
  • 违反 noexcept 契约的后果
    • 若标记为 noexcept 的函数实际抛出了异常，C++ 标准规定会直接调用 std::terminate() 终止程序（而非栈展开），因此必须确保 noexcept 函数内不会抛异常。

noexcept 说明符的使用场景

  • 移动构造 / 移动赋值函数：让容器 / 算法优先使用移动，避免退化为拷贝
  • 析构函数：C++11 后析构函数默认隐式 noexcept (true)，无需手动写（除非显式声明 noexcept (false)）
  • 简单访问器（getter/setter）
  • 资源释放函数：释放资源不能抛异常，否则会导致内存泄漏 / 资源泄漏

noexcept 运算符

noexcept 运算符是编译期表达式，用于判断 “某个表达式是否会抛出异常”，返回布尔常量（true/false），常和模板、条件编译结合使用。

  • 结果：若表达式在编译期确定不会抛异常，返回 true；否则返回 false；
  • 特性：不会执行表达式，仅做编译期类型检查。

核心用法

  • 动态标记函数的 noexcept 说明符，可让函数的异常契约 “跟随其他函数”

    • // 模板函数：异常契约跟随 Func 的调用结果
template <typename Func, typename... Args>
auto Wrapper(Func&& func, Args&&... args) 
    noexcept(noexcept(func(std::forward<Args>(args)...))) // 动态判断
-> decltype(func(std::forward<Args>(args)...)) {
    return func(std::forward<Args>(args)...);
}

// 测试函数1：不抛异常
void Func1() noexcept {}
// 测试函数2：可能抛异常
void Func2() {}

int main() {
    // 编译期判断：Wrapper(Func1) 是 noexcept(true)
    static_assert(noexcept(Wrapper(Func1)), "Wrapper(Func1) should be noexcept");
    // 编译期判断：Wrapper(Func2) 是 noexcept(false)
    static_assert(!noexcept(Wrapper(Func2)), "Wrapper(Func2) should not be noexcept");
    return 0;
}

  • 判断标准库函数的异常行为

    • // 判断 std::vector<int>::push_back 是否 noexcept（取决于元素类型）
std::vector<int> vec;
static_assert(noexcept(vec.push_back(10)), "push_back 是 noexcept"); // 成立
// 判断 std::vector<int>::resize 是否 noexcept（可能抛内存异常，不成立）
static_assert(!noexcept(vec.resize(100)), "resize 不是 noexcept");
