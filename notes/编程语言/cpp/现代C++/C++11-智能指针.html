智能指针基础

本质是封装了原生指针的类模板，核心目标是自动管理内存，避免手动 new/delete 导致的内存泄漏、野指针、重复释放等问题。

它遵循 RAII（资源获取即初始化）原则，利用对象的生命周期（构造时获取资源，析构时释放资源）来保证内存安全。其核心逻辑：

  • 构造时：接管原始指针的所有权，申请动态资源；
  • 析构时：自动释放接管的资源（无需手动调用 delete）；
  • 使用时：重载 operator* 和 operator->，行为与原始指针一致。
手动管理内存的问题 智能指针的解决方案
忘记 delete 导致内存泄漏 析构函数自动调用 delete
多次 delete 导致双重释放 所有权管理（独占 / 共享），确保资源仅释放一次
指针悬空（野指针） 析构时置空指针，弱指针检测资源是否有效
异常安全问题 析构函数在栈展开时自动执行，保证资源释放

std::unique_ptr（独占式智能指针）

std::unique_ptr 是通过指针占有并管理另一对象，并在 unique_ptr 离开作用域时释放该对象的智能指针。

std::unique_ptr表示对资源的唯一所有权。同一时间，只能有一个 unique_ptr 指向该对象。

发生下列两者之一时用关联的删除器释放对象：

  • 销毁了管理的 unique_ptr 对象
  • 通过 operator= 或 reset() 赋值另一指针给管理的 unique_ptr 对象。

Deleter 必须是 函数对象 或到 函数对象的左值引用或到函数的左值引用，可以 unique_ptr<T, Deleter>::pointer 类型参数调用

特性：

  • 独占所有权：同一时刻，只有一个 unique_ptr 能指向某一资源，不支持拷贝（copy），仅支持移动（move）；
  • 不可拷贝：拷贝构造函数和拷贝赋值运算符被删除（= delete）。你不能复制一个 unique_ptr。
  • 可移动：支持移动语义（Move Semantics）。所有权可以通过 std::move 转移给另一个 unique_ptr。
  • 零开销：在大小和行为上与普通裸指针几乎无异，没有引用计数的开销。
  • 自动释放：离开作用域或调用 reset() 时自动 delete 对象。
  • 支持自定义删除器：可指定资源释放的方式（如释放数组、文件句柄）。

关键说明

  • 禁止拷贝：std::unique_ptr<MyClass> ptr4 = ptr2; 会编译报错，因为拷贝构造函数被禁用。

  • 适用场景：单个对象的独占管理（如函数返回值、局部动态对象、容器中的独占元素）。

  • 容器支持：可作为 std::vector 等容器的元素（因为支持移动）。

  • 自定义删除器：适用于非 new 申请的资源（如 malloc、文件句柄）：

    • // 自定义删除器：释放 malloc 申请的内存
auto del = [](int* p) { free(p); cout << "释放 malloc 内存\n"; };
unique_ptr<int, decltype(del)> p5((int*)malloc(4), del);

  • 避免裸指针重复构造，用裸指针构造两个 shared_ptr（例如 shared_ptr<int> p1(new int(1)); shared_ptr<int> p2(p1.get());），p1.get() 的作用是仅返回 p1 管理的原始指针，这会导致双重释放。应该始终从同一个 shared_ptr 拷贝，或使用 make_shared。

  • 避免循环引用：如果两个对象互相持有对方的 shared_ptr，引用计数永远无法归零，导致内存泄漏。需用 weak_ptr 解决。

std::weak_ptr（弱引用智能指针）

weak_ptr 是 shared_ptr 的辅助工具。它不拥有对象，不增加引用计数。主要用于解决 shared_ptr 的循环引用问题，或者作为“观察者”检查对象是否还存在。

特性：

  • 弱引用：不拥有资源所有权，仅观察 shared_ptr 管理的资源；
  • 不控制生命周期：它的存在与否不影响对象的销毁。
  • 不影响引用计数：创建 / 拷贝 weak_ptr 不会增加 shared_ptr 的引用计数；
  • 不能直接解引用：必须先通过 lock() 提升为 shared_ptr。
  • 检查有效性：expired() 方法可判断对象是否已被销毁。

关键方法

  • 不能直接解引用：weak_ptr 无 operator* 和 operator->，需通过 lock() 转为 shared_ptr 后使用；

  • lock()：将 weak_ptr 转换为 shared_ptr，如果对象已销毁，返回空的 shared_ptr（安全访问对象的核心方法）；

  • expired()：检查所指向的对象是否已销毁（引用计数为 0），返回 bool。

智能指针的最佳实践

  1. 优先使用 make_unique/make_shared：

    • 避免直接用 new 创建智能指针，make_xxx 更安全（防止异常导致内存泄漏），且 make_shared 会一次性分配对象内存和引用计数内存，效率更高。
    • 异常安全：new T 和 shared_ptr 构造是分开的两步。如果 new 成功后，构造 shared_ptr 前抛出异常，内存会泄漏。make_shared 是一步完成的，完全异常安全。
    • 性能：make_shared 会将对象和控制块分配在同一块内存中，减少一次堆分配，提高缓存命中率。

  2. 避免混合使用智能指针和原生指针：

    • 不要用原生指针访问智能指针管理的对象，更不要手动 delete 智能指针管理的原生指针（会导致重复释放）。

  3. 自定义删除器:智能指针不仅限于 delete。你可以传入自定义删除器来管理文件、Socket、数据库连接等资源。

    • // 管理 FILE*
auto fileDeleter = [](FILE* f) { if(f) fclose(f); };
std::unique_ptr<FILE, decltype(fileDeleter)> fp(fopen("test.txt", "r"), fileDeleter);
// fp 离开作用域自动 fclose

线程安全

unique_ptr本身不提供线程安全保证：

  • 由于独占所有权，多线程下无需同步引用计数；
  • 若需在多线程间转移所有权，需用户自行保证同步。

shared_ptr的内存布局

每个shared_ptr对象仅包含两个指针（内存开销为两个指针大小）：

  1. 指向管理对象的原始指针（用于operator*、operator->）；
  2. 指向控制块的指针（用于管理引用计数）。

关键操作的实现逻辑

构造函数

  • 若通过原始指针构造（shared_ptr<T> p(new T)）：分配新的控制块，强引用计数初始化为 1；
  • 若通过拷贝构造（shared_ptr<T> p = q）：共享同一控制块，强引用计数 + 1（原子操作）；
  • 若通过移动构造（shared_ptr<T> p = std::move(q)）：转移控制块所有权，原shared_ptr置空，引用计数不变。

析构函数

  • 强引用计数 - 1（原子操作）；
  • 若强引用计数降为 0：
    1. 调用删除器销毁对象；
    2. 弱引用计数 - 1；
    3. 若弱引用计数也为 0：释放控制块。

删除器的类型擦除

与unique_ptr不同，shared_ptr的删除器不是模板参数的一部分，而是通过类型擦除存储在控制块中（使用std::function或虚函数）。这使得：

  • 不同删除器的shared_ptr<T>可互相赋值（只要指向同一类型T）；
  • 删除器可在运行时动态指定，灵活性更高。

优化与异常安全

make_shared<T>(args...)是创建shared_ptr的推荐方式，优势在于：

  1. 内存分配优化：一次性分配对象和控制块的内存（减少一次内存分配，提升性能）；
  2. 异常安全：若对象构造失败，控制块也会被自动释放，避免内存泄漏。

线程安全

shared_ptr的线程安全分为两层：

  1. 引用计数的线程安全：强 / 弱引用计数的增减通过原子操作（std::atomic）实现，多线程下拷贝 / 销毁shared_ptr无需同步；
  2. 对象访问的线程安全：shared_ptr不保护对象本身的线程安全，若多线程同时读写同一对象，需用户自行加锁。

定义

实现原理

weak_ptr与shared_ptr共享同一控制块，但仅影响弱引用计数：

  • 当shared_ptr构造weak_ptr时，弱引用计数 + 1；
  • 当weak_ptr析构时，弱引用计数 - 1；
  • 当强引用计数降为 0 时，对象被销毁，但控制块需等弱引用计数也为 0 才释放。

关键操作

lock()：获取shared_ptr

weak_ptr不能直接访问对象，需通过lock()方法获取有效的shared_ptr：

  • 若对象未被销毁：返回指向该对象的shared_ptr（强引用计数 + 1）；
  • 若对象已被销毁：返回空的shared_ptr。

expired()：检查对象是否销毁

expired()等价于lock() == nullptr，但更高效（不增加引用计数）。
