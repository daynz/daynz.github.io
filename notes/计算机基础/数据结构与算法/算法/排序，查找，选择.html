1. 冒泡排序

思路

重复遍历数组，依次比较相邻元素，若顺序错误则交换；每一轮遍历会将当前未排序部分的最大元素“冒泡”到末尾；加入标志位优化，若某轮无交换则说明数组已有序，提前终止，减少不必要的遍历。

代码

重点

  • 时间复杂度：平均/最坏 O(n2)O(n^2)O(n2)，最好（近乎有序）O(n)O(n)O(n)；
  • 空间复杂度 O(1)O(1)O(1)，稳定排序、原地排序；
  • 核心优化点是“交换标志位”，避免对已排序数组的无效遍历；
  • 仅适用于小规模或几乎有序的数据排序。

2. 选择排序

思路

将数组分为“已排序区”和“未排序区”，每轮从未排序区找到最小（大）元素，与未排序区的第一个元素交换；逐步扩大已排序区，直到整个数组有序。

代码

重点

  • 时间复杂度：平均/最坏/最好均为 O(n2)O(n^2)O(n2)，无最优情况；
  • 空间复杂度 O(1)O(1)O(1)，不稳定排序、原地排序；
  • 交换次数少（最多 n−1n-1n−1 次），适合交换成本高的场景；

3. 插入排序

思路

将数组分为“已排序区”和“未排序区”，依次取未排序区的元素，插入到已排序区的合适位置（从后往前比较，大于当前元素则后移）；直到所有元素插入完成。

代码

重点

  • 时间复杂度：平均/最坏 O(n2)O(n^2)O(n2)，最好（近乎有序）O(n)O(n)O(n)；
  • 空间复杂度 O(1)O(1)O(1)，稳定排序、原地排序；
  • 对近乎有序的小规模数据效率极高，是希尔排序的基础；
  • 插入过程仅移动元素，无频繁交换，实际执行效率优于冒泡/选择排序。

4. 希尔排序

思路

插入排序的改进版，核心是“分组插入排序”：先将数组按步长 gap 分组，对每组进行插入排序；逐步缩小步长（通常减半），直到步长为1，此时数组已基本有序，最后做一次普通插入排序。

代码

重点

  • 时间复杂度：平均 O(n1.3)O(n^{1.3})O(n1.3)，最坏 O(n2)O(n^2)O(n2)，最好 O(n)O(n)O(n)；
  • 空间复杂度 O(1)O(1)O(1)，不稳定排序、原地排序；
  • 步长选择影响效率，常用步长序列：n/2,n/4,...,1n/2, n/4,...,1n/2,n/4,...,1；
  • 相比简单排序，对中等规模数据效率提升显著。

5. 快速排序

思路

分治思想：选一个“基准值”，将数组分为“小于基准”和“大于基准”两部分，基准归位；递归对左右子数组重复上述操作，直到子数组长度为1（天然有序）。优化：选基准时用“三数取中法”（避免最坏情况），小规模子数组改用插入排序。

代码

重点

  • 时间复杂度：平均/最好 O(nlog⁡n)O(n\log n)O(nlogn)，最坏（已排序数组，未优化）O(n2)O(n^2)O(n2)；
  • 空间复杂度 O(log⁡n)O(\log n)O(logn)（递归栈），不稳定排序、原地排序；
  • 工程中首选的通用排序算法，优化后可避免最坏情况；
  • 分区操作是核心，基准归位后左右子数组独立排序。

6. 归并排序

思路

分治思想：将数组递归拆分为两个子数组，直到子数组长度为1；然后将两个有序子数组合并为一个有序数组，逐层合并直到整个数组有序。合并过程需要额外空间存储临时数据。

代码

重点

  • 时间复杂度：平均/最坏/最好均为 O(nlog⁡n)O(n\log n)O(nlogn)，性能稳定；
  • 空间复杂度 O(n)O(n)O(n)（临时数组），稳定排序、非原地排序；
  • 适合链表排序（无需额外空间）、外部排序（数据量超内存）；
  • 合并操作是核心，需保证合并过程的稳定性（arr[i] <= arr[j] 而非 <）。

7. 堆排序

思路

利用“最大堆”的特性（根节点是最大值）：先将数组构建为最大堆；然后依次将堆顶（最大值）与堆尾元素交换，缩小堆的范围并重新调整堆结构；直到堆的范围为1，数组有序。

代码

重点

  • 时间复杂度：平均/最坏/最好均为 O(nlog⁡n)O(n\log n)O(nlogn)，性能稳定；
  • 空间复杂度 O(1)O(1)O(1)，不稳定排序、原地排序；
  • 适合大规模数据且要求原地排序的场景；
  • 构建堆的时间复杂度为 O(n)O(n)O(n)，调整堆的时间复杂度为 O(log⁡n)O(\log n)O(logn)。

8. 计数排序

思路

适用于整数且取值范围小的场景：先统计每个数值出现的次数；然后根据次数计算每个数值的最终位置；最后反向填充数组，保证稳定性。

代码

重点

  • 时间复杂度：平均/最坏/最好均为 O(n+k)O(n+k)O(n+k)（kkk 为数值范围）；
  • 空间复杂度 O(n+k)O(n+k)O(n+k)，稳定排序、非原地排序；
  • 仅适用于整数且 kkk 较小时（如成绩排序、年龄排序）；
  • 反向填充是保证稳定性的关键，避免相同元素相对位置改变。

9. 桶排序

思路

将数据分配到多个“桶”中，每个桶内单独排序（可用插入排序）；最后按桶的顺序合并所有桶的元素。核心是数据分布均匀，否则退化为 O(n2)O(n^2)O(n2)。

代码

重点

  • 时间复杂度：平均/最好 O(n)O(n)O(n)，最坏（数据集中在一个桶）O(n2)O(n^2)O(n2)；
  • 空间复杂度 O(n+k)O(n+k)O(n+k)（kkk 为桶数），稳定排序、非原地排序；
  • 适合数据分布均匀的场景（如均匀分布的浮点数、整数）；
  • 桶的数量和范围需根据数据分布调整，是效率的关键。

10. 基数排序

思路

按“位”排序（个位、十位、百位…），每一位用计数排序/桶排序实现；从最低位到最高位依次排序，最终得到有序数组。适用于整数或字符串（按字符位）。

代码

重点

  • 时间复杂度：平均/最坏/最好均为 O(n×k)O(n×k)O(n×k)（kkk 为最大位数）；
  • 空间复杂度 O(n+k)O(n+k)O(n+k)，稳定排序、非原地排序；
  • 适合整数、字符串（按字符ASCII码）排序；
  • 必须从低位到高位排序，且每一位的排序需保证稳定性。

11. 模拟C++ std::sort（introsort）

思路

std::sort 是混合排序算法（introsort）：核心是快速排序，当递归深度超过阈值（2×log⁡2n2×\log_2n2×log2​n）时切换为堆排序，小规模子数组改用插入排序；保证最坏时间复杂度 O(nlog⁡n)O(n\log n)O(nlogn)。

重点

  • 时间复杂度：平均/最坏/最好均为 O(nlog⁡n)O(n\log n)O(nlogn)，无最坏 O(n2)O(n^2)O(n2) 情况；
  • 空间复杂度 O(log⁡n)O(\log n)O(logn)（递归栈），不稳定排序、原地排序；
  • C++标准库默认实现，是通用场景的最优选择；
  • 混合了快速排序（高效）、堆排序（避免最坏情况）、插入排序（小规模优化）。

1. 顺序查找 (Linear Search)

思路

从数组/容器的第一个元素开始，逐个遍历并与目标值比较，找到则返回索引；遍历结束未找到则返回-1。无数据有序性要求，逻辑最简单。

代码

重点

  • 时间复杂度：平均/最坏 O(n)O(n)O(n)，最好（目标在首位）O(1)O(1)O(1)；
  • 空间复杂度 O(1)O(1)O(1)，原地查找，无额外空间；
  • 数据无任何要求（有序/无序均可），适配链表、数组等任意线性结构；
  • 缺点是效率低，仅适合小规模数据或单次查找场景。

2. 二分查找 (Binary Search)

思路

仅适用于有序数组：取数组中间元素与目标值比较，若目标值更小则在左半区间继续查找，若更大则在右半区间查找；重复缩小查找范围，直到找到目标或区间为空。

代码

重点

  • 时间复杂度：平均/最坏 O(log⁡n)O(\log n)O(logn)，最好（目标在中间）O(1)O(1)O(1)；
  • 空间复杂度 O(1)O(1)O(1)（迭代版），递归版为 O(log⁡n)O(\log n)O(logn)（递归栈）；
  • 核心要求：数据有序且支持随机访问（数组），链表无法高效实现；
  • 优势是查找效率极高，适合静态有序数组（查找频繁、修改少）。

3. 插值查找 (Interpolation Search)

思路

二分查找的优化版，适用于有序且分布均匀的数组：不再固定取中间值，而是根据目标值的位置动态计算查找点（类似数轴插值），公式为：

pos=left+(target−arr[left])×(right−left)arr[right]−arr[left]pos = left + \frac{(target - arr[left]) \times (right - left)}{arr[right] - arr[left]} pos=left+arr[right]−arr[left](target−arr[left])×(right−left)​

分布均匀时，查找点更接近目标，效率远高于二分查找；分布不均时退化为顺序查找。

代码

重点

  • 时间复杂度：平均 O(log⁡log⁡n)O(\log \log n)O(loglogn)，最坏（分布极不均）O(n)O(n)O(n)，最好 O(1)O(1)O(1)；
  • 空间复杂度 O(1)O(1)O(1)，原地查找；
  • 核心要求：数组有序且数值分布均匀（如 1,2,3,4… 或 10,20,30…）；
  • 适合大规模均匀分布的有序数组，比二分查找减少查找次数。

4. 斐波那契查找 (Fibonacci Search)

思路

二分查找的变种，利用斐波那契数列分割区间：用斐波那契数 F[k]F[k]F[k] 确定查找点（mid=left+F[k−1]−1mid = left + F[k-1] - 1mid=left+F[k−1]−1），避免二分查找的除法运算（仅用加减法），更适配硬件底层；同时内存访问局部性更好，缓存命中率更高。

代码

重点

  • 时间复杂度：平均/最坏 O(log⁡n)O(\log n)O(logn)，最好 O(1)O(1)O(1)；
  • 空间复杂度 O(1)O(1)O(1)（可优化斐波那契数列生成，仅保留前两个值）；
  • 核心优势：仅用加减法，无除法/乘法，硬件执行效率更高；内存访问局部性好；
  • 适用场景：对运算效率（如嵌入式系统）、缓存命中率有要求的有序数组查找。

5. 哈希查找 (Hash Search)

思路

核心是“空间换时间”：先构建哈希表（键=数组元素，值=元素索引），查找时直接通过哈希函数计算目标值的哈希地址，访问哈希表即可得到结果；处理哈希冲突采用链地址法（每个哈希桶存储链表）。

重点

  • 时间复杂度：平均 O(1)O(1)O(1)，最坏（所有元素哈希冲突）O(n)O(n)O(n)，最好 O(1)O(1)O(1)；
  • 空间复杂度 O(n)O(n)O(n)（哈希表占用额外空间）；
  • 核心优势：查找速度极快，是高频查找场景的最优选择；
  • 注意事项：哈希函数设计（避免冲突）、冲突处理（链地址法/开放寻址法）；
  • 适用场景：高频查找、允许额外空间、对速度要求极高的场景（如缓存、数据库索引）。

6. 分块查找 (Block Search)

思路

结合顺序查找和二分查找的优点：将数组分为若干块，要求块间有序、块内无序；先构建“块索引表”（存储每块的最大值和块起始位置），查找时先二分/顺序查找索引表确定目标所在块，再在块内顺序查找。

代码

重点

  • 时间复杂度：平均 O(n)O(\sqrt{n})O(n​)，最坏 O(n)O(n)O(n)（目标在最后一块且块内全遍历），最好 O(1)O(1)O(1)；
  • 空间复杂度 O(1)O(1)O(1)（仅存储块索引表，可忽略）；
  • 核心要求：块间有序、块内无序，块大小需合理（通常取 n\sqrt{n}n​）；
  • 优势：支持动态插入删除（只需调整对应块），适合数据量较大且动态变化的场景。

7. 二叉搜索树查找 (BST Search)

思路

二叉搜索树（BST）特性：左子树所有节点值 < 根节点值，右子树所有节点值 > 根节点值；查找时从根节点开始，目标值小于当前节点则递归/迭代查左子树，大于则查右子树，等于则找到；最坏情况（树退化为链表）效率极低。

重点

  • 时间复杂度：平均 O(log⁡n)O(\log n)O(logn)，最坏（树退化）O(n)O(n)O(n)，最好 O(1)O(1)O(1)；
  • 空间复杂度 O(h)O(h)O(h)（hhh 为树高，迭代版 O(1)O(1)O(1)，递归版 O(h)O(h)O(h)）；
  • 核心特性：支持动态插入/删除，天然适合动态数据集；
  • 缺点：未平衡的BST可能退化，实际开发中优先用平衡树（如下文AVL/红黑树）。

8. 平衡树查找 (AVL树，红黑树简化版)

思路

AVL树是自平衡二叉搜索树，要求任意节点的左右子树高度差不超过1；插入/删除时通过旋转（左旋/右旋）保持平衡，保证查找效率稳定在 O(log⁡n)O(\log n)O(logn)；以下实现简化版AVL树查找（核心逻辑与红黑树一致，均为平衡BST）。

重点

  • 时间复杂度：平均/最坏 O(log⁡n)O(\log n)O(logn)，最好 O(1)O(1)O(1)；
  • 空间复杂度 O(h)O(h)O(h)（h=log⁡nh=\log nh=logn，平衡树高度）；
  • 核心优势：自平衡，避免BST退化，查找效率稳定；
  • 应用场景：C++ std::map/std::set 底层（红黑树，弱平衡，插入/删除效率更高），动态数据集的高效查找。

9. B+树查找 (简化版，适配内存)

思路

B+树是多路平衡查找树，所有数据都存储在叶子节点，且叶子节点通过链表相连；非叶子节点仅存储索引（关键字+子节点指针），查找时从根节点开始，按关键字找到对应子节点，直到叶子节点；适合磁盘IO场景（减少磁盘访问次数），是数据库索引、文件系统的核心。

重点

  • 时间复杂度：O(log⁡tn)O(\log_t n)O(logt​n)（ttt 为B+树阶数，远大于2，高度远低于AVL树）；
  • 空间复杂度 O(n)O(n)O(n)（存储索引和数据）；
  • 核心优势：高度低（减少IO次数）、叶子节点链表支持范围查询；
  • 应用场景：数据库索引（MySQL InnoDB）、文件系统（NTFS/Ext4），大规模数据的磁盘级查找。

10. 模拟C++ std::binary_search

思路

C++标准库 std::binary_search 是二分查找的标准化实现，仅返回“是否存在目标值”（而非索引）；要求输入容器支持随机访问迭代器（如 vector/array），且元素已排序；底层实现为优化版二分查找，保证 O(log⁡n)O(\log n)O(logn) 复杂度。

重点

  • 时间复杂度：平均/最坏 O(log⁡n)O(\log n)O(logn)，最好 O(1)O(1)O(1)；
  • 空间复杂度 O(1)O(1)O(1)，无额外空间；
  • 核心要求：容器支持随机访问、元素已排序；
  • 优势：标准化、高性能，是C++中有序容器查找的首选；
  • 注意：std::binary_search 仅返回bool，如需索引用 lower_bound/upper_bound。

随机选择算法

随机选择算法（也叫快速选择算法）是基于快速排序的分治思想，核心目标是在未排序数组中找到第 k 小（或第 k 大）的元素，无需对整个数组排序，平均时间复杂度远优于先排序再取值的方式。

思路

  1. 分治核心：借鉴快速排序的分区（Partition）操作，随机选择一个基准值（pivot），将数组分为“小于基准”“等于基准”“大于基准”三部分；
  2. 缩小范围：
    • 若“小于基准”的元素数量 ≥ k，说明第 k 小元素在左半区，递归处理左半区；
    • 若“小于基准+等于基准”的元素数量 < k，说明第 k 小元素在右半区，递归处理右半区（k 需减去左半区+基准的数量）；
    • 否则，基准值就是第 k 小元素；
  3. 随机基准优化：随机选择基准值，避免最坏情况（如数组已排序时固定选第一个元素导致 O(n2)O(n^2)O(n2) 复杂度）。

重点

  1. 核心特性：
    • 无需完整排序，仅聚焦目标元素所在区间，是找“第 k 小/大元素”的最优算法；
    • 稳定性：算法本身不稳定（分区会交换元素位置），但不影响“找第 k 小元素”的核心目标；
    • 原地操作：分区过程仅交换元素，无需额外数组空间。
  2. 适用场景：
    • 快速找到数组的中位数（k = n/2）、TOP-K 问题（找前 k 小/大元素，可结合随机选择+局部排序）；
    • 大数据量下的Top-K筛选（如从1000万条数据中找第100小的元素，无需全排序）；
    • 工程优化：小规模区间（如元素数量 < 10）可直接用插入排序，进一步提升效率。
