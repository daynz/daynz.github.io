思维框架

审题与建模阶段 (2分钟)

核心目标：将自然语言问题转化为数学模型或数据结构问题。

  1. 输入输出分析
    • 数据范围 (N,M,ValueN, M, \text{Value}N,M,Value)：决定时间复杂度要求。
      • N≤20N \le 20N≤20: O(2N)O(2^N)O(2N) (DFS/状压DP)
      • N≤100N \le 100N≤100: O(N4)O(N^4)O(N4) (Floyd/区间DP)
      • N≤1000N \le 1000N≤1000: O(N3)O(N^3)O(N3) 或 O(N2)O(N^2)O(N2)
      • N≤105N \le 10^5N≤105: O(Nlog⁡N)O(N \log N)O(NlogN) 或 O(N)O(N)O(N) (排序/二分/贪心/线段树)
      • N≤109N \le 10^9N≤109: O(log⁡N)O(\log N)O(logN) 或 O(1)O(1)O(1) (数学推导/快速幂)
    • 数据类型：是否需要 long long？是否涉及浮点数精度？
  2. 问题归类 (Pattern Recognition)
    • 最值问题 →\rightarrow→ 动态规划 (DP)、贪心、二分答案。
    • 方案数问题 →\rightarrow→ DP、组合数学、DFS回溯。
    • 存在性/可行性 →\rightarrow→ BFS/DFS、二分答案、并查集。
    • 区间查询/修改 →\rightarrow→ 线段树、树状数组、前缀和。
    • 图论相关 →\rightarrow→ 最短路 (Dijkstra/SPFA)、最小生成树 (Kruskal/Prim)、拓扑排序。
    • 字符串匹配 →\rightarrow→ KMP、Trie字典树、AC自动机、后缀数组/自动机。
  3. 特殊情况 (Corner Cases)
    • N=0,1N=0, 1N=0,1 时的边界。
    • 所有元素相同、已排序、逆序。
    • 图不连通、有重边、自环。
    • 内存限制是否紧张？

策略选择与复杂度预估 (2分钟)

核心目标：确定解题算法，确保不会TLE (Time Limit Exceeded)。

常见复杂度 对应算法/数据结构 C++ STL 辅助
O(1)O(1)O(1) 数学公式、哈希表查找 unordered_map
O(log⁡N)O(\log N)O(logN) 二分查找、堆操作、平衡树 lower_bound, priority_queue, set
O(N)O(N)O(N) 双指针、单调队列/栈、桶排序 vector, deque, stack
O(Nlog⁡N)O(N \log N)O(NlogN) 快排、归并、线段树单点/区间 sort, map
O(N2)O(N^2)O(N2) 简单DP、冒泡/插入排序、Floyd -
O(2N)O(2^N)O(2N) 暴力DFS、状态压缩DP bitset

决策树：

  • 如果是静态区间查询 →\rightarrow→ 前缀和 / ST表 / 线段树。
  • 如果是动态区间修改 →\rightarrow→ 线段树 / 树状数组 / 分块。
  • 如果求最短路径且边权非负 →\rightarrow→ Dijkstra (priority_queue)。
  • 如果求连通性 →\rightarrow→ 并查集 (DSU)。
  • 如果不确定正解 →\rightarrow→ 先写暴力 (DFS/BF) 拿部分分，再思考优化。

模块化实现思维

不要把所有逻辑塞进 main。将功能拆解：

  • solve(): 处理单组测试用例的核心逻辑。
  • check(mid): 二分答案中的验证函数。
  • dfs(u, state): 搜索函数。
  • build() / update() / query(): 数据结构操作。

常见陷阱自查清单

  • [ ] 整数溢出？(int vs long long)
  • [ ] 除法是否除零？
  • [ ] 浮点数比较是否用了 eps？
  • [ ] 多组数据 memset 或 vector.clear() 了吗？
  • [ ] 图的邻接表 head 数组初始化了吗？
  • [ ] 递归是否有终止条件？是否会爆栈？
